# 系统时间感知开发文档

> 文档日期：2026-11-10  
> 文档范围：角色的当前日期、时间、星期、时区和距离上一条消息的时间感知  
> 当前状态：已实现；默认开启，可在「设置 > 聊天 > 系统感知」关闭

## 1. 背景

之前只有主动消息、动态生成和日记生成在各自的提示词里带了零散的时间信息，普通单聊和群聊没有告诉模型“现在是什么时候”。因此角色无法可靠回答：

- 今天几号、星期几；
- 现在几点、上午还是深夜；
- 距离上一条消息过了多久；
- “明天”“下周”“下个月”大概对应什么时间。

本轮新增统一的 `SystemContextBuilder`，把本地系统时间整理成一段只读上下文，注入需要时间感的模型请求。

## 2. 实现方式

### 2.1 系统上下文

文件：`lib/services/system_context_builder.dart`

输出示例：

```text
【系统上下文】
当前日期：2026 年 11 月 10 日，星期二
当前时间：14:32（UTC+08:00，中国标准时间）
当前时段：下午
距离上一条消息：2 小时 5 分钟前
当用户问现在几点、今天几号、星期几或某个日期时，按以上时间回答，不要编造日期。平时不用主动频繁报时。
```

说明：

- 使用设备本地时间，不联网校时；
- 时区偏移来自系统 `DateTime.timeZoneOffset`，时区名称来自 `DateTime.timeZoneName`；
- 当前时段分为凌晨、清晨、上午、中午、下午、傍晚、晚上、深夜；
- `previousMessageAt` 由聊天页传入，取当前用户消息之前最近一条有时间戳的消息；
- 如果距离上一条消息不到 1 分钟，显示“刚刚”。

### 2.2 设置

数据模型：`lib/models/system_context_settings.dart`  
存储：`lib/services/system_context_settings_store.dart`

| 字段 | 默认值 | 说明 |
|---|---|---|
| `timeAwarenessEnabled` | `true` | 是否注入系统时间上下文 |

持久化 Key：`system_context_settings_v1`

入口：「设置 > 聊天 > 系统感知 > 让角色知道当前时间」。

关闭后：

- 单聊、群聊、主动消息、目的引擎、动态和动态评论不再注入系统时间；
- 记忆提炼也不再使用系统时间做相对日期换算；
- 不影响原有聊天记录、日记或主动消息调度。

## 3. 注入范围

| 场景 | 注入内容 | 文件 |
|---|---|---|
| 单聊 | 日期、时间、星期、时区、距上一条消息 | `lib/pages/chat_page.dart` |
| 群聊 | 同上，每个发言角色都会看到 | `lib/pages/chat_page.dart` |
| 主动消息 | 当前日期、时间、星期、时区；隐藏提醒里仍保留沉默时长 | `lib/services/proactive_message_service.dart` |
| 目的引擎 | 系统上下文 + 当前时间 | `lib/services/proactive_message_service.dart` |
| 角色动态 | 系统上下文 | `lib/services/moment_generator.dart` |
| 动态评论/回复 | 系统上下文 | `lib/services/moment_generator.dart` |
| 长期记忆提炼 | 系统上下文，并要求把“明天/下周/下个月”换算成具体日期 | `lib/services/memory_extractor.dart` |
| 群公共记忆提炼 | 系统上下文，并做同样的相对日期换算 | `lib/services/group_memory_extractor.dart` |
| 日记 | 原有日期和素材时间；日记本身已有明确日期 | `lib/services/diary_generator.dart` |

提示词顺序（单聊/群聊）：

```text
角色卡提示词
→ 系统上下文
→ 跨场景活动
→ 长期记忆 / 人物档案 / 未完成话题
→ 最近日记
→ 心情
→ 连发说明
```

## 4. 为什么不需要“系统权限”

当前实现只读取应用进程内的公开系统信息：

- 本地时间；
- 时区偏移和时区名称；
- 星期和时段；
- 当前会话消息时间戳。

这些信息不需要申请 Android/iOS 危险权限，也不读取通讯录、相册、位置、日历、短信或设备标识。不会上传时间信息，时间上下文只随模型请求发送。

以后如果要扩展真正的系统能力，需要单独评估权限和隐私：

- 电量、网络状态：可加 `battery_plus` / `connectivity_plus`，通常不需要危险权限；
- 日历、联系人、定位：需要系统权限和明确的用户授权；
- 读取剪贴板、通知、后台任务：平台限制和隐私风险更高；
- 让模型主动调用系统工具：需要引入 function calling / tool calling，并为每个工具做权限白名单。

当前没有引入工具调用，只是把系统上下文作为提示词的一部分注入。

## 6. 已知限制

- 使用设备本地时间，不处理用户手动修改系统时间或时区变化；
- 不包含节假日、农历和节气，只提供公历日期、星期和时段；
- 不包含天气、电量、网络、位置等额外系统信息；
- 不提供工具调用，模型只能“知道”时间，不能主动读取其他系统状态；
- 时间上下文会略微增加每次请求的 token，但内容很短；
- 关闭时间感知后，历史聊天里已有的时间戳不会被删除，只是不再注入新请求。
