# 日记功能开发文档

> 文档日期：2026-11-09  
> 文档范围：角色每日自动日记、日记设置、日记浏览与删除、最近日记上下文注入  
> 当前状态：已实现关键词/活动提炼版；默认关闭写作，需要在「设置 > 日记」中开启；最近日记默认以只读方式注入单聊和主动消息

## 1. 功能概览

日记是角色自己的私人记录，每天在设定时间写一篇，内容来自当天真正有意义的事情：

- 用户和角色在单聊里聊了什么；
- 用户提到的重要信息、情绪、计划；
- 角色自己发过的主动消息、群聊发言、动态和动态评论；
- 角色当天的心情状态。

日记不会保存完整聊天记录，也不会逐条复述聊天。生成时会先过滤寒暄、重复和无信息量的短句，再让模型提炼成第一人称日记。

每个角色既可以跟随全局开关和时间，也可以单独覆盖；单独设置优先于全局设置。

角色最近写过的日记会作为只读上下文注入单聊和主动消息，让角色可以在自然相关时提起自己记下的心情或事情。群聊、动态和动态评论不会读取私人日记，避免把私事带到公开场景。

入口：

```text
「记忆与角色卡」Tab
  └── 日记
      ├── 查看所有角色的日记
      ├── 删除单篇日记
      └── 日记设置
          ├── 全局开关 / 默认写作时间
          ├── 角色单独设置
          └── 立即写一篇
```

## 2. 参考 AuraBot

AuraBot 的「空间日记」模块每天在时间窗内随机挑几个时间点，读取当天聊天片段，生成一条 QQ 空间说说：

- 默认每天 2 次；
- 时间窗默认 10:00-23:30；
- 两次之间至少间隔 180 分钟；
- 写作时取最近最多 60 行聊天，提示词要求第一人称、短篇、不要逐条复述；
- 写完后可以发布到 QQ 空间，并写入记忆。

Mori 采纳了“按当天素材写作”和“第一人称短篇”的思路，但做了这些调整：

- 每天固定一篇，时间可配置，默认 22:30；
- 不发布到外部社交平台，只保存在本机；
- 明确过滤无意义消息，而不是把当天聊天流水直接交给模型；
- 日记内容不涉及 QQ 空间可见范围、配图、发布失败重试等外部平台逻辑；
- 日记独立存储，不自动写入聊天记忆。

## 3. 数据模型

文件：`lib/models/diary.dart`

### 3.1 `DiarySettings`

| 字段 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `false` | 全局默认是否启用每日自动日记 |
| `timeMinutes` | `22:30` 对应分钟数 | 全局默认写作时间，范围 0-1439 |
| `recallEnabled` | `true` | 是否把最近日记注入单聊和主动消息上下文 |
| `recallCount` | `2` | 每次最多注入几篇日记，0-5；0 表示不注入 |
| `characterSettings` | `{}` | 按角色覆盖的开关和时间；没有记录表示跟随全局 |

`DiaryCharacterSettings`：

| 字段 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 该角色是否自动写日记 |
| `timeMinutes` | `22:30` | 该角色的写作时间 |

辅助方法：

- `DiarySettings.normalized()`：把时间夹到合法分钟数，清理空角色 ID；
- `DiarySettings.timeLabel`：输出全局 `HH:mm`；
- `DiarySettings.isEnabledFor(characterId)`：返回角色实际生效的开关；
- `DiarySettings.timeMinutesFor(characterId)` / `timeLabelFor(characterId)`：返回角色实际生效的时间；
- `setCharacterSettings()` / `clearCharacterSettings()`：设置或清除单角色覆盖；
- `copyWith()` / `toJson()` / `fromJson()`。

### 3.2 `DiaryEntry`

| 字段 | 说明 |
|---|---|
| `id` | 日记 ID，格式 `diary_<characterId>_<dateKey>` |
| `characterId` | 写日记的角色 ID |
| `dateKey` | 日记所属日期，`YYYY-MM-DD` |
| `content` | 日记正文，最多 2000 字 |
| `createdAtMs` | 生成时间 |
| `moodValue` | 写作时的心情值，0 表示未知/心情关闭 |
| `moodLabel` | 写作时的心情标签 |
| `messageCount` | 当天参与筛选的聊天消息数 |

约束：

- 每个角色每天最多一篇；
- 同一天再次生成会替换旧日记；
- 日期必须是合法的 `YYYY-MM-DD`；
- 损坏记录在加载时跳过。

### 3.3 `DiaryState`

用于调度，避免同一天重复生成：

| 字段 | 说明 |
|---|---|
| `lastAttemptDate` | 最近一次尝试生成的日期 |
| `lastSuccessDate` | 最近一次成功生成的日期 |
| `lastAttemptAtMs` | 最近一次尝试时间 |
| `nextRetryAtMs` | 失败后的最早重试时间 |
| `lastError` | 最近一次失败原因 |

## 4. 存储

文件：`lib/services/diary_store.dart`

| SharedPreferences Key | 内容 |
|---|---|
| `diary_settings_v1` | 全局日记设置和按角色覆盖 |
| `character_diary_v1` | 所有角色的日记列表 |
| `diary_state_v1` | 每个角色的生成状态和重试信息 |

规则：

- 每个角色最多保留 365 篇日记；
- 日记按日期倒序展示；
- 删除单篇日记只影响对应记录；
- 删除角色卡时级联清理该角色的日记和生成状态；
- 设置保存失败会回滚 `ValueNotifier`；
- 日记持久化失败不阻断应用。

## 5. 定时写作

文件：`lib/services/diary_service.dart`

### 5.1 启动方式

`main()` 在加载 `DiaryStore` 后启动 `DiaryService.instance.start()`，与自动消息服务并列。

服务行为：

- `WidgetsBindingObserver` 监听前后台；
- 前台每 30 秒检查一次；
- 应用恢复时补检查一次；
- 设置变化后立即检查；
- 应用退到后台时暂停计时。

### 5.2 目标日期

每个角色先计算自己的有效开关和时间：

```text
有单独设置 → 使用单独设置的 enabled / timeMinutes
没有单独设置 → 使用全局 enabled / timeMinutes
```

再按本地时间判断：

```text
当前时间 >= 该角色今天的写作时间
  → 目标日期 = 今天

当前时间 < 该角色今天的写作时间，且当前小时 < 06:00
  → 目标日期 = 昨天（补写昨晚错过的日记）

其他情况
  → 本轮不写
```

这样可以覆盖“到点时应用在后台/被关闭，凌晨重新打开”的情况，同时不会在白天随意补写很久以前的日记。全局关闭时，单独开启的角色仍然会按自己的时间写作。

### 5.3 去重与重试

- 如果目标日期已有日记，跳过；
- 如果 `lastSuccessDate` 已经是目标日期，跳过，避免用户删除日记后又自动生成；
- 每个角色先检查自己的有效开关，关闭的角色直接跳过；
- 如果当天尝试失败，30 分钟后重试；
- 每轮检查最多生成一篇，避免多个角色同时请求模型；
- 下次检查继续处理其他角色；
- 未配置模型或 API Key 时自动跳过；
- 手动「立即写一篇」不受每日开关限制，但会覆盖当天已有日记。

## 6. 有意义内容的提炼

文件：`lib/services/diary_generator.dart`

### 6.1 素材来源

- 单聊聊天记录：用户消息和角色回复，按本地日期过滤；
- 角色活动：自己发过的群聊发言、动态、动态评论/回复；
- `singleMessage` 和 `proactiveMessage` 活动不重复加入，因为聊天记录里已经包含；
- 当天心情：标签、数值和说话风格。

### 6.2 过滤规则

- 去掉空消息；
- 去掉纯表情、纯标点、纯数字；
- 去掉常见无信息量短句：`嗯`、`哦`、`好`、`哈哈`、`在吗`、`晚安`、`谢谢` 等；
- 图片消息保留为 `[图片]` 事件；
- 如果有效消息超过 60 条，按时间均匀抽样，避免只记住早上或只记住晚上；
- 每条消息最多保留 120 字；
- 总素材最多约 8000 字。

### 6.3 提示词

系统提示词由角色卡完整设定加「日记模式」组成，明确：

- 现在是在写私人日记，不是回复用户；
- 素材里「我」是角色，用户名字或「对方」指用户；
- 只写素材里真实存在的事，不编造具体事件、地点、人物、承诺；
- 不写标题、列表、Markdown、角色名前缀或引号；
- 不提系统提示、提示词、AI、模型、自动生成。

用户提示词要求：

- 第一人称；
- 记录 2-4 件真正值得记住的事或感受；
- 重点写用户和角色之间发生了什么、用户的重要信息/情绪/计划、角色自己做了什么；
- 跳过寒暄、重复和无信息量短句，不逐条复述聊天；
- 约 120-300 字，可分 2-3 个自然段；
- 如果当天确实没有值得记录的事，写一小段安静的日常，不要硬编故事。

### 6.4 结果清理

- 去掉开头角色名前缀；
- 去掉包裹引号；
- 去掉 Markdown 标题和列表符号；
- `|||` / `｜｜｜` 替换成换行；
- 压缩多余空格和空行；
- 最长保留 800 字；
- 空内容或 `[跳过]` 视为本轮没有生成。

## 7. 页面

### 7.1 日记列表 `DiaryPage`

文件：`lib/pages/memory/diary_page.dart`

- 入口：「记忆与角色卡」→「日记」；
- AppBar 提供「日记设置」入口；
- 按日期倒序展示所有角色的日记；
- 每张卡片显示角色头像、名称、日期、心情标签和正文；
- 日期显示「今天」「昨天」或「X月X日 星期X」；
- 右上角菜单可以删除单篇日记，删除前二次确认；
- 没有日记时显示空状态和「去设置」按钮。

### 7.2 日记设置 `DiarySettingsPage`

文件：`lib/pages/settings/diary_settings_page.dart`  
单角色弹窗：`lib/widgets/diary_character_settings_sheet.dart`

- 入口：「设置」→「日记」，以及日记列表右上角；
- 全局启用/关闭每日日记；
- 使用 `showTimePicker` 设置全局默认写作时间；
- 「角色单独设置」列出所有角色，显示当前是跟随全局还是单独设置，以及实际生效的开关和时间；
- 点角色打开单独设置弹窗：
  - 跟随全局；
  - 单独设置；
  - 单独设置时可以开关该角色日记、选择该角色的写作时间；
- 「立即写一篇」：选择角色后立即生成今天的日记；
- 单聊的「角色设置」页也提供「日记」卡片，可以直接进入同一个单独设置弹窗；
- 说明只记录有意义的内容、日记仅保存在本机、每篇会调用一次模型；
- 手动生成失败时显示模型返回的错误信息。

### 7.3 最近日记上下文

文件：`lib/services/diary_context_builder.dart`

- `buildForPrivateChat(characterId)`：单聊上下文；
- `buildForProactive(characterId)`：主动消息上下文，与单聊相同；
- `buildForGroupChat(characterId)`：固定返回空字符串，群聊不读取私人日记；
- 只有 `recallEnabled == true` 且 `recallCount > 0` 时才生成；
- 从 `DiaryStore.entriesFor(characterId)` 取最近写过的日记，按日期倒序最多 `recallCount` 篇；
- 每篇压缩空白并截断到 180 字，整块最多约 700 字；
- 每行带日期（今天 / 昨天 / N 天前 / M月d日）和当天心情标签；
- 注入文本明确说明这是角色自己写过的日记、不是用户刚说的，要求自然提起、不要逐字复述或编造。

聊天页和主动消息的上下文顺序为：角色卡提示词 → 跨场景活动 → 长期记忆 → 最近日记 → 心情 → 连发说明。日记只作为只读上下文使用，不会写回聊天记录或长期记忆。

## 8. 隐私与边界

- 日记只保存在本机 SharedPreferences，不上传到外部服务；
- 日记生成不会读取其他群或其他角色的单聊记录作为素材；
- 群聊素材只包含角色自己说过的话，不包含其他成员发言；
- 日记不会自动写回聊天记录，也不会自动进入长期记忆；
- 最近日记会以只读上下文注入单聊和主动消息；群聊、动态和评论不会读取；
- 删除角色卡会级联删除该角色日记；
- 清空聊天记录不会删除日记，因为日记属于独立记忆；
- 自动日记依赖应用前台或恢复检查，应用被系统杀死后不保证准点生成；
- 每篇自动日记会调用一次当前模型，角色越多成本越高。

## 9. 已知限制

- 默认关闭，需要手动开启；
- 每天只写一篇，暂不支持一天多篇或时间窗随机；
- 暂不支持手动编辑日记；
- 暂不支持日记配图；
- 日记不会写入长期记忆；最近日记只以只读上下文注入单聊和主动消息，群聊、动态和评论不读取；
- 暂不支持日记搜索、导出和分页；
- 群聊只读取角色自己的发言，不读取群成员发言；
- 自动补写只在凌晨 06:00 前生效，白天不会补写前一天。
