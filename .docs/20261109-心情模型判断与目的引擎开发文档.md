# 心情模型判断与目的引擎开发文档

> 文档日期：2026-11-09  
> 文档范围：可选的心情模型判断、角色主动消息目的引擎  
> 当前状态：均已实现；心情模型判断默认关闭，目的引擎为实验性功能且默认关闭

## 1. 功能概览

本轮在现有心情和主动消息基础上增加了两项能力：

| 能力 | 默认状态 | 模型调用 | 作用 |
|---|---|---|---|
| 心情模型判断 | 关闭 | 单聊每次用户发言 +1 次 | 结合上下文判断用户消息让角色心情变化多少 |
| 目的引擎 | 关闭 | 沉默搭话每轮 +1 次 | 先选择本轮主动消息的真实目的，再生成消息 |

两项功能都默认关闭，避免无意增加模型成本。关闭时保持原有行为：

- 心情只根据本地关键词判断；
- 主动消息只使用随机由头和普通沉默触发。

## 2. 心情模型判断

### 2.1 设置

`MoodSettings` 新增字段：

| 字段 | 默认值 | 说明 |
|---|---|---|
| `modelJudgeEnabled` | `false` | 是否用模型判断心情；关闭时使用关键词 |

入口：「设置 > 心情 > 使用模型判断心情」。

页面说明会明确提示“单聊每次用户发言会多调用一次模型”。

### 2.2 服务

文件：`lib/services/mood_judge_service.dart`

`MoodJudgeService`：

- 使用当前模型和 API Key；
- 输入角色名、当前心情值、最近最多 8 条聊天和用户最新消息；
- 要求模型输出 JSON：
  ```json
  {"delta": 6, "reason": "用户说喜欢你"}
  ```
- `delta` 限制在 `-20..20`；
- `reason` 最多 40 字；
- 空内容、非法 JSON、缺少 `delta` 或 `reason` 时返回 `null`；
- 网络或模型失败时返回 `null`，不阻断聊天。

### 2.3 应用流程

单聊发送消息后、生成回复前：

```text
心情开启且 modelJudgeEnabled == true
  │
  ▼
MoodJudgeService.judge()
  │
  ├─ 成功 → MoodStore.nudge(characterId, delta, reason)
  └─ 失败/无结果 → 回退到 MoodStore.observe() 关键词判断
```

- 模型判断成功时不再执行关键词判断，避免重复加分；
- 模型判断 `delta == 0` 时不改变心情，也不回退关键词；
- 群聊仍只使用关键词判断，避免每个群成员都额外调用模型；
- 主动消息、日记、动态不会触发心情模型判断。

### 2.4 成本与边界

- 每次单聊用户发言最多增加一次模型调用；
- 默认关闭；
- 使用较低 temperature（0.2），减少随机性；
- 模型返回异常时静默回退，不弹错误提示；
- 心情值和历史仍按原规则持久化，存储 Key 不变。

## 3. 目的引擎

### 3.1 设置

`ProactiveMessageSettings` 新增字段：

| 字段 | 默认值 | 说明 |
|---|---|---|
| `purposeEnabled` | `false` | 是否启用实验性目的引擎 |

入口：「设置 > 自动消息 > 目的引擎（实验性）」。

页面说明会提示“开启后沉默搭话会先多调用一次模型选择目的”。

### 3.2 生效范围

目的引擎只替换**自动沉默搭话**：

- 沉默触发到期且 `purposeEnabled == true` 时，先运行目的选择；
- 定时问候仍使用原来的普通主动消息流程；
- 追问（nudge）仍使用原来的追问流程；
- 手动「立即让角色发一条」仍使用普通主动消息流程；
- 这样不会同时运行两套主动引擎，避免重复打扰。

如果目的选择没有找到足够真实的素材，本轮直接放弃，不硬找话，也不消耗每日次数。

### 3.3 目的选择

文件：`lib/services/proactive_message_service.dart`

`_selectPurpose()`：

输入素材：

- 最近最多 20 条聊天；
- 长期记忆、人物小档案和未完成话题（`MemoryContextBuilder`）；
- 最近日记（`DiaryContextBuilder`）；
- 角色最近 3 条动态；
- 当前日期和时间。

提示词要求：

- 只选一个最自然、最有依据的目的；
- 优先使用真实聊天、记忆、日记和动态；
- 不编造素材里不存在的事件、地点或人物；
- 素材不足时输出 `{"purpose":"[沉默]"}`；
- 输出 JSON：
  ```json
  {
    "purpose": "问问用户昨天说的面试结果",
    "reason": "用户昨天提到今天面试",
    "messageAngle": "先关心结果，不要催"
  }
  ```

解析规则：

- 目的为空、`[沉默]`、`沉默` 或少于 4 字时视为放弃；
- 目的最多 120 字，依据和角度各最多 80 字；
- 解析失败或模型调用失败时返回 `null`，本轮不发送。

### 3.4 消息生成

目的选择成功后，普通主动消息生成流程继续执行，但 system prompt 追加：

```text
【本轮目的】
<目的、依据和切入角度>
请围绕这个目的自然发一条消息；不要解释目的，不要提及系统、模型或自动触发。
```

之后仍复用原有：

- 主动消息模式提示；
- 跨场景活动、长期记忆、最近日记和心情上下文；
- 多气泡拆分；
- `[沉默]` 处理；
- 角色名前缀清理和出戏内容过滤；
- 每日上限、未回复上限、免打扰和冷却。

### 3.5 成本与失败处理

- 每次自动沉默搭话会从 1 次模型调用变成最多 2 次：目的选择 + 消息生成；
- 目的选择失败或返回空时，本轮不发送，不消耗每日额度；
- 自动触发失败后仍按原有逻辑安排下一次沉默时间；
- 目的引擎默认关闭；
- 定时问候、追问和手动触发不会增加目的选择调用。

## 4. 数据与存储

本轮没有新增存储 Key：

| 存储 Key | 新增内容 |
|---|---|
| `mood_settings_v1` | `modelJudgeEnabled` |
| `proactive_message_settings_v1` | `purposeEnabled` |

旧版本设置缺少字段时自动使用默认值，不影响已有数据。

## 6. 已知限制

- 心情模型判断只支持单聊，群聊仍使用关键词；
- 心情模型判断会增加每次单聊发言的模型调用和首字延迟；
- 目的引擎是实验性功能，每次自动沉默搭话最多两次模型调用；
- 目的引擎只替换沉默搭话，定时问候和追问仍走普通流程；
- 目的引擎没有独立的“目的历史”去重，只依赖素材和提示词约束；
- 两项功能都依赖当前模型质量，模型输出异常时会静默回退或放弃；
- 目的引擎不会在应用被系统杀死后运行，仍受前台/恢复限制。
