# 用户表情包开发文档

> 文档日期：2026-11-11  
> 文档范围：用户在聊天里添加和使用自己的表情包  
> 当前状态：已实现用户侧第一阶段；角色侧表情包后续单独做

## 1. 功能概览

- 输入框右侧新增「表情包」按钮；
- 点开后弹出表情包选择面板；
- 表情包网格第一个位置固定是「添加」按钮，支持从相册添加表情包；
- 点按表情包立即作为一条消息发送；
- 长按表情包可以删除；
- 表情包在聊天气泡里以无气泡图片形式显示，不带正文；
- 支持 JPEG、PNG、GIF、WebP，单张最大 4 MB；
- 每个用户最多保存 60 张表情包，超过后自动清理最旧的。

## 2. 数据模型与存储

### 2.1 `Sticker`

文件：`lib/models/sticker.dart`

| 字段 | 说明 |
|---|---|
| `id` | 表情包 ID，格式 `sticker_<microseconds>` |
| `fileName` | 本地相对文件名 |
| `mimeType` | 图片 MIME 类型 |
| `bytes` | 运行时图片字节，不写入 SharedPreferences |
| `createdAtMs` | 添加时间 |

### 2.2 `StickerStore`

文件：`lib/services/sticker_store.dart`

| 数据 | 位置 |
|---|---|
| 表情包元数据 | SharedPreferences，Key `user_stickers_v1` |
| 表情包图片 | 应用 Support Directory 下的 `user_stickers/` 目录 |

行为：

- `load()` 读取元数据并加载本地文件，跳过文件缺失或损坏的记录；
- `addSticker(bytes, mimeType)` 写入文件、更新列表并持久化；
- `deleteSticker(id)` 删除文件并从列表移除；
- 超过 60 张时按添加时间从旧到新清理；
- 文件扩展名按 MIME 类型生成（`.jpg` / `.png` / `.gif` / `.webp`）。

## 3. 选择与添加

### 3.1 入口

`ChatPage` 输入区 `_Composer`：

```text
输入框 → 表情包按钮 → 图片按钮 → 停止按钮 → 发送按钮
```

- 表情包按钮使用 `Icons.emoji_emotions_outlined`，tooltip「表情包」；
- 图片按钮仍只在视觉模型下显示，表情包按钮始终显示。

### 3.2 表情包面板

文件：`lib/widgets/sticker_picker_sheet.dart`

- 底部弹窗高度约 380；
- 顶部显示「表情包」和「点按发送 · 长按删除」提示；
- `GridView` 每行 5 个；
- 第一个格子是虚线边框的「添加」按钮；
- 其余格子显示已保存的表情包；
- 点按表情包：关闭面板并立即发送；
- 长按表情包：弹出删除确认框，确认后从本地删除。

### 3.3 添加流程

1. 点击「添加」；
2. `image_picker` 从相册选择；
3. 最大宽高 1024，质量 90；
4. 校验字节非空、不超过 4 MB、MIME 在 JPEG/PNG/GIF/WebP 范围内；
5. 通过 `StickerStore.addSticker()` 保存；
6. 面板自动刷新，新表情包出现在最前面。

## 4. 发送与展示

### 4.1 消息模型

`ChatMessage` 新增字段：

| 字段 | 说明 |
|---|---|
| `isSticker` | 是否是一条表情包消息，默认 `false` |

表情包消息：

- `content` 为空；
- `image` 保存表情包字节和 MIME；
- `isSticker = true`；
- 群聊中仍然写入 `senderId` / `senderName`。

`ChatMessage.toApiJson({includeImage})`：

- 表情包发送给模型时，文本部分固定为 `[表情包]`；
- 视觉模型：同时发送 `[表情包]` 文字和图片；
- 非视觉模型：只发送 `[表情包]` 文字，本地仍然正常显示表情包。

### 4.2 展示

`_ChatBubble`：

- 表情包不显示气泡背景、不显示正文；
- 图片最大 150×150，按比例缩放；
- 加载失败显示损坏图片图标；
- 用户消息右侧显示，群聊 AI 消息左侧显示；
- 长按消息仍然可以删除。

### 4.3 聊天记录

`ChatHistoryStore`：

- 保存和加载 `isSticker`；
- 会话列表摘要显示 `[表情包]`；
- 删除单条消息时同步删除对应聊天图片；
- 清空会话时删除该会话所有聊天图片；
- 表情包消息和普通图片消息共用聊天图片目录。

## 5. 与模型请求的关系

`ChatService.streamChat()` 新增可选参数：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `includeImages` | `true` | 是否把消息里的图片发送给模型 |

`ChatPage` 根据当前模型是否支持视觉传入：

- 支持视觉：图片和表情包都会发送图片；
- 不支持视觉：所有图片和表情包只发送文字占位，其中表情包为 `[表情包]`。

这样表情包不再要求必须切换到视觉模型，普通文本模型也能收到一条 `[表情包]` 消息并作出回应。

## 6. 隐私与边界

- 表情包只保存在本机，不上传服务器；
- 添加表情包只访问相册，复用现有 `image_picker` 权限；
- 已发送的表情包会作为聊天图片单独保存，删除表情包库里的原图不会影响历史消息；
- 表情包不会自动写入记忆或日记；
- 表情包只发送给当前选择的模型供应商。

## 8. 已知限制

- 当前只有用户侧表情包，角色还不会主动发送表情包；
- 没有表情包分类、搜索、排序和批量管理；
- 一个表情包库跨所有会话共享，不支持按角色单独配置；
- 不支持视频、动态图之外的复杂格式；
- 非视觉模型只能看到 `[表情包]` 文字，无法理解表情包画面；
- 表情包不会自动进入长期记忆或动态；
- 表情包删除后已发送的历史消息不受影响。

## 9. 后续可以继续做

1. 角色侧表情包：给角色配置表情包库，并在回复中随机或按语境发送；
2. 角色也能“收藏”用户发来的表情包；
3. 按角色区分表情包可见范围；
4. 表情包管理页：分类、搜索、排序、批量删除；
5. 表情包和心情联动：心情好时更常发表情包；
6. 在记忆或档案里记录“常用表情包风格”，但保持隐私隔离。
