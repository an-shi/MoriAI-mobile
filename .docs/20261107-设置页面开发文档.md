# 设置页面开发文档

> 文档日期：2026-11-08  
> 页面文件：`lib/pages/settings_page.dart`  
> 子页面目录：`lib/pages/settings/`  
> 入口位置：左侧 `UserProfileDrawer` 底部的「设置」入口  
> 说明：设置页已不再是底部导航 Tab；底部第三个 Tab 现在是「动态」

## 1. 页面概览

设置页负责应用级配置，当前包含五个入口：

| 入口 | 子页面 | 功能 |
|---|---|---|
| 模型 | `settings/model_settings_page.dart` | 供应商、模型、API Key、模型预设 |
| 外观 | `settings/appearance_settings_page.dart` | 跟随系统、浅色、深色 |
| 动态互动 | `settings/moment_interaction_settings_page.dart` | 自动评论人数、自动回复层数 |
| 自动消息 | `settings/proactive_message_settings_page.dart` | 主动消息总开关、沉默触发、定时问候、免打扰、频率保护 |
| 关于 Mori | `settings/about_settings_page.dart` | 版本、模型服务、隐私说明 |

设置主页是 `StatelessWidget`，不持有独立状态；状态来自：

- `ModelStore`
- `ThemeStore`
- `MomentInteractionSettingsStore`
- `ProactiveMessageStore`

设置主页现在自带 `Scaffold` 和 `AppBar`，因为它是从抽屉 push 出来的独立页面，不再嵌入 `HomePage` 的 `IndexedStack`。

## 2. 技术依赖

| 类型 | 依赖 | 用途 |
|---|---|---|
| UI | Flutter Material 3 | 设置列表、卡片、下拉框、对话框、SnackBar |
| 状态 | `AnimatedBuilder` / `ValueListenableBuilder` | 监听模型、预设、主题和互动设置变化 |
| 模型存储 | `ModelStore` | 当前供应商、模型、预设、模型能力缓存 |
| Key 存储 | `ApiKeyStore` | 按供应商保存 API Key |
| 主题存储 | `ThemeStore` | 主题模式持久化 |
| 模型列表 | `ModelListService` | 调用供应商 `/models` 接口 |
| 动态互动 | `MomentInteractionSettingsStore` | 自动评论人数和自动回复层数 |
| 自动消息 | `ProactiveMessageStore` | 自动消息全局设置 |
| 自动消息服务 | `ProactiveMessageService` | 手动测试和调度状态读取 |
| 网络 | `http` | 模型列表请求 |
| 数据模型 | `ModelProvider` / `ModelOption` / `ModelSelection` / `ModelPreset` | 供应商、模型能力、当前选择、预设 |

### 3.2 状态监听

```dart
AnimatedBuilder(
  animation: Listenable.merge([
    ModelStore.instance.selection,
    ModelStore.instance.activePresetId,
    ModelStore.instance.presets,
    ThemeStore.instance.themeMode,
    MomentInteractionSettingsStore.instance.settings,
    ProactiveMessageStore.instance.settings,
```

监听目的：

- 模型或预设变化后，模型入口的副标题实时更新。
- 主题变化后，外观入口的副标题实时更新。
- 动态互动设置变化后，动态互动的副标题实时更新。
- 自动消息设置变化后，自动消息的副标题实时更新。

### 3.3 模型摘要逻辑

`_modelSummary()` 按以下顺序生成副标题：

1. 读取 `ModelStore.instance.selection.value`。
2. 通过 `ModelProviderCatalog.byId()` 获取供应商，找不到时使用默认供应商。
3. 如果 `selection.hasModel == false`，显示 `${provider.name} · 尚未选择模型`。
4. 如果存在当前预设 `activePresetId`，显示预设名称。
5. 否则显示 `${provider.name} · ${selection.modelId}`。

### 3.4 外观摘要逻辑

`_themeModeLabel()`：

| ThemeMode | 文案 |
|---|---|
| `ThemeMode.system` | 跟随系统 |
| `ThemeMode.light` | 浅色模式 |
| `ThemeMode.dark` | 深色模式 |

### 3.5 动态互动摘要逻辑

`_momentInteractionSummary()`：

- `autoCommentCount <= 0`：显示「评论关闭」；
- 否则显示「评论 N 人」；
- `autoReplyDepth <= 0`：显示「回复关闭」；
- 否则显示「回复 N 层」；
- 最终格式：`评论 N 人 · 回复 N 层` 或对应的关闭状态。

### 3.6 自动消息摘要逻辑

`_proactiveMessageSummary()`：

- 总开关关闭：显示「关闭」；
- 沉默关闭：显示「沉默关闭」，否则显示「沉默 60-180 分钟」；
- 定时关闭：显示「定时关闭」，否则显示「定时 N 个」；
- 最后追加「每日 N 条」。

## 4. 模型设置页

文件：`lib/pages/settings/model_settings_page.dart`  
类型：`StatefulWidget`

### 4.1 页面状态

| 字段 | 类型 | 说明 |
|---|---|---|
| `_apiKeyController` | `TextEditingController` | API Key 输入 |
| `_modelListService` | `ModelListService` | 模型列表请求 |
| `_providerId` | `String` | 当前供应商 ID |
| `_modelId` | `String` | 当前模型 ID |
| `_models` | `List<ModelOption>` | 当前供应商的模型列表 |
| `_modelsError` | `String?` | 模型列表错误信息 |
| `_loadingModels` | `bool` | 是否正在加载模型 |
| `_savingKey` | `bool` | 是否正在保存/清除 Key |
| `_obscureKey` | `bool` | 是否隐藏 API Key |
| `_modelRequestId` | `int` | 异步请求序号，用于丢弃过期响应 |

初始化流程：

1. 从 `ModelStore.instance.selection.value` 读取供应商和模型。
2. 从 `ModelStore.instance.modelsFor(providerId)` 读取模型缓存。
3. 从 `ApiKeyStore.instance.keyFor(providerId).value` 读取已保存 Key。
4. `addPostFrameCallback` 中，如果已有 Key，自动请求模型列表。

```text
    │   ├── 保存 API Key 按钮
    │   └── 清除按钮（已配置时显示）
    └── 模型预设卡片
        ├── 标题「模型预设」
        ├── 预设列表 / 空状态

        ├── 删除按钮
        └── 「保存当前配置为预设」按钮
```

### 4.3 供应商切换

`_changeProvider()` 流程：

1. 校验供应商 ID 存在。
2. 保存旧状态：供应商、模型、Key 输入、模型列表。
3. `_modelRequestId++`，使进行中的模型请求失效。
4. 更新 UI：
   - 新供应商；
   - 清空模型；
   - 读取新供应商的模型缓存；
   - 清空错误与加载状态；
   - 读取新供应商的 Key。
5. 调用 `ModelStore.instance.saveSelection()` 持久化。
6. 保存失败时回滚旧状态并提示。
7. 如果新供应商已有 Key，自动请求模型列表。

### 4.4 模型选择

`_changeModel()`：

1. 先乐观更新 `_modelId`。
2. 调用 `ModelStore.instance.saveSelection()` 持久化。
3. 保存失败时回滚并提示「模型设置保存失败，请重试」。

模型下拉框：

- 数据源为 `_modelOptions`。
- 如果当前模型 ID 不在模型列表中，会临时插入一个 `ModelOption`，`supportsVision = false`。
- 支持视觉的模型在名称右侧显示 `Icons.image_outlined` 图标。
- 选中后立即保存。

### 4.5 模型列表加载

`_loadModels()` 流程：

1. 如果正在加载，直接返回。
2. 读取安全存储中的已保存 Key。
3. 读取输入框中的 Key。
4. 校验：
   - 没有已保存 Key：提示先保存 Key；
   - 输入框与已保存 Key 不一致：提示先保存修改后的 Key。
5. `_modelRequestId++` 并记录当前 `provider`。
6. 调用 `ModelListService.fetchModels()`。
7. 成功后：
   - 调用 `ModelStore.instance.saveModels()` 缓存模型列表与视觉能力；
   - 更新 `_models`。
8. 失败：
   - 展示 `ModelListException.message` 或通用提示。
9. `finally` 中仅在请求序号仍然有效时结束加载状态。

模型列表缓存：

- `ModelStore.modelCatalog`：`Map<String, List<ModelOption>>`；
- 持久化 Key：`llm_model_catalog`；
- 缓存包含模型 `id`、`name`、`supportsVision`；
- 缓存持久化失败不影响本次会话内存数据。

模型提示文案 `_modelHelperText`：

| 条件 | 文案 |
|---|---|
| 有错误 | 显示错误信息 |
| 列表为空且加载中 | 正在获取模型列表 |
| 列表为空且未加载 | 保存 Key 后自动获取，也可点击刷新 |
| 当前模型不在列表 | 无法确认图片能力，请刷新或重新选择 |
| 当前模型支持视觉 | 支持图片识别，可在对话页发送图片 |
| 当前模型不支持视觉 | 只能发送文本 |
| 其他 | 已获取 N 个模型 |

### 4.6 API Key 管理

保存 `_saveApiKey()`：

1. 去除首尾空格，空值提示。
2. 调用 `ApiKeyStore.instance.save(providerId, key)`。
3. 成功后将输入框内容规范化为去空格后的 Key。
4. 自动调用 `_loadModels()`。

清除 `_clearApiKey()`：

1. `_modelRequestId++`。
2. 调用 `ApiKeyStore.instance.clear(providerId)`。
3. 清空输入框、模型列表、错误与加载状态。

存储规则：

- 每个供应商独立 Key：`api_key_<providerId>`；
- 当前 DeepSeek：`api_key_deepseek`；
- 兼容旧版本 Key：`deepseek_api_key`，读取时自动迁移；
- 底层使用 `flutter_secure_storage`（Android Keystore / iOS Keychain）。

### 4.7 模型预设

保存预设：

1. 要求 `_modelId` 非空。
2. 弹出 `_PresetNameDialog`，默认名称 `${provider.name} · ${modelId}`。
3. 调用 `ModelStore.instance.savePreset(name: name)`。
4. 同名预设会被替换，新预设成为当前预设。

应用预设：

1. 校验预设中的供应商仍受支持。
2. 调用 `ModelStore.instance.applyPreset(preset.id)`。
3. 更新页面供应商、模型、模型缓存和 Key 输入框。
4. 没有 Key 时提示配置，有 Key 时自动加载模型列表。

删除预设：

1. 弹出确认对话框。
2. 调用 `ModelStore.instance.deletePreset(preset.id)`。
3. 删除当前预设后 `activePresetId` 置空，当前模型选择保留。

预设徽标：

- `_ActivePresetBadge` 通过 `AnimatedBuilder` 监听 `presets` 与 `activePresetId`；
- 有当前预设时显示预设名称，最大宽度 140，单行省略。

### 4.8 异常与竞态处理

| 机制 | 说明 |
|---|---|
| `_modelRequestId` | 供应商切换、预设切换、清除 Key 时递增，丢弃旧请求结果 |
| `mounted` 检查 | 所有异步回调更新 UI 前检查页面是否仍存在 |
| 乐观更新 + 回滚 | 供应商、模型、主题保存失败时恢复旧状态 |
| Key 一致性校验 | 输入框 Key 与已保存 Key 不一致时禁止拉取模型 |
| 缓存失败降级 | `saveModels` 持久化失败只保留内存缓存，不阻断页面 |
| 空 Key 校验 | 保存、拉取、发送前均检查 Key |

## 6. 动态互动设置页

文件：`lib/pages/settings/moment_interaction_settings_page.dart`  
类型：`StatefulWidget`  
数据模型：`lib/models/moment_interaction_settings.dart`  
存储：`lib/services/moment_interaction_settings_store.dart`

### 6.1 默认值与范围

| 字段 | 默认值 | 范围 | 说明 |
|---|---|---|---|
| `autoCommentCount` | 2 | 0-5 | 每条新动态自动评论的角色数；0 表示关闭 |
| `autoReplyDepth` | 1 | 0-3 | 自动回复最大嵌套层数；0 表示关闭 |

### 6.2 页面状态

- `_settings`：当前编辑中的 `MomentInteractionSettings`。
- `_update()`：调用 `normalized()` 后更新。
- `_save()`：保存失败时显示 SnackBar「保存动态互动设置失败，请重试」。
- `_reset()`：恢复默认值并立即保存。

### 6.3 页面结构

```text
MomentInteractionSettingsPage
├── AppBar「动态互动」
└── ListView
    ├── 说明文字
    ├── 自动评论人数卡片
    │   ├── 说明
    │   ├── Slider 0-5
    │   └── 两端标签
    ├── 自动回复层数卡片
    │   ├── 说明
    │   ├── Slider 0-3
    │   └── 两端标签
    ├── 恢复默认设置
    └── 成本提示
```

### 6.4 生效方式

- 设置在滑块 `onChangeEnd` 时保存；
- 在下一次动态或评论触发自动互动时生效；
- 用户直接回复角色评论时不受 `autoReplyDepth` 限制，被回复的角色会主动回复一次；
- 自动评论人数大于 1 时，额外角色会作为共同好友加入同一条评论线程。

详细互动逻辑见 `.docs/20261108-动态页面开发文档.md`。

### 7.4 定时时间编辑

- 使用 `showTimePicker`；
- 初始时间 08:00；
- 添加后去重、排序；
- 使用 `HH:mm` 格式存储；
- 时间 chip 支持删除；
- 定时问候关闭时，添加和删除按钮不可用。

### 7.5 免打扰编辑

- 开始和结束分别使用 `showTimePicker`；
- 支持跨午夜，例如 23:30-07:00；
- 开始和结束相同表示不启用实际静默区间；
- 时间段内不会主动发送消息。

### 7.6 手动测试

「立即让角色发一条」流程：

1. 读取 `CharacterStore.instance.cards.value`；
2. 底部弹窗选择角色；
3. 调用 `ProactiveMessageService.instance.triggerNow(character.id)`；
4. 成功发送：提示「已让「角色名」主动发了一条消息」；
5. 模型选择 `[沉默]`：提示「这轮选择沉默，没有发送消息」；
6. 缺少模型/API Key、角色不存在等异常：显示 `ProactiveMessageException.message`。

手动触发不消耗每日额度，也不增加未回复计数。

### 7.7 单角色配置

单角色的自动消息开关和每日上限不在本页，而在：

- `lib/pages/character/character_chat_settings_page.dart` 的「允许主动消息」卡片。

单角色状态存储 Key：

```text
proactive_message_state_v1_<conversationId>
```

单角色 `dailyLimit = 0` 表示跟随全局总上限；全局每日总上限仍然生效。

### 7.8 运行限制

- 自动消息只在应用前台或从后台恢复时检查；
- 应用被系统关闭后无法保证定时发送；
- 每次自动触发或追问都会调用一次当前模型；
- 未配置模型或 API Key 时自动跳过；

## 11. 开发注意事项

- 设置页不直接操作 `SharedPreferences` 或 `FlutterSecureStorage`，统一通过 Store。
- 模型列表来自供应商 `/models` 接口，不在代码中硬编码；新增供应商时只需扩展 `ModelProviderCatalog`。
- 切换供应商会清空当前模型，这是刻意设计，避免模型 ID 与供应商不匹配。
- 模型视觉能力依赖 `ModelOption.supportsVision`，对话页据此决定是否显示图片按钮。
- 预设保存的是「供应商 + 模型」，不包含 API Key；Key 始终按供应商独立保存。
- 保存操作采用乐观更新，失败必须回滚，避免 UI 与持久化状态不一致。
- 所有异步请求都要考虑页面销毁和过期响应。
- 动态互动设置和自动消息设置都在 `onChangeEnd` / 开关变化时立即持久化，不设置单独的保存按钮。
- 自动消息设置页只负责全局配置；单角色开关和上限属于角色设置页。
- 自动消息不要在设置页直接启动 Timer，统一由 `ProactiveMessageService` 调度。
- 设置页新增入口时，需要同步更新 `SettingsPage` 的 `AnimatedBuilder` 监听和摘要逻辑。
- 自动消息前台/恢复限制必须在页面中明确说明，避免用户误以为应用关闭后仍会发送。
