# 设置页面开发文档

> 文档日期：2026-11-08  
> 页面文件：`lib/pages/settings_page.dart`  
> 子页面目录：`lib/pages/settings/`  
> 入口位置：左侧 `UserProfileDrawer` 底部的「设置」入口  
> 说明：设置页已不再是底部导航 Tab；底部第三个 Tab 现在是「动态」

## 1. 页面概览

设置页负责应用级配置，当前包含九个入口：

| 入口 | 子页面 | 功能 |
|---|---|---|
| 模型 | `settings/model_settings_page.dart` | 供应商、模型、API Key、模型预设 |
| 外观 | `settings/appearance_settings_page.dart` | 跟随系统、浅色、深色 |
| 聊天 | `settings/chat_settings_page.dart` | 全局连发倾向、条数范围、字数范围 |
| 心情 | `settings/mood_settings_page.dart` | 心情开关、基线、半衰期、角色心情列表与重置 |
| 日记 | `settings/diary_settings_page.dart` | 每日日记开关、写作时间、立即写一篇 |
| 记忆 | `memory/memory_settings_page.dart` | 长期记忆开关、自动整理、召回和容量 |
| 动态互动 | `settings/moment_interaction_settings_page.dart` | 自动评论人数、自动回复层数 |
| 自动消息 | `settings/proactive_message_settings_page.dart` | 主动消息总开关、沉默触发、定时问候、免打扰、频率保护 |
| 关于 Mori | `settings/about_settings_page.dart` | 版本、模型服务、隐私说明 |

设置主页是 `StatelessWidget`，不持有独立状态；状态来自：

- `ModelStore`
- `ThemeStore`
- `MomentInteractionSettingsStore`
- `ProactiveMessageStore`
- `ChatBurstSettingsStore`
- `MoodStore`
- `DiaryStore`
- `MemoryStore`

设置主页现在自带 `Scaffold` 和 `AppBar`，因为它是从抽屉 push 出来的独立页面，不再嵌入 `HomePage` 的 `IndexedStack`。

监听目的：

- 自动消息设置变化后，自动消息的副标题实时更新。

- 记忆设置变化后，记忆入口的副标题实时更新。

### 3.3 模型摘要逻辑

`_modelSummary()` 按以下顺序生成副标题：

1. 读取 `ModelStore.instance.selection.value`。
2. 通过 `ModelProviderCatalog.byId()` 获取供应商，找不到时使用默认供应商。
3. 如果 `selection.hasModel == false`，显示 `${provider.name} · 尚未选择模型`。
4. 如果存在当前预设 `activePresetId`，显示预设名称。
5. 否则显示 `${provider.name} · ${selection.modelId}`。

### 3.4 外观摘要逻辑

`_themeModeLabel()`：

| ThemeMode | 文案 |
|---|---|
| `ThemeMode.system` | 跟随系统 |
| `ThemeMode.light` | 浅色模式 |
| `ThemeMode.dark` | 深色模式 |

### 3.5 动态互动摘要逻辑

`_momentInteractionSummary()`：

- `autoCommentCount <= 0`：显示「评论关闭」；
- 否则显示「评论 N 人」；
- `autoReplyDepth <= 0`：显示「回复关闭」；
- 否则显示「回复 N 层」；
- 最终格式：`评论 N 人 · 回复 N 层` 或对应的关闭状态。

### 3.6 自动消息摘要逻辑

`_proactiveMessageSummary()`：

- 总开关关闭：显示「关闭」；
- 沉默关闭：显示「沉默关闭」，否则显示「沉默 60-180 分钟」；
- 定时关闭：显示「定时关闭」，否则显示「定时 N 个」；
- 最后追加「每日 N 条」。

### 3.9 日记摘要逻辑

## 4. 模型设置页

文件：`lib/pages/settings/model_settings_page.dart`  
类型：`StatefulWidget`

### 4.1 页面状态

| 字段 | 类型 | 说明 |
|---|---|---|
| `_apiKeyController` | `TextEditingController` | API Key 输入 |
| `_modelListService` | `ModelListService` | 模型列表请求 |
| `_providerId` | `String` | 当前供应商 ID |
| `_modelId` | `String` | 当前模型 ID |
| `_models` | `List<ModelOption>` | 当前供应商的模型列表 |
| `_modelsError` | `String?` | 模型列表错误信息 |
| `_loadingModels` | `bool` | 是否正在加载模型 |
| `_savingKey` | `bool` | 是否正在保存/清除 Key |
| `_obscureKey` | `bool` | 是否隐藏 API Key |
| `_modelRequestId` | `int` | 异步请求序号，用于丢弃过期响应 |

初始化流程：

1. 从 `ModelStore.instance.selection.value` 读取供应商和模型。
2. 从 `ModelStore.instance.modelsFor(providerId)` 读取模型缓存。
3. 从 `ApiKeyStore.instance.keyFor(providerId).value` 读取已保存 Key。
4. `addPostFrameCallback` 中，如果已有 Key，自动请求模型列表。

```text

└── ListView

    │   ├── 供应商下拉框
    │   ├── 供应商描述
    │   ├── 模型下拉框 + 刷新按钮

    │   ├── 分隔线

    │   ├── API Key 输入框（可切换显示）
    │   ├── 保存 API Key 按钮
    │   └── 清除按钮（已配置时显示）
    └── 模型预设卡片
        ├── 标题「模型预设」
        ├── 预设列表 / 空状态
```

### 4.3 供应商切换

`_changeProvider()` 流程：

1. 校验供应商 ID 存在。
2. 保存旧状态：供应商、模型、Key 输入、模型列表。
3. `_modelRequestId++`，使进行中的模型请求失效。
4. 更新 UI：
   - 新供应商；
   - 清空模型；
   - 读取新供应商的模型缓存；
   - 清空错误与加载状态；
   - 读取新供应商的 Key。
5. 调用 `ModelStore.instance.saveSelection()` 持久化。
6. 保存失败时回滚旧状态并提示。
7. 如果新供应商已有 Key，自动请求模型列表。

### 4.4 模型选择

`_changeModel()`：

1. 先乐观更新 `_modelId`。
2. 调用 `ModelStore.instance.saveSelection()` 持久化。
3. 保存失败时回滚并提示「模型设置保存失败，请重试」。

模型下拉框：

- 数据源为 `_modelOptions`。
- 如果当前模型 ID 不在模型列表中，会临时插入一个 `ModelOption`，`supportsVision = false`。
- 支持视觉的模型在名称右侧显示 `Icons.image_outlined` 图标。
- 选中后立即保存。

### 4.5 模型列表加载

`_loadModels()` 流程：

1. 如果正在加载，直接返回。
2. 读取安全存储中的已保存 Key。
3. 读取输入框中的 Key。
4. 校验：
   - 没有已保存 Key：提示先保存 Key；
   - 输入框与已保存 Key 不一致：提示先保存修改后的 Key。
5. `_modelRequestId++` 并记录当前 `provider`。
6. 调用 `ModelListService.fetchModels()`。
7. 成功后：
   - 调用 `ModelStore.instance.saveModels()` 缓存模型列表与视觉能力；
   - 更新 `_models`。
8. 失败：
   - 展示 `ModelListException.message` 或通用提示。
9. `finally` 中仅在请求序号仍然有效时结束加载状态。

模型列表缓存：

- `ModelStore.modelCatalog`：`Map<String, List<ModelOption>>`；
- 持久化 Key：`llm_model_catalog`；
- 缓存包含模型 `id`、`name`、`supportsVision`；
- 缓存持久化失败不影响本次会话内存数据。

模型提示文案 `_modelHelperText`：

| 条件 | 文案 |
|---|---|
| 有错误 | 显示错误信息 |
| 列表为空且加载中 | 正在获取模型列表 |
| 列表为空且未加载 | 保存 Key 后自动获取，也可点击刷新 |
| 当前模型不在列表 | 无法确认图片能力，请刷新或重新选择 |
| 当前模型支持视觉 | 支持图片识别，可在对话页发送图片 |
| 当前模型不支持视觉 | 只能发送文本 |
| 其他 | 已获取 N 个模型 |

### 4.6 API Key 管理

保存 `_saveApiKey()`：

1. 去除首尾空格，空值提示。
2. 调用 `ApiKeyStore.instance.save(providerId, key)`。
3. 成功后将输入框内容规范化为去空格后的 Key。
4. 自动调用 `_loadModels()`。

清除 `_clearApiKey()`：

1. `_modelRequestId++`。
2. 调用 `ApiKeyStore.instance.clear(providerId)`。
3. 清空输入框、模型列表、错误与加载状态。

存储规则：

- 每个供应商独立 Key：`api_key_<providerId>`；
- 当前 DeepSeek：`api_key_deepseek`；
- 兼容旧版本 Key：`deepseek_api_key`，读取时自动迁移；
- 底层使用 `flutter_secure_storage`（Android Keystore / iOS Keychain）。

### 4.7 模型预设

保存预设：

1. 要求 `_modelId` 非空。
2. 弹出 `_PresetNameDialog`，默认名称 `${provider.name} · ${modelId}`。
3. 调用 `ModelStore.instance.savePreset(name: name)`。
4. 同名预设会被替换，新预设成为当前预设。

应用预设：

1. 校验预设中的供应商仍受支持。
2. 调用 `ModelStore.instance.applyPreset(preset.id)`。
3. 更新页面供应商、模型、模型缓存和 Key 输入框。
4. 没有 Key 时提示配置，有 Key 时自动加载模型列表。

删除预设：

1. 弹出确认对话框。
2. 调用 `ModelStore.instance.deletePreset(preset.id)`。
3. 删除当前预设后 `activePresetId` 置空，当前模型选择保留。

预设徽标：

- `_ActivePresetBadge` 通过 `AnimatedBuilder` 监听 `presets` 与 `activePresetId`；
- 有当前预设时显示预设名称，最大宽度 140，单行省略。

### 4.8 异常与竞态处理

| 机制 | 说明 |
|---|---|
| `_modelRequestId` | 供应商切换、预设切换、清除 Key 时递增，丢弃旧请求结果 |
| `mounted` 检查 | 所有异步回调更新 UI 前检查页面是否仍存在 |
| 乐观更新 + 回滚 | 供应商、模型、主题保存失败时恢复旧状态 |
| Key 一致性校验 | 输入框 Key 与已保存 Key 不一致时禁止拉取模型 |
| 缓存失败降级 | `saveModels` 持久化失败只保留内存缓存，不阻断页面 |
| 空 Key 校验 | 保存、拉取、发送前均检查 Key |

## 6. 动态互动设置页

文件：`lib/pages/settings/moment_interaction_settings_page.dart`  
类型：`StatefulWidget`  
数据模型：`lib/models/moment_interaction_settings.dart`  
存储：`lib/services/moment_interaction_settings_store.dart`

### 6.1 默认值与范围

| 字段 | 默认值 | 范围 | 说明 |
|---|---|---|---|
| `autoCommentCount` | 2 | >=0 / 负数 | 每条新动态自动评论的角色数；0 关闭，负数表示无上限 |
| `autoReplyDepth` | 1 | >=0 / 负数 | 自动回复最大嵌套层数；0 关闭，负数表示无上限（内部安全上限 50） |

持久化 Key：`moment_interaction_settings_v1`。

### 6.2 页面状态

- `_settings`：当前编辑中的 `MomentInteractionSettings`。
- `_update()`：调用 `normalized()` 后更新。
- `_save()`：保存失败时显示 SnackBar「保存动态互动设置失败，请重试」。
- `_reset()`：恢复默认值并立即保存。

### 6.3 页面结构

```text
MomentInteractionSettingsPage
├── AppBar「动态互动」
└── ListView
    ├── 说明文字
    ├── 自动评论人数卡片
    │   ├── 说明
    │   └── NumberSettingField 数字输入框
    ├── 自动回复层数卡片
    │   ├── 说明
    │   └── NumberSettingField 数字输入框
    ├── 恢复默认设置
    └── 成本提示
```

自动评论人数和自动回复层数使用 `lib/widgets/number_setting_field.dart` 的数字输入框，不再使用 Slider。输入负数会归一化为 `-1`，表示无上限；正数不设上限，可填写任意非负整数（实际评论人数不会超过可用角色数）。

### 6.4 生效方式

- 设置在输入框失焦、回车或点击输入框外部时保存；
- 在下一次动态或评论触发自动互动时生效；
- 用户直接回复角色评论时不受 `autoReplyDepth` 限制，被回复的角色会主动回复一次；
- 自动评论人数大于 1 时，额外角色会作为共同好友加入同一条评论线程。

详细互动逻辑见 `.docs/20261108-动态页面开发文档.md`。

## 7. 自动消息设置页

### 7.1 默认值与范围

| 字段 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `false` | 全局总开关 |
| `silenceEnabled` | `true` | 沉默触发开关 |
| `scheduledEnabled` | `true` | 定时问候开关 |
| `silenceMinMinutes` | 60 | 沉默间隔下限 |
| `silenceMaxMinutes` | 180 | 沉默间隔上限 |
| `dailyLimit` | 6 | 所有单聊每日总上限；负数表示无上限 |
| `maxUnanswered` | 3 | 连续未回复上限；负数表示无上限 |
| `nudgeEnabled` | `true` | 追问开关 |

### 7.4 数字输入规则

- 所有数字设置使用 `NumberSettingField`，不再使用 Slider / RangeSlider；
- 输入框支持负数；
- 每日总上限、连续未回复上限、单角色每日上限：负数表示无上限；
- 所有数字设置不设上限，可填写任意更大的非负整数；
- 沉默间隔：至少 1 分钟，最长间隔不能小于最短间隔；
- 输入完成后通过失焦、回车或点击输入框外部保存；
- 单角色每日上限：`0` 表示跟随全局，负数表示该角色无上限；
- 自动评论人数 / 自动回复层数：负数表示无上限，自动回复在“无上限”模式下内部最多执行 50 层，避免无限循环。

### 7.5 定时时间编辑

- 使用 `showTimePicker`；
- 初始时间 08:00；
- 添加后去重、排序；
- 使用 `HH:mm` 格式存储；
- 时间 chip 支持删除；
- 定时问候关闭时，添加和删除按钮不可用。

### 7.6 免打扰编辑

- 开始和结束分别使用 `showTimePicker`；
- 支持跨午夜，例如 23:30-07:00；
- 开始和结束相同表示不启用实际静默区间；
- 时间段内不会主动发送消息。

### 7.7 手动测试

「立即让角色发一条」流程：

1. 读取 `CharacterStore.instance.cards.value`；
2. 底部弹窗选择角色；
3. 调用 `ProactiveMessageService.instance.triggerNow(character.id)`；
4. 成功发送：提示「已让「角色名」主动发了一条消息」；
5. 模型选择 `[沉默]`：提示「这轮选择沉默，没有发送消息」；
6. 缺少模型/API Key、角色不存在等异常：显示 `ProactiveMessageException.message`。

手动触发不消耗每日额度，也不增加未回复计数。

### 7.8 运行诊断

点击「运行诊断」后：

1. 调用 `ProactiveMessageService.diagnose()`；
2. 底部弹窗显示：
   - 全局开关；
   - 模型配置；
   - 服务是否运行；
   - 当前是否免打扰；
   - 今日全局触发次数 / 上限；
   - 上次检查时间；
   - 上次自动触发时间；
   - 每个角色自己的冷却剩余时间；
   - 最近错误及时间；
   - 每个角色的阻塞原因、今日次数、未回复次数、下次沉默时间、上次主动时间和已触发定时槽位。
3. 提供「立即检查一次」：
   - 调用 `checkNow()`；
   - 重新读取诊断状态；
   - 用于确认当前是否满足触发条件。

诊断只读取状态，不会主动发送消息；「立即检查一次」可能触发已经到期的自动消息。

冷却原因会区分场景：定时问候到期时显示「定时问候已到时间，可以触发（不受角色冷却限制）」；只有该角色自己的沉默触发和追问会被「该角色刚触发过，冷却中」阻断，其他角色不受影响。

## 10. 开发注意事项

- 设置页不直接操作 `SharedPreferences` 或 `FlutterSecureStorage`，统一通过 Store。
- 模型列表来自供应商 `/models` 接口，不在代码中硬编码；新增供应商时只需扩展 `ModelProviderCatalog`。
- 切换供应商会清空当前模型，这是刻意设计，避免模型 ID 与供应商不匹配。
- 模型视觉能力依赖 `ModelOption.supportsVision`，对话页据此决定是否显示图片按钮。
- 预设保存的是「供应商 + 模型」，不包含 API Key；Key 始终按供应商独立保存。
- 保存操作采用乐观更新，失败必须回滚，避免 UI 与持久化状态不一致。
- 所有异步请求都要考虑页面销毁和过期响应。
- 动态互动设置和自动消息设置都在 `onChangeEnd` / 开关变化时立即持久化，不设置单独的保存按钮。
- 自动消息设置页只负责全局配置；单角色开关和上限属于角色设置页。
- 自动消息不要在设置页直接启动 Timer，统一由 `ProactiveMessageService` 调度。
- 设置页新增入口时，需要同步更新 `SettingsPage` 的 `AnimatedBuilder` 监听和摘要逻辑。
- 心情设置只保存全局参数；角色心情状态由 `MoodStore` 按角色 ID 管理，页面不直接读写 SharedPreferences。
- 心情只做关键词判断，不额外调用模型；如果以后加入模型判断，必须提供开关并默认关闭。
- 日记自动写作由 `DiaryService` 调度，设置页不要自己启动 Timer。
- 日记只记录有意义的内容，不要直接把完整聊天记录拼进提示词。
- 日记默认关闭；每次自动生成会调用一次当前模型，必须在设置页明确说明。
- 记忆只从单聊提炼；群聊不会注入单聊记忆。
- 记忆自动整理由 `MemoryService` 调度，群公共记忆由 `GroupMemoryService` 调度，不要在设置页直接启动 Timer。
- 记忆召回需要在聊天和主动消息的 system prompt 中统一通过 `MemoryContextBuilder` 生成。
- 自动消息前台/恢复限制必须在页面中明确说明，避免用户误以为应用关闭后仍会发送。

### 13.2 单角色覆盖

`CharacterChatSettingsPage` 新增「聊天连发倾向」卡片：

- 跟随全局；
- 关闭；
- 自然；
- 积极。

选择结果按角色 ID 保存在同一份 `ChatBurstSettings.characterTendencies` 中；选择“跟随全局”会删除该角色的覆盖记录。群聊中每个发言角色也按自己的设置生效。单角色使用对应倾向在全局配置里的条数和字数范围；范围统一在「设置 → 聊天」中调整。

### 13.3 生效方式

`ChatPage._streamReply()` 在构建 system prompt 时读取当前发言角色的有效倾向和范围：

- `off`：不追加连发说明，关闭自动换行/标点拆条；
- `natural`：追加自然连发说明，带上“X-Y 条、每条 Z-W 字”；
- `active`：追加积极连发说明，带上“X-Y 条、每条 Z-W 字”；
- 模型返回条数超过范围上限时，合并多余内容到最后一条；
- `active` 返回条数少于范围下限时，自动续发补齐（最多 2 次）；
- 用户明确要求“多发几条”时，无论倾向如何都追加指定条数的 JSON 连发要求，指定条数会先夹到当前范围内，再执行数量校正与续发。

角色卡编辑页的「填入连发模板」仍然推荐使用：全局倾向负责“要不要鼓励连发”，角色卡负责“说话像不像真人”。

### 14.4 行为影响

- 关键词评分：正向词 `+6`，负向词 `-8`，单条消息总分夹在 `±20`。
- 权重：单聊 `1.0`，群聊 `0.3`，用户本人发言 `1.5`。
- 心情实际值限制在 `5-100`，避免完全失去回复意愿。
- 单聊、群聊、主动消息、角色动态、动态评论/回复都会注入心情上下文。
- 只有非「平平常常」时才注入，避免把角色性格固定成某一种语气。
- 回复气泡延迟按心情系数缩放：超开心 `0.85`、心情不错 `0.92`、平常 `1.0`、有点低落 `1.3`、不太开心 `1.5`。
- 每次关键词心情变化只写入本地，不走模型请求；开启模型判断后每次单聊发言会多一次模型调用。
- 心情按角色独立保存，不同角色互不影响。

### 14.5 与 AuraBot 的差异

已实现：

- 0-100 心情值、基线 60、半衰期衰减；
- 关键词推动心情；
- 可选模型判断心情（默认关闭，失败回退关键词）；
- 心情标签与说话风格；
- 聊天、主动消息和动态上下文注入；
- 回复延迟影响；
- 设置页开关、基线、半衰期与角色重置。

暂未实现：

- 表情包、语音频率和群聊插话积极程度；
- 主动消息触发间隔随心情变化；
- 心情日志 AuraBot 默认保留 200 条，Mori 当前保留 50 条。

详细对照见 `.docs/20261108-自动消息与AuraBot参考开发分析文档.md`。

## 14. 日记设置页

文件：`lib/pages/settings/diary_settings_page.dart`  
类型：`StatefulWidget`  
数据模型：`lib/models/diary.dart`  
存储：`lib/services/diary_store.dart`  
服务：`lib/services/diary_service.dart`  
入口：`SettingsPage` →「日记」；日记列表右上角也可进入

### 15.1 默认值与范围

| 字段 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `false` | 全局默认是否启用每日自动日记 |
| `timeMinutes` | `22:30` | 全局默认写作时间，范围 0-1439 分钟 |
| `recallEnabled` | `true` | 是否把最近日记注入单聊和主动消息 |
| `recallCount` | `2` | 每次最多注入几篇日记，0-5 |
| `characterSettings` | `{}` | 按角色覆盖的开关和时间；没有记录表示跟随全局 |

持久化 Key：

```text
diary_settings_v1     全局日记设置和按角色覆盖
character_diary_v1    所有角色的日记
diary_state_v1        每个角色的生成状态与重试信息
```

### 15.2 页面结构

```text
DiarySettingsPage
├── AppBar「日记」
└── ListView
    ├── 每日日记卡片
    │   ├── 全局开关 SwitchListTile
    │   ├── 全局写作时间 ListTile（showTimePicker）
    │   ├── 「让角色记得最近的日记」SwitchListTile
    │   └── 召回日记条数 NumberSettingField（0-5）
    ├── 「立即写一篇」角色选择
    ├── 「角色单独设置」角色列表
    │   └── 点角色打开单独设置弹窗
    │       ├── 跟随全局 / 单独设置
    │       ├── 该角色日记开关
    │       └── 该角色写作时间
    ├── 「只记录有意义的内容」说明
    └── 本地保存 / 模型调用 / 补写限制说明
```

### 15.3 自动写作

- 默认关闭，开启后每天在设定时间检查；
- 全局开关和时间作为默认值；单角色可以单独覆盖开关和时间；
- 单角色设置优先于全局设置：全局关闭时，单独开启的角色仍会写；
- 到点后按当天素材为每个角色写一篇；
- 每轮最多生成一篇，多个角色按 30 秒检查间隔依次处理；
- 目标日期已有日记或已成功生成过时跳过；
- 失败后 30 分钟重试；
- 凌晨 06:00 前会补写前一天错过的日记；
- 未配置模型或 API Key 时自动跳过；
- 应用被系统关闭后不保证准点生成；
- 「让角色记得最近的日记」默认开启，单聊和主动消息会读取最近最多 5 篇日记作为只读上下文，群聊不读取；
- 召回日记条数为 0 时等同于关闭上下文注入。

### 15.4 手动写作

「立即写一篇」：

1. 底部弹窗选择角色；
2. 调用 `DiaryService.instance.writeNow(characterId)`；
3. 生成成功后提示「已生成「角色名」今天的日记」；
4. 当天已有日记时覆盖；
5. 缺少模型、API Key 或生成失败时显示具体错误。

### 15.5 与日记列表的关系

- 日记列表位于「记忆与角色卡」→「日记」；
- 设置页只负责全局开关、全局时间、角色单独设置和手动生成；
- 浏览、删除和空状态在 `DiaryPage` 中完成；
- 单聊的「角色设置」页也提供「日记」卡片，直接打开该角色的单独设置弹窗；
- 删除角色卡会级联删除该角色的日记、生成状态和单独设置。

详细实现见 `.docs/20261108-日记功能开发文档.md`。

## 15. 记忆设置页

文件：`lib/pages/memory/memory_settings_page.dart`  
数据模型：`lib/models/memory.dart`  
存储：`lib/services/memory_store.dart`  
服务：`lib/services/memory_service.dart`  
入口：`SettingsPage` →「记忆」；记忆库右上角也可进入

### 16.1 默认值与范围

| 字段 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 是否启用长期记忆和召回 |
| `groupMemoryEnabled` | `true` | 是否启用群聊公共记忆和群印象 |
| `autoExtract` | `true` | 是否自动从单聊和群聊提炼记忆 |
| `recallCount` | `6` | 每次最多召回条数，0-20 |
| `extractIdleMinutes` | `10` | 聊天闲置多少分钟后开始整理 |
| `extractMinMessages` | `8` | 新消息达到多少条才整理 |
| `maxMemoriesPerCharacter` | `500` | 每个角色最多保留记忆数 |

持久化 Key：

```text
memory_settings_v1    全局记忆设置
character_memory_v1   按角色保存的记忆
memory_state_v1       每个角色的整理游标和重试状态
character_memory_profile_v1  按角色保存的人物小档案
character_memory_topics_v1   按角色保存的未完成话题
group_memory_v1       按群保存的群公共记忆
group_memory_state_v1 每个群的整理游标和重试状态
group_memory_profile_v1 按群保存的群印象
```

### 16.2 页面结构

```text
MemorySettingsPage
├── AppBar「记忆设置」
└── ListView
    ├── 启用长期记忆
    ├── 自动整理记忆
    ├── 启用群聊公共记忆
    ├── 召回条数 NumberSettingField
    ├── 自动整理闲置时间 NumberSettingField
    ├── 自动整理最少消息数 NumberSettingField
    ├── 每个角色最多记忆数 NumberSettingField
    ├── 立即整理记忆
    ├── 清空某个角色的记忆
    └── 隐私 / 模型调用 / 容量说明
```

### 16.3 自动整理

- 服务每 60 秒检查一次；
- 单聊最后一条消息超过闲置时间、且新消息达到最少条数时触发；
- 每轮最多整理一个角色；
- 一次最多处理 40 条消息，保存游标后下一次继续；
- 失败后 30 分钟重试；
- 未配置模型或 API Key 时自动跳过；
- 记忆总开关或自动整理关闭时不自动运行。

### 16.4 手动操作

- 「立即整理记忆」：选择角色后立即整理，不使用闲置时间和最少消息数限制；
- 「清空某个角色的记忆」：二次确认后清空该角色的全部记忆；
- 手动整理失败时显示具体错误。

### 16.5 与记忆库的关系

- 记忆库位于「记忆与角色卡」→「记忆」；
- 设置页只负责开关、召回和整理参数；
- 浏览、搜索、添加、编辑和删除在 `MemoryLibraryPage` 中完成；
- 删除角色卡会级联删除该角色记忆和整理状态。

详细实现见 `.docs/20261108-记忆库功能开发文档.md`。
