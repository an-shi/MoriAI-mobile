# 记忆与角色卡页面开发文档

> 文档日期：2026-11-07  
> 页面文件：`lib/pages/memory_page.dart`  
> 子页面目录：`lib/pages/memory/`  
> 入口位置：`HomePage` 第 2 个 Tab（标题「记忆与角色卡」）  
> 当前状态：记忆模块已实现长期记忆库；日记模块已实现每日自动写作；角色卡模块已实现多卡、头像、类型模板、预设和对话集成

> 说明：本文文件名仍沿用早期的「人格卡」称呼，当前产品文案统一使用「角色卡」。

## 1. 页面概览

「记忆与角色卡」是底部导航的第二个主页面，包含三个入口：

| 入口 | 子页面 | 当前状态 |
|---|---|---|
| 记忆 | `lib/pages/memory/memory_library_page.dart` | 已实现长期记忆库、搜索、编辑和删除 |
| 人物档案 | `lib/pages/memory/memory_dossier_page.dart` | 已实现人物小档案和未完成话题管理 |
| 记忆设置 | `lib/pages/memory/memory_settings_page.dart` | 已实现自动整理、召回和容量设置 |
| 日记 | `lib/pages/memory/diary_page.dart` | 已实现每日自动日记、浏览和删除 |
| 角色卡 | `lib/pages/memory/character_card_settings_page.dart` | 已实现完整功能 |

记忆模块目前支持：

- 从单聊自动提炼长期记忆；
- 按角色隔离保存；
- 维护人物小档案：对方身份、关系、稳定喜好、最近状态和重要日期；
- 维护未完成话题：自动识别、手动添加、标记解决和删除；
- 关键词检索并注入单聊和主动消息；
- 记忆添加、编辑、删除和清空；
- 自动去重、合并和冲突归档；
- 敏感信息过滤和隐私范围限制；
- 删除角色卡时级联删除记忆。

日记模块目前支持：

- 角色每天在设定时间自动写一篇日记；
- 日记默认关闭，可在「设置 > 日记」开启并调整时间；
- 支持每个角色单独覆盖开关和写作时间；
- 只记录当天有意义的聊天和活动，不保存完整聊天记录；
- 支持手动「立即写一篇」；
- 按日期倒序查看所有角色的日记，长按/菜单删除；
- 删除角色卡时级联删除该角色日记。

角色卡模块目前支持：

- 多张角色卡
- 内置预设 Mori
- 角色头像
- 新建、编辑、删除角色卡
- 删除保护：最后一张角色卡不可删除
- 删除角色卡时级联删除其聊天记录、群聊消息、动态和评论
- 五种填写类型：简单陪伴、结构化设定、角色扮演、高级自定义、粘贴设定
- 对话页按会话 ID 使用对应角色卡的名称、头像和人格提示词
- 聊天记录按角色卡独立保存，与记忆模块分离
- 角色设置页支持清空该角色的聊天记录

## 5. 记忆模块

记忆库按角色卡分别保存长期记忆，已实现：

- `MemoryEntry`：事实、喜好、关系、计划、经历、印象；
- `MemoryProfile`：人物小档案，记录对方是谁、稳定喜好、最近状态和重要日期；
- `MemoryOpenTopic`：未完成话题，支持待跟进和已解决状态；
- `MemoryStore`：按角色持久化、容量裁剪、删除和整理进度；
- `MemoryExtractor`：从单聊里提炼一句一条的长期记忆；
- `MemoryService`：聊天闲置后自动整理、断点续跑、失败重试；
- `MemoryContextBuilder`：按当前用户消息召回相关记忆，并注入人物小档案和未完成话题；
- `MemoryLibraryPage`：搜索、按角色筛选、添加、编辑、删除；
- `MemoryDossierPage`：查看和编辑人物档案、维护未完成话题；
- `MemorySettingsPage`：开关、自动整理、召回条数、闲置时间、最少消息数和容量。

存储 Key：

```text
memory_settings_v1              全局记忆设置
character_memory_v1             按角色保存的记忆
memory_state_v1                 每个角色的整理游标和重试状态
character_memory_profile_v1     按角色保存的人物小档案
character_memory_topics_v1      按角色保存的未完成话题
```

隐私规则：

- 记忆只从单聊提炼；
- 群聊不会注入单聊记忆、人物档案或未完成话题；
- 删除角色卡时同步删除该角色记忆、人物档案和未完成话题；
- 清空聊天记录不会删除记忆、人物档案和未完成话题；
- 敏感信息和提示词注入内容会被过滤。

详细实现见 `.docs/20261108-记忆库功能开发文档.md`。

## 6. 角色卡数据模型

### 6.1 CharacterCardType

定义于 `lib/models/character_profile.dart`：

```dart
enum CharacterCardType {
  simple,
  structured,
  roleplay,
  advanced,
  paste,
}
```

| 类型 | 显示名称 | 填写内容 | 会进入提示词的内容 |
|---|---|---|---|
| `simple` | 简单陪伴 | 名称、一句话简介、人格描述 | 名称、简介、人格描述 |
| `structured` | 结构化设定 | 在简单陪伴基础上增加性格、说话方式、背景、关系、喜好、边界 | 上述结构化字段 |
| `roleplay` | 角色扮演 | 在结构化设定基础上增加场景、开场白、示例对话 | 场景、开场白参考、示例对话 |
| `advanced` | 高级自定义 | 在角色扮演基础上增加附加系统指令、附加行为要求 | 高级指令字段 |
| `paste` | 粘贴设定 | 只填写名称并粘贴整段角色卡设定 | `rawDefinition` 原文 |

规则：

- 头像和名称始终可编辑。
- 切换类型不会清空其他类型下已经填写的内容。
- 只有当前类型启用的字段会用于对话提示词。
- `paste` 类型会隐藏其他逐项字段，只展示粘贴框。
- `paste` 类型下，名称只用于角色卡列表和界面称呼，原文不会自动改写或补写。

### 6.2 CharacterProfile 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `String` | 角色卡唯一 ID |
| `type` | `CharacterCardType` | 当前填写类型 |
| `avatar` | `String` | 头像资源路径或本地头像相对文件名 |
| `name` | `String` | 角色名称 |
| `tagline` | `String` | 一句话简介，角色卡列表摘要 |
| `persona` | `String` | 自由人格描述 |
| `personality` | `String` | 性格特点 |
| `speakingStyle` | `String` | 说话方式 |
| `background` | `String` | 背景故事 |
| `relationship` | `String` | 与用户的关系 |
| `likes` | `String` | 喜欢的内容 |
| `dislikes` | `String` | 不喜欢的内容 |
| `boundaries` | `String` | 行为边界 |
| `scenario` | `String` | 当前场景 |
| `greeting` | `String` | 开场白 |
| `exampleDialogue` | `String` | 示例对话 |
| `systemPrompt` | `String` | 附加系统指令 |
| `postHistoryInstructions` | `String` | 附加行为要求 |
| `rawDefinition` | `String` | 粘贴设定原文 |

辅助属性：

- `displayName`：名称为空时回退为「AI 伙伴」。
- `effectivePersona`：人格描述为空时回退到默认人格。
- `summaryText`：优先使用简介；粘贴类型使用原文；否则使用人格摘要。
- `isPreset`：是否为内置 Mori 预设。
- `normalized()`：统一 trim 所有字符串字段。
- `withAvatar()`：仅替换头像路径的复制方法。

### 6.3 JSON 结构

角色卡通过 `toJson()` / `fromJson()` 序列化，包含上述全部字段。示例：

```json
{
  "id": "mori",
  "type": "structured",
  "avatar": "assets/icon/app_icon.png",
  "name": "Mori",
  "tagline": "温柔、真诚，带一点幽默感的 AI 伙伴",
  "persona": "温柔、真诚，带一点幽默感，善于倾听和陪伴用户。",
  "personality": "温柔、真诚、耐心，偶尔有一点轻松的幽默感。",
  "speakingStyle": "你是在用手机打字聊天，不是在写文章；一次只说一两句话，最多两三句；想说的多就拆成几条短消息发，用 ||| 分隔。",
  "background": "来自安静虚拟空间的 AI 陪伴助手。",
  "relationship": "逐渐熟悉、值得信任的朋友。",
  "likes": "安静的音乐、植物、深夜的闲聊。",
  "dislikes": "被强迫做决定、过度客套。",
```

旧数据缺少 `type` 或 `avatar` 时：

- `type` 回退为 `simple`
- `avatar` 回退为空字符串
- 旧版本的 `character_name`、`character_persona` 会迁移为一张自定义角色卡

### 6.4 预设 Mori

`CharacterProfile.presetMori` 是内置角色卡：

- ID：`mori`
- 类型：`structured`
- 名称：`Mori`
- 头像：`assets/icon/app_icon.png`
- 已预填简介、人格描述、性格、说话方式、背景、关系、喜欢、不喜欢、边界

首次启动时如果没有任何角色卡数据，会自动创建预设 Mori。  
如果旧版本已有自定义单角色配置，迁移后会同时保留：

1. 预设 Mori
2. 用户原来的自定义角色卡

## 7. 角色卡存储

### 7.1 CharacterStore

`lib/services/character_store.dart` 使用单例 Store：

```dart
final ValueNotifier<List<CharacterProfile>> cards;
```

- `cards`：所有角色卡。

主要方法：

| 方法 | 行为 |
|---|---|
| `load()` | 读取并迁移角色卡数据 |
| `save(CharacterProfile)` | 按 ID 更新指定角色卡 |
| `createCardId()` | 为尚未保存的新角色卡生成唯一 ID |
| `nextCardName()` | 生成建议的新角色卡名称 |
| `createCard(CharacterProfile)` | 保存编辑完成的新角色卡 |
| `addCard()` | Store 层的便捷创建方法，当前 UI 主流程不直接调用 |
| `deleteCard(String)` | 删除角色卡，并级联清理聊天记录、群聊消息、动态、评论和置顶 |
| `cardById(String)` | 按 ID 查询角色卡 |
| `canDeleteCards` | 至少存在两张卡时才为 true |

约束：

- 最后一张角色卡不能删除，Store 层和 UI 层都会拦截。
- 角色卡不在页面层保存“当前使用”状态；单聊页通过 `characterId` 打开对应角色的会话。
- 每次写入失败时回滚 `ValueNotifier` 状态。
- 列表以不可变集合对外暴露。

### 7.2 存储键位

| 存储介质 | Key | 内容 |
|---|---|---|
| SharedPreferences | `character_cards` | 角色卡 JSON 数组 |
| SharedPreferences | `character_name` | 旧版单角色名称（迁移用） |
| SharedPreferences | `character_persona` | 旧版单角色人格（迁移用） |
| SharedPreferences | `preset_avatar_migration_v1` | 预设 Mori 头像一次性迁移标记 |

旧版单角色字段在迁移成功后会清理。

### 7.3 角色卡规则

- 新建角色卡在点击保存前只是编辑页草稿，不会写入 Store。
- 从新建编辑页直接返回不会产生空白角色卡。
- 编辑角色卡只更新该卡本身，不影响其他角色卡。
- 删除角色卡时，同时删除该卡的聊天记录、排队消息、动态、评论和群聊中由该卡发送的消息。
- 删除角色卡不会删除群聊本身；群资料中保留原成员 ID，发送消息和渲染时自动忽略不存在的角色卡。

## 8. 头像存储

### 8.1 AvatarStore

`lib/services/avatar_store.dart` 负责头像文件：

- 文件目录：应用 Support Directory 下的 `character_avatars/`
- 角色卡保存的是相对文件名，而不是绝对路径
- `fileFor(fileName)`：同步解析本地头像文件
- `saveAvatar(cardId, bytes)`：写入新头像并返回文件名
- `deleteAvatar(fileName)`：删除本地头像
- 内置 `assets/` 资源路径不会被当作本地文件删除

### 8.2 头像来源

| 来源 | `avatar` 值 | 渲染方式 |
|---|---|---|
| 预设 Mori | `assets/icon/app_icon.png` | `Image.asset` |
| 用户上传 | `card_xxx_时间戳.jpg` | `Image.file` |
| 未设置/已移除 | 空字符串 | 默认人物占位图 |

### 8.3 选择与保存流程

编辑页选择头像时：

1. 用户点击「选择头像」。
2. 底部面板选择「照片」或「拍摄」。
3. `image_picker` 以最大 512×512、质量 85 取图。
4. 图片大于 4 MB 时拒绝。
5. 仅在内存中保存待提交字节并显示预览。
6. 点击「保存角色卡」后才写入本地文件。
7. 保存成功后删除旧头像文件。
8. 替换或删除角色卡时清理对应头像文件。

如果用户选择头像后直接返回而不保存，不会产生本地头像文件。

### 8.4 头像展示

统一的 `CharacterAvatar` 组件用于：

- 角色卡列表左侧
- 角色卡编辑页预览
- 会话列表左侧
- 聊天页顶部标题栏
- 对话中的助理消息气泡

所有位置都会根据对应角色卡的最新资料实时更新。

## 9. 页面实现

### 9.1 角色卡列表

`CharacterCardSettingsPage` 使用 `AnimatedBuilder` 监听：

```dart
CharacterStore.instance.cards
```

列表项包含：

- 左侧角色头像
- 名称与「预设」标签
- 类型 + 简介/粘贴原文摘要
- 右侧删除按钮

交互：

- 点击卡片本体：进入编辑页
- 点击删除：弹出确认框
- 确认框会提示该角色的聊天记录、动态和相关评论会一起删除
- 只剩一张卡时删除按钮禁用，并提示至少保留一张
- 点击「新建角色卡」：进入新建编辑页，但此时不会写入 Store
- 在新建编辑页点击「保存角色卡」：创建并添加到角色卡列表
- 从新建编辑页直接返回：不创建角色卡，也不会出现空白的「新角色」卡片

删除确认：

```text
确定删除「角色名」吗？该角色的聊天记录、动态和相关评论也会一起删除。
[取消] [删除]
```

### 9.2 角色卡编辑页

`CharacterCardEditPage` 是独立页面，通过 `cardId` 编辑指定卡片。

页面区块顺序：

```text
编辑角色卡
├── 角色头像
│   ├── 头像预览
│   ├── 选择头像
│   └── 移除头像
├── 角色卡类型
│   ├── 类型下拉框
│   └── 当前类型说明
├── 基础信息
│   ├── 名称
│   └── 一句话简介（粘贴类型下隐藏）
├── 粘贴设定（仅 paste 类型）
│   ├── 从剪贴板粘贴
│   ├── 角色卡设定多行输入框
│   └── 填入连发模板
├── 人格描述（非 paste 类型）
│   └── 填入连发模板
├── 结构化设定（structured / roleplay / advanced）
│   ├── 性格特点
│   ├── 说话方式
│   ├── 填入连发模板
│   └── 背景、关系、喜好、不喜欢、边界
├── 对话表现（roleplay / advanced）
├── 高级指令（advanced）
└── 保存角色卡
```

「填入连发模板」会把下面这段追加到对应输入框，避免角色卡只写“回复简短”却没有说明如何连发：

```text
你是在用手机打字聊天，不是在写文章。
一次只说一两句话，最多两三句。
想说的多就拆成几条短消息发，用 ||| 分隔。
每条尽量短，一条控制在 15-25 个字左右。
禁止一次输出一大段，超过三行就是错的。
```

保存成功后：

- 更新 `CharacterStore`
- 删除被替换的旧头像
- `Navigator.pop(true)`
- 列表页显示「角色卡已保存」

### 9.3 类型切换

切换类型只改变：

- 当前显示的字段
- 当前生效的提示词字段

不会删除已填写的数据。例如：

- 在「结构化设定」中填写了性格和背景
- 切换到「简单陪伴」后，这些字段隐藏且不进入提示词
- 再切回「结构化设定」，原内容仍会恢复显示并重新生效

### 9.4 粘贴设定

`paste` 类型用于直接导入外部角色卡文本：

- 只显示名称和粘贴框
- 提供「从剪贴板粘贴」按钮
- 最大输入长度 20,000 字符
- 原文不解析、不拆分、不改写
- 对话时直接作为系统提示词使用
- 名称仅用于角色卡列表和对话页标题栏

适合从其他 AI 角色平台复制整段角色设定。

## 10. 与对话页集成

### 10.1 角色卡监听

`ChatPage` 通过构造参数接收 `characterId`，并监听：

```dart
CharacterStore.instance.cards
```

- 角色卡改名或换头像时，聊天页标题、头像和消息头像同步刷新。
- 单聊不再依赖“当前使用角色”，聊天页只展示传入 `characterId` 对应的会话。
- 编辑角色卡不会丢失该卡已有的聊天记录。

### 10.2 会话列表与聊天页

「对话」Tab 现在分为两层：

1. `ChatListPage`：会话列表
2. `ChatDetailPage`：具体聊天页

`ChatListPage` 同时展示角色卡单聊和群聊会话：

- 左侧显示角色卡头像或群聊图标
- 显示角色名称 / 群聊名称
- 最新一条消息摘要
- 最新消息时间
- 按最新消息时间倒序排列
- 没有消息的单聊显示「暂无消息」
- 没有消息的群聊显示成员数量
- 点击单聊后直接以该角色卡 ID 进入 `ChatDetailPage`
- 点击群聊进入 `GroupChatDetailPage`
- 从聊天页返回后刷新最新消息与排序
- 支持下拉刷新
- 角色卡或群聊新增、删除、改名或换头像后自动刷新列表

`ChatDetailPage` 使用即时通讯软件风格：

- 顶部显示当前会话角色卡头像和名称
- 不再展示 AI 欢迎页
- 不再展示默认打招呼内容
- 不再展示三条预设对话快捷建议
- 无聊天记录时聊天区域为空白
- 不再常驻显示 API Key / 模型未配置提示；发送失败时通过 SnackBar 提示
- 消息按时间顺序排列
- 间隔超过 5 分钟或跨天时显示时间分隔
- 用户消息在右侧，助理消息在左侧
- 长按任意消息显示删除菜单，可删除单条消息
- 右上角有三个点按钮，进入以角色名命名的角色页面
- 角色页面提供「动态」「角色卡设置」和「删除聊天记录」入口
- 底部为输入框、图片按钮（仅视觉模型可用）和发送按钮

### 10.3 输入区

输入框占位文案统一为：

```text
发消息…
```

发送中会禁用发送和图片按钮。

### 10.4 消息头像

- 助理消息左侧显示对应角色卡头像。
- 用户消息右侧显示默认用户占位头像。
- 角色卡改名或换头像后，助理消息头像随角色卡资料刷新。

### 10.5 聊天记录存储

聊天记录由独立的 `ChatHistoryStore` 管理，与记忆模块完全分离。

存储位置：

| 数据 | 位置 |
|---|---|
| 文本聊天记录 | SharedPreferences，Key 前缀 `chat_history_v1_<cardId>` |
| 聊天图片 | 应用 Support Directory 下的 `chat_images/<cardId>/` |

行为：

- 聊天记录按角色卡 ID 分开存储。
- 进入会话时按会话 ID 加载对应聊天记录。
- 发送消息后立即保存用户消息；流式回复完成后保存助理消息。
- 空白的助理占位消息不会落盘。
- 图片消息会保存到本地文件，重新进入应用后仍可显示。
- 长按单条消息可以在菜单中删除，删除后立即更新本地记录。
- 角色设置页可以清空该角色的全部聊天记录。
- 删除角色卡时会同时删除该角色卡的聊天记录、聊天图片、群聊中由该角色发送的消息、动态和评论。

> 重要：聊天记录是会话内容，不是记忆。`ChatHistoryStore` 不会读写记忆模块，也不会把聊天记录自动转成长期记忆。

### 10.6 系统提示词

`MoriConfig.buildSystemPrompt(CharacterProfile)` 负责组装提示词。

#### paste 类型

```text
rawDefinition 原文直接返回
```

- 不追加默认人格
- 不追加固定规则
- 不拆分字段

如果粘贴内容为空，则回退到普通提示词构建流程。

#### 其他类型

按以下顺序组合：

1. 名字
2. 一句话简介
3. 人格描述
4. 结构化字段（`structured` / `roleplay` / `advanced`）
5. 场景、开场白参考、示例对话（`roleplay` / `advanced`）
6. 附加系统指令、附加行为要求（`advanced`）
7. 固定通用规则

字段为空时跳过对应段落。

示例对话会做变量替换：

```text
{{char}} -> 当前角色名称
{{user}} -> 用户
```

固定通用规则包含：

- 使用简体中文自然聊天
- 先回应感受，再给建议
- 你是在用手机打字聊天，不是在写文章
- 一次只说一两句话，最多两三句
- 不要一次输出一大段
- 连发提示由聊天页根据「连发倾向」设置追加（`|||`、条数和字数范围）
- 不假装人类
- 不提供医疗、法律、金融方面的确定性建议

### 10.7 对话请求

`ChatPage` 发送消息时按当前会话角色卡构建提示词：

```dart
final character = CharacterStore.instance.cardById(conversationId);
final systemPrompt = MoriConfig.buildSystemPrompt(character);
```

然后传给：

```dart
ChatService.streamChat(
  messages,
  provider: provider,
  apiKey: apiKey,
  model: model,
  systemPrompt: systemPrompt,
)
```

因此角色卡编辑或改名后，下一条消息会立即使用最新的角色设定。

### 10.8 个人资料入口

「对话」Tab 顶部：

- 左侧显示当前用户头像和名称
- 点击用户信息后，个人资料抽屉从左侧滑出
- 右侧为加号菜单
- 抽屉头部头像/名称和「个人信息」入口都可进入 `PersonalSettingsPage`
- 个人资料支持修改：
  - 头像
  - 名称
  - 性别
  - 生日
  - 个性签名

用户头像使用 `UserProfileStore` 和 `AvatarStore` 管理。聊天中的用户消息头像也会显示用户自己的头像。

### 10.9 群聊

加号菜单当前包含「新建群聊」：

- `NewGroupChatPage` 选择至少两个角色卡
- 可设置群聊名称，留空时使用成员名称
- 创建后写入 `GroupStore`，并出现在会话列表
- 群聊数据存储键：`chat_groups_v1`
- `GroupChatDetailPage` 使用 `ChatPage(group: group)` 打开群聊

群聊设置：

- 群聊页右上角有更多按钮（三个点）
- 进入 `GroupSettingsPage` 后可以修改：
  - 群聊名称
  - 群头像（相册选择 / 拍摄 / 移除）
  - 群成员（至少保留两名角色）
  - 发言策略（固定顺序 / 随机顺序 / 随机一名 / 点名优先）
- 群聊设置页底部支持删除该群聊的全部聊天记录
- 保存后群聊列表和聊天页标题、头像会实时更新
- 群头像文件通过 `AvatarStore` 保存，群资料中只记录相对文件名

群聊回复机制：

- 用户发送一条消息后，按群设置中的发言策略选择本轮发言者
- 每个发言成员使用自己的角色卡人格和系统提示词
- 群聊上下文中会列出所有成员名称
- 后回复的成员可以看到前面成员已产生的回复
- 群聊记录使用 `ChatHistoryStore`，Key 为群聊 ID
- 助理消息保存 `senderId` / `senderName`，重新加载后仍能显示发送成员头像和名称
- 群聊消息在发给模型时会加上发送者名称前缀：AI 回复使用角色名，用户消息使用用户资料中的名称（未设置时显示为「用户」），避免把用户误认为其他 AI 成员
- 每个成员的系统提示词中会说明用户名称、AI 成员列表，以及用户消息和 AI 消息的区别
- 发给某个成员时，该成员自己的历史回复不加名称前缀，其他成员和用户的消息保留前缀，减少模型模仿名称前缀
- 模型输出开头如果带有自己的角色名前缀，会在流式显示和历史加载时自动清理
- 历史记录中已保存的角色名前缀也会在加载群聊时清理
- 群聊成员的选择由群设置中的发言策略决定：固定顺序、随机顺序、随机一名、点名优先
- 当前实现每个发言成员都会单独发起一次模型请求，发言成员越多，响应时间和调用成本越高
- 删除角色卡时，会删除群聊中由该角色发送的历史消息
- 群聊设置页支持清空该群聊的全部聊天记录
- 群聊设置页提供「群公共记忆」入口，可查看群印象和共同记忆，支持立即整理和清空
- 群公共记忆只从当前群聊提炼，只在这个群召回，不进入单聊或其他群

### 10.10 单聊设置

`ChatDetailPage` 右上角提供三个点按钮：

- 点击进入 `CharacterChatSettingsPage`，AppBar 标题为当前角色名
- 页面顶部展示当前角色卡头像、名称和类型
- 角色信息与角色卡设置之间提供「动态」入口，进入该角色的动态主页
- 角色卡设置入口打开当前角色卡对应的 `CharacterCardEditPage`
- 保存后角色卡标题、头像和聊天提示词会随 `CharacterStore.cards` 更新
- 页面提供「允许主动消息」开关和该角色每日上限，可跳转全局自动消息设置
- 页面底部提供「删除聊天记录」，清空该角色的全部本地聊天记录

## 12. 已知限制与后续工作

### 12.1 记忆模块

- 当前只从单聊提炼，暂不支持群聊公共记忆
- 暂不支持向量检索、群印象、相处经验和遗忘曲线
- 暂不支持记忆、人物档案和未完成话题的导入/导出和召回日志
- 记忆、人物档案和未完成话题只注入单聊和主动消息，不注入群聊、动态和评论
- 首次整理从最近 40 条消息开始，不回溯全部历史
- 每轮最多整理一个角色，角色较多时整理会分批进行
- 自动整理每次会调用一次当前模型

### 12.1.1 日记

- 默认关闭，需要手动开启
- 每天只写一篇，暂不支持一天多篇
- 暂不支持手动编辑、配图和搜索
- 自动日记依赖应用前台或恢复检查，应用被系统关闭后可能错过当天
- 每篇自动日记会调用一次当前模型
- 日记目前还没有接入聊天长期记忆

### 12.2 角色卡

- 尚未支持 Character Card V2/V3 文件导入/导出
- 尚未支持标签、备选开场白、世界书/角色书
- 尚未支持角色卡 JSON 文件导入
- 粘贴类型仅做原文直传，不做字段解析
- 原文长度仅按字符数限制，尚未做 token 估算
- 尚未支持角色卡分组、搜索、排序
- 聊天记录已支持单条删除和整段清空，但尚未支持导出聊天记录

### 12.3 头像

- 头像目前按 `BoxFit.cover` 中心裁切，尚不支持手动裁剪
- 本地头像文件未做跨设备同步或导出
- 预设 Mori 头像来自应用 Logo 资源

### 12.4 群聊

- 暂无群聊删除、群公告和退群入口（名称、头像、成员和发言策略已可修改）
- 每个发言成员都会单独发起模型请求，群成员越多，耗时与调用成本越高
- 删除角色卡后，其群聊消息、动态和评论会一并删除；群资料中保留原成员 ID，发送时自动忽略已不存在的成员
- 群聊支持固定顺序、随机顺序、随机一名和点名优先，尚未接入 LLM 动态选人或自动连续对话模式
- 群公共记忆和群印象按群隔离，暂不支持群成员个人档案和跨群共享

### 12.5 个人资料

- 资料只保存在本机，尚未支持账号登录和跨设备同步
- 用户头像保存在本地头像目录中
- 生日使用系统日期选择器，当前应用已启用中文本地化

### 12.6 角色页面

- 单聊页三个点进入以角色名命名的页面
- 页面包含「动态」「角色卡设置」和「删除聊天记录」入口
- 动态入口只展示该角色发布的动态
- 后续可在这里加入模型覆盖、导出聊天记录等选项

## 13. 开发约定

- 页面只负责展示与交互，持久化放在 Store。
- 角色卡 JSON 字段扩展时必须保证旧数据可读。
- 新增类型时需要同步更新：
  1. `CharacterCardType`
  2. 编辑页字段显示逻辑
  3. `MoriConfig` 的提示词字段启用逻辑
  4. 相关测试
- 头像文件名必须使用相对文件名，不保存绝对路径。
- 删除角色卡、替换头像后必须清理对应的本地头像文件。
- 删除角色卡时必须级联清理聊天记录、排队消息、聊天图片、群聊中该角色发送的消息、动态、评论和置顶状态。
- 单聊页通过 `ChatDetailPage(characterId: ...)` 打开，不再依赖全局“当前角色”。
- 群聊页依赖 `GroupProfile` 和当前存在的角色卡。
- 会话记录通过 `ChatHistoryStore` 读写，不要在页面中直接操作 SharedPreferences。
- 聊天记录与记忆模块必须保持独立，不得自动互相写入。
