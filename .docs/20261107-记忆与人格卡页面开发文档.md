# 记忆与人格卡页面开发文档

> 文档日期：2026-11-07  
> 页面文件：`lib/pages/memory_page.dart`  
> 入口位置：`HomePage` 第 1 个 Tab（标题「记忆与人格卡」）  
> 页面类型：`StatelessWidget`（当前为占位实现）

## 1. 页面概览

「记忆与人格卡」是底部导航的第二个主页面，规划承载两类内容：

- **记忆**：Mori 在长期对话中记住的用户信息、偏好、事件与约定。
- **人格卡**：定义 Mori 或不同角色的人格设定、语气、背景与开场白。

当前代码只实现了「记忆」的空状态占位，人格卡尚未实现。本文档分为两部分：

1. 当前已实现内容。
2. 后续开发设计建议（明确标记为未实现）。

## 2. 当前实现

### 2.1 入口与导航

`lib/pages/home_page.dart` 中：

```dart
static const _titles = ['对话', '记忆与人格卡', '设置'];
static const _pages = [ChatPage(), MemoryPage(), SettingsPage()];
```

- 第二个 Tab 的标题与导航标签均为「记忆与人格卡」。
- 三个页面使用 `IndexedStack` 保持状态。
- 键盘弹出时底部导航隐藏。
- 页面外层 `AppBar` 由 `HomePage` 提供，`MemoryPage` 自身没有 `Scaffold` 和 `AppBar`。

### 2.2 页面结构

当前 `MemoryPage` 为纯展示组件：

```text
MemoryPage（StatelessWidget）
└── Center
    └── Padding（水平 32）
        └── Column（mainAxisSize: min）
            ├── Container 72×72 圆形
            │   └── Icon(Icons.auto_stories_outlined)
            ├── SizedBox(height: 20)
            ├── Text('还没有记忆')
            └── Text('Mori 记住的内容会出现在这里')
```

样式：

- 图标容器颜色：`Theme.of(context).colorScheme.secondaryContainer`。
- 图标颜色：`onSecondaryContainer`。
- 标题：`headlineSmall`，`FontWeight.w600`。
- 副标题：`bodyMedium`，颜色 `onSurfaceVariant`，居中对齐。

### 2.3 状态与数据

当前没有：

- 页面状态字段。
- 数据模型。
- Store 或本地持久化。
- 网络服务。
- 用户交互按钮。
- 人格卡相关代码。

因此页面刷新、重启后没有任何数据变化。

## 3. 待开发功能：记忆模块

> 以下设计尚未在代码中实现，仅作为后续开发的技术方案。

### 3.1 数据模型建议

新增 `lib/models/memory_item.dart`：

```dart
enum MemoryCategory { preference, event, profile, relationship, other }

class MemoryItem {
  final String id;
  final String content;
  final MemoryCategory category;
  final DateTime createdAt;
  final DateTime updatedAt;
  final String? sourceMessageId;

  Map<String, dynamic> toJson();
  factory MemoryItem.fromJson(Map<String, dynamic> json);
}
```

设计要点：

- `id` 使用时间戳或 UUID。
- `content` 保存可直接注入模型上下文的自然语言文本。
- `category` 用于页面筛选与展示。
- `sourceMessageId` 可选，用于追溯记忆来源。
- JSON 解析需校验字段类型，损坏条目跳过，不影响其他数据。

### 3.2 Store 建议

新增 `lib/services/memory_store.dart`：

```dart
class MemoryStore {
  static final MemoryStore instance = MemoryStore._();

  final ValueNotifier<List<MemoryItem>> items = ValueNotifier([]);

  Future<void> load();
  Future<void> add(MemoryItem item);
  Future<void> update(MemoryItem item);
  Future<void> delete(String id);
  Future<void> clear();
}
```

实现建议：

- 数据量较小可继续使用 `SharedPreferences`，Key 建议为 `memory_items`。
- 数据量增长或需要全文检索时，改用 `sqflite` / Drift。
- 写入失败时回滚 `ValueNotifier`，与现有 `ModelStore` 的错误处理方式保持一致。
- 列表对外暴露不可变集合。

### 3.3 记忆服务建议

新增 `lib/services/memory_service.dart`，可选职责：

- 从对话中抽取值得记住的信息。
- 对记忆去重、合并、分类。
- 根据当前对话检索相关记忆。
- 生成注入对话的上下文片段。

如果不希望增加额外模型调用，也可以先做手动记忆管理，仅提供增删改查。

### 3.4 页面结构建议

建议将 `MemoryPage` 改为 `StatefulWidget` 或拆分出子页面，并采用：

```text
MemoryPage
├── TabBar / 顶部分段
│   ├── 记忆
│   └── 人格卡
├── 记忆列表
│   ├── 空状态（复用当前设计）
│   └── MemoryItemTile × N
│       ├── 内容摘要
│       ├── 分类标签
│       ├── 更新时间
│       └── 删除 / 编辑
└── 新增记忆按钮
```

交互建议：

- 点击条目进入详情或编辑页。
- 左滑或菜单删除，删除前确认。
- 支持按分类筛选。
- 支持手动新增记忆。
- 空状态与列表状态切换使用 `ValueListenableBuilder`。

### 3.5 与对话页集成建议

当前 `ChatService` 只拼接固定的 `MoriConfig.systemPrompt`。若要注入记忆，需要扩展请求构造逻辑，例如：

```dart
final systemPrompt = [
  MoriConfig.systemPrompt,
  if (memoryContext.isNotEmpty) '以下是你记住的信息：\n$memoryContext',
].join('\n\n');
```

可选方案：

1. `ChatService.streamChat` 增加 `String? extraSystemContext` 参数。
2. 由 `ChatPage` 组装完整 system prompt 后传入。
3. 新增 `PromptBuilder` 统一管理系统提示词、人格卡与记忆，避免逻辑散落在页面中。

## 4. 待开发功能：人格卡模块

> 当前代码未实现任何人格卡模型、存储或界面。

### 4.1 数据模型建议

新增 `lib/models/persona_card.dart`：

```dart
class PersonaCard {
  final String id;
  final String name;
  final String description;
  final String personality;
  final String tone;
  final String background;
  final String greeting;
  final String? avatarPath;

  Map<String, dynamic> toJson();
  factory PersonaCard.fromJson(Map<String, dynamic> json);
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `id` | 人格卡唯一标识 |
| `name` | 角色名称 |
| `description` | 一句话介绍 |
| `personality` | 性格、价值观、行为边界 |
| `tone` | 语气与表达风格 |
| `background` | 角色背景故事 |
| `greeting` | 进入对话时的开场白 |
| `avatarPath` | 本地头像路径（可选） |

### 4.2 Store 建议

新增 `lib/services/persona_store.dart`：

```dart
class PersonaStore {
  static final PersonaStore instance = PersonaStore._();

  final ValueNotifier<List<PersonaCard>> cards = ValueNotifier([]);
  final ValueNotifier<String?> activeCardId = ValueNotifier(null);

  Future<void> load();
  Future<void> save(PersonaCard card);
  Future<void> delete(String id);
  Future<void> activate(String id);
}
```

存储建议：

- `SharedPreferences` Key：`persona_cards`、`persona_active_id`。
- 默认人格卡可以不落盘，由代码内置并在首次启动时使用。
- 删除当前人格卡后回退到默认人格。

### 4.3 页面结构建议

人格卡区域可采用列表 + 编辑器：

```text
人格卡
├── 当前使用的人格卡摘要
├── 人格卡列表
│   └── PersonaCardTile
│       ├── 头像 / 名称 / 描述
│       ├── 使用中标记
│       └── 编辑 / 删除
├── 新建人格卡按钮
└── 编辑页
    ├── 名称
    ├── 一句话介绍
    ├── 性格设定
    ├── 语气设定
    ├── 背景故事
    ├── 开场白
    └── 保存 / 删除
```

### 4.4 与对话页集成建议

人格卡最终应影响 system prompt。建议新增统一的提示词组装器：

```text
最终 system prompt =
  MoriConfig.systemPrompt
  + 当前人格卡设定
  + 相关记忆上下文
```

注意：

- 需要限制总长度，避免超出模型上下文窗口。
- 人格卡字段为空时不拼接对应段落。
- 记忆与人格卡都应参与每次对话请求，而不是只影响 UI。
- 需要明确优先级：人格卡约束 > 记忆事实 > 通用系统提示词。

## 8. 开发注意事项

- 当前页面没有任何数据层，新增功能时不要直接在 `MemoryPage` 内操作 `SharedPreferences`，应保持 `pages → services → models` 的分层。
- 记忆属于用户隐私数据，正式实现时需要明确本地存储方式与清除入口。
- 人格卡与记忆会进入 system prompt，需要处理长度上限与敏感内容。
- 若后续引入数据库，建议把记忆与对话历史统一放在同一存储层，避免多套持久化方案并存。
- 在功能实现前，本文档第 3、4 节均为设计建议，不代表现有代码行为。
