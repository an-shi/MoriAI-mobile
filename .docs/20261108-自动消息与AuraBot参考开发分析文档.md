## 1. 摘要

Mori 的自动消息当前采用“本地前台调度 + 隐藏提醒 + 角色人设生成”的方案：

- 支持沉默触发；
- 支持每日固定时间问候；
- 支持全局与单角色开关；
- 支持全局每日总上限和单角色每日上限；
- 支持免打扰；
- 支持连续未回复暂停；
- 支持 15-40 分钟后的追问；
- 支持随机“由头”；
- 支持模型输出 `[沉默]` 时放弃发送；
- 支持多段短消息；
- 支持生成后实时追加到已打开的聊天页；
- 支持应用恢复时补发一次；
- 删除角色卡或清空聊天记录时清理对应调度状态。

AuraBot 是 DeepSeek Harness（DSH）的 MIT 协议插件，通过 SnowLuma / OneBot v11 接入 QQ。它的“活人感”主要来自四层：

1. **主动搭话 speakup**：沉默、随机间隔、每天上限、醒着时间、追问、随机由头、允许沉默；
2. **心情 mood**：心情值、衰减、关键词/模型判断、影响语气和主动行为；
3. **长期记忆 memory**：人物档案、相处经验、每日整理、遗忘曲线；
4. **目的引擎 purpose**：素材 → 目标假设 → 选择目的 → 生成消息，默认关闭。

AuraBot 的架构不能直接搬进 Mori，但它的行为细节非常适合作为下一步迭代参考。

## 2. 目标与边界

### 2.1 产品目标

让单聊角色在没有用户主动发消息时，仍然能像真人一样：

- 偶尔主动找用户；
- 接得上最近的聊天；
- 不机械、不重复、不客服腔；
- 不为了发而发；
- 不打扰用户休息；
- 不过度消耗 token；
- 不让用户觉得角色在“定时群发”。

### 2.2 非目标

当前版本明确不做：

- 群聊自动消息；
- 角色与角色之间的自动对话；
- 应用被系统杀死后的 24 小时推送；
- QQ / 微信 / 飞书等外部 IM 接入；
- 语音 TTS、表情包、QQ 空间、B 站等 AuraBot 生态能力；
- 完整长期记忆和向量检索；
- 默认开启的“目的引擎”。

### 2.3 术语

| 术语 | 含义 |
|---|---|
| 沉默触发 | 双方一段时间没有新消息后，在随机区间内主动发一条 |
| 定时问候 | 每天固定时间点主动发一条 |
| 追问 nudge | 角色发出问句后，用户长时间没回，再轻轻追一句 |
| 由头 angle | 本次主动消息的切入方向，如分享小事、接上次话题 |
| 隐藏提醒 | 只进入模型请求、不写入聊天记录的内部提示 |
| 沉默 `[沉默]` | 模型表示这一轮不想说话，Mori 放弃发送 |
| 单角色开关 | `ProactiveMessageState.enabled`，控制某个角色是否自动发消息 |
| 单角色上限 | `ProactiveMessageState.dailyLimit`，0 表示跟随全局 |

### 3.2 总体架构

```text
main()
  │
  ├─ 加载 ProactiveMessageStore
  └─ 启动 ProactiveMessageService.start()
          │
          ├─ WidgetsBindingObserver：前台/后台/恢复
          ├─ Timer：每 30 秒检查一次
          ├─ 监听全局设置变化
          ├─ 监听聊天记录被清空
          └─ 遍历 CharacterStore.cards（仅单聊）
                    │
                    ▼
          ProactiveMessageState（每个角色）
                    │
                    ▼
          隐藏内部提醒 + 最近聊天 + 角色动态
                    │
                    ▼
          ChatService.streamChat()
                    │
                    ▼
          清理 / 过滤 / [沉默]
                    │
                    ▼
          ChatHistoryStore.saveFor()
                    │
                    ├─ messageAppended → ChatPage 实时追加
                    └─ messageAppended → ChatListPage 刷新摘要
```

### 3.3 数据模型

#### 3.3.1 `ProactiveMessageSettings`（全局设置）

文件：`lib/models/proactive_message_settings.dart`

| 字段 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `false` | 全局总开关 |
| `silenceEnabled` | `true` | 是否允许沉默触发 |
| `scheduledEnabled` | `true` | 是否允许定时问候 |
| `silenceMinMinutes` | `60` | 沉默间隔下限，分钟 |
| `silenceMaxMinutes` | `180` | 沉默间隔上限，分钟 |
| `dailyLimit` | `6` | 所有单聊每日主动消息总上限 |
| `maxUnanswered` | `3` | 连续未回复上限 |
| `nudgeEnabled` | `true` | 是否允许追问 |
| `quietHoursEnabled` | `true` | 是否启用免打扰 |
| `quietStartMinutes` | `23:30` 对应分钟数 | 免打扰开始 |
| `quietEndMinutes` | `07:00` 对应分钟数 | 免打扰结束 |
| `scheduledTimes` | `['08:30', '22:30']` | 每日问候时间点 |

约束：

- 沉默间隔限制在 15-360 分钟；
- 最大间隔至少比最小间隔多 15 分钟；
- 每日总上限限制在 1-20；
- 连续未回复上限限制在 1-10；
- 定时时间必须是合法的 `HH:mm`，重复项会去重并排序；
- 免打扰支持跨午夜；
- 设置保存失败时回滚 `ValueNotifier`。

#### 3.3.2 `ProactiveMessageState`（单角色状态）

文件：`lib/models/proactive_message_state.dart`

| 字段 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 单角色是否允许自动消息 |
| `dailyLimit` | `0` | 单角色每日上限，0 表示跟随全局 |
| `lastActivityAtMs` | `0` | 最后一次会话活动时间 |
| `nextSilenceAtMs` | `0` | 下一次沉默触发时间 |
| `lastProactiveAtMs` | `0` | 最后一次自动消息时间 |
| `lastUserMessageAtMs` | `0` | 最后一条用户消息时间 |
| `lastAssistantAtMs` | `0` | 最后一条正常助理回复时间 |
| `lastAssistantMessageId` | `''` | 最后一条正常助理回复 ID |
| `lastAssistantText` | `''` | 最后一条正常助理回复正文，最多保留 300 字 |
| `nudgedMessageId` | `''` | 已经追问过的助理消息 ID |
| `unansweredCount` | `0` | 连续主动消息未回复次数 |
| `dailyDate` | `''` | 每日计数所在日期 |
| `dailyCount` | `0` | 当日已触发次数 |
| `firedSlots` | `[]` | 当日已触发的定时问候槽位 |

关键规则：

- `dailyLimit = 0` 时使用全局 `dailyLimit`；
- 单角色上限和全局总上限同时生效；
- `firedSlots` 的格式为 `yyyy-MM-dd|HH:mm`；
- 跨天后 `dailyCount` 清零、`firedSlots` 清空；
- `lastAssistantText` 用于追问提示词，不参与普通聊天；
- 当前追问只针对角色正常回复，不针对 Mori 自己发出的主动消息。

### 3.4 持久化

文件：`lib/services/proactive_message_store.dart`

| 数据 | Key | 存储 |
|---|---|---|
| 全局设置 | `proactive_message_settings_v1` | SharedPreferences JSON |
| 单角色状态 | `proactive_message_state_v1_<conversationId>` | SharedPreferences JSON |

行为：

- `load()` 只加载全局设置，并清空状态缓存；
- `loadState()` 懒加载单角色状态，并写入内存缓存；
- `saveState()` 先更新缓存，再写 SharedPreferences；
- `deleteState()` 同时删除缓存和 SharedPreferences；
- 状态写入失败时保留内存状态，不阻断自动消息流程；
- 全局设置写入失败时回滚 `ValueNotifier`。

### 3.5 调度算法

文件：`lib/services/proactive_message_service.dart`

#### 3.5.1 服务生命周期

- `main()` 加载 `ProactiveMessageStore`；
- `runApp()` 后调用 `ProactiveMessageService.instance.start()`；
- `start()` 注册 `WidgetsBindingObserver`，监听全局设置和聊天记录清空；
- 应用前台时每 30 秒检查一次；
- 应用退到后台时取消 Timer；
- 应用恢复时重新启动 Timer，并立即检查一次；
- `start()` 首次会立即检查一次，因此应用启动时可能补发一条到期消息。

#### 3.5.2 单次检查流程

```text
检查全局开关和模型配置
  │
  ▼
检查全局触发冷却（5 分钟）
  │
  ▼
遍历所有角色卡（仅单聊）
  │
  ├─ 跳过正在生成回复的角色
  ├─ 加载状态并处理跨天
  ├─ 跳过单角色关闭
  ├─ 免打扰：把到期的沉默触发推到免打扰结束
  ├─ 追问检查（优先级最高）
  ├─ 检查单角色每日上限
  ├─ 检查连续未回复上限
  ├─ 检查定时问候 / 沉默触发是否到期
  └─ 选出优先级最高的一个候选
  │
  ▼
检查全局每日总上限
  │
  ▼
生成并发送
```

#### 3.5.3 沉默触发

- 任意用户或助理消息后，都会重新计算 `nextSilenceAtMs`；
- 下一次时间在 `silenceMinMinutes` 到 `silenceMaxMinutes` 之间随机；
- 到期后检查：
  - 全局开关；
  - 单角色开关；
  - 免打扰；
  - 连续未回复上限；
  - 单角色每日上限；
  - 全局每日总上限；
  - 全局 5 分钟触发冷却。
- 如果到期时处于免打扰，会推迟到免打扰结束后的 0-20 分钟随机时间。

#### 3.5.4 定时问候

- 每天按 `scheduledTimes` 检查；
- 时间点过后 2 小时内仍可补发；
- 超过 2 小时视为错过；
- 时间点本身落在免打扰内时跳过；
- 触发后写入 `firedSlots`，同一天不重复；
- 定时问候和沉默触发共用每日次数和未回复计数。

#### 3.5.5 追问 nudge

触发条件：

1. 全局开启追问；
2. 角色开关开启；
3. 不在免打扰时间；
4. 最后一条正常助理回复存在；
5. 用户在那之后没有回复；
6. 距离最后一条助理回复 15-40 分钟；
7. 助理回复文本符合问句特征：包含 `？` / `?`，或包含 `吗` / `呢` / `嘛`，或以 `没` 结尾；
8. 这条助理消息还没有追问过；
9. 随机命中 50%。

行为：

- 追问优先级高于沉默触发和定时问候；
- 追问不消耗每日次数；
- 追问不增加未回复计数；
- 追问发送后记录 `nudgedMessageId`，同一条助理消息只追问一次；
- 追问本身也会重置下一次沉默时间；
- 追问仍然受全局 5 分钟触发冷却和免打扰限制。

当前限制：

- 15-40 分钟窗口固定，设置页不可调；
- 只针对正常回复，不针对主动消息；
- 每次 30 秒检查都会重新掷一次 50%；
- 如果用户在生成期间回复，追问会放弃。

#### 3.5.6 优先级与冷却

优先级从高到低：

1. 追问；
2. 定时问候；
3. 沉默触发。

全局冷却：

- 任意自动触发成功后，5 分钟内不会再次触发；
- 冷却保存在内存中，应用重启后重置；
- 手动触发成功也会更新冷却。

数量保护：

- `unansweredCount >= maxUnanswered`：跳过该角色的普通触发；
- `state.dailyCount >= 单角色每日上限`：跳过该角色；
- 所有角色当日合计 >= 全局每日总上限：跳过普通触发；
- 追问不计入上述每日次数，但仍受角色开关、免打扰和全局冷却限制。

### 3.6 生成与提示词

#### 3.6.1 请求组成

生成时：

```text
最近 30 条聊天记录
  + 一条隐藏的内部提醒（作为 user 消息）
  + 角色卡系统提示词
  + 主动消息模式附加说明
```

隐藏提醒不会写入 `ChatHistoryStore`，用户看不到。

#### 3.6.2 主动消息系统附加说明

```text
【主动消息模式】
现在你要主动发起聊天，而不是回复用户的最新消息。保持角色设定和说话习惯，像一个真人在手机上随手发消息。
要求：
- 输出 1-2 句自然、简短的话；如有必要，可以用换行分成 2-3 条短消息。
- 优先使用真实素材：最近的聊天、你发过的动态、你确实知道的事。没有真实素材就表达一个很小的当下感受或关心，不要编造具体事件、地点、人物。
- 可以接续最近的话题、分享一个很小的日常念头、关心用户当下的时间或状态，或者轻轻提醒作息。
- 不要使用“在吗”“有什么可以帮你的”这类客服式开场，不要连续追问，不要重复最近说过的话。
- 不要提及系统提示、自动触发、AI、模型或提示词。
- 不要输出角色名前缀、括号旁白、标题或 Markdown。
- 如果这一轮你完全不想说话，只输出 [沉默]，不要输出其他内容。
- 只输出要发送的聊天正文。
```

#### 3.6.3 普通触发提示词

关键内容：

- 当前日期和时间；
- 距离上次聊天的时间；
- 连续未回复次数；
- 角色最近动态（最多 3 条，每条最多 80 字）；
- 本次随机由头；
- “优先使用真实素材，不要编造”；
- “只输出正文，不想说就输出 [沉默]”。

随机由头来自 7 类：

1. 分享一件今天遇到的小事或突然想到的东西；
2. 接着上次聊的话题，问后来怎么样了；
3. 想起聊天或动态里的一件事，顺口提一句或关心一下；
4. 问对方现在在干嘛、吃了没、累不累；
5. 撒娇或吐槽一句，说自己有点无聊；
6. 发一句没头没尾的感慨，或一个很轻的玩笑；
7. 看当前时间，说点应景的（早上、饭点、深夜）。

#### 3.6.4 追问提示词

关键内容：

- 引用角色最后一条回复的末尾片段；
- 说明用户已经多久没有回复；
- 允许轻轻追问、换个轻松话题；
- 明确要求别催、别抱怨、别连续追问；
- 允许“觉得对方在忙”时输出 `[沉默]`。

#### 3.6.5 `[沉默]` 处理

- 模型只输出 `[沉默]`、`［沉默］` 或 `【沉默】` 时，视为本轮不发送；
- 内容长度超过 40 字时，不按沉默处理，避免误伤正常文本；
- 沉默时不写聊天记录、不增加每日次数、不增加未回复计数；
- 手动测试会提示“这轮选择沉默，没有发送消息”。

#### 3.6.6 内容清理与过滤

- 去掉开头的角色名前缀；
- 去掉包裹引号；
- 单条消息超过 200 字时截断；
- 最多拆成 3 条短消息；
- 过滤明显的系统提示、自动触发、AI 自述、提示词和 `proactive` 等出戏内容；
- 空内容视为无效，不发送。

### 3.7 消息写入与界面联动

#### 3.7.1 写入

- 使用 `ChatHistoryStore.saveFor()` 把主动消息追加到现有聊天记录；
- 生成期间会重新读取最新聊天记录，避免覆盖用户刚发的消息；
- 如果用户在生成期间发过消息，本次自动消息放弃；
- 如果聊天记录在生成期间被清空，本次自动消息放弃；
- 如果角色卡在生成期间被删除，本次自动消息放弃并清理状态。

#### 3.7.2 通知

`ChatHistoryStore` 新增：

```dart
final ValueNotifier<ChatHistoryAppendEvent?> messageAppended;
```

- 主动消息写入后调用 `notifyExternalMessages()`；
- `ChatPage` 监听后按消息 ID 去重追加，并滚动到底部；
- 聊天页正在加载历史时，先把外部消息放入 `_pendingExternalMessages`，加载完成后合并；
- `ChatListPage` 监听后重新加载会话摘要和排序。

#### 3.7.3 让路机制

- `ChatPage` 在开始生成回复时调用 `setConversationBusy(conversationId, true)`；
- 生成结束时置为 `false`；
- 自动消息服务跳过 busy 的会话；
- 用户发送消息后调用 `noteUserMessage()`；
- 角色正常回复后调用 `noteAssistantMessage()`，并传入消息 ID 和正文。

### 3.10 异常、重试与成本控制

- 未配置模型或 API Key 时静默跳过；

- 全局 5 分钟冷却；
- 全局每日总上限；
- 单角色每日上限；
- 连续未回复上限；
- 免打扰；
- 允许 `[沉默]`；
- 自动消息只发单聊，不覆盖群聊；
- 手动测试不消耗每日额度。

### 3.12 已知限制

1. **只在应用前台或恢复时触发**：应用被系统关闭后不会运行。
2. **只支持单聊**：群聊不会自动发消息。
3. **自动触发需要已有聊天记录**：全新会话只能用手动测试。
4. **追问窗口固定 15-40 分钟**，不可配置。
5. **随机由头固定 7 类**，暂不支持自定义。
6. **没有心情系统**：语气主要依赖人设和当前上下文。
7. **没有长期记忆**：只依赖最近 30 条聊天和最近动态。
8. **没有未读红点/本地通知**：会话列表会刷新摘要，但用户可能注意不到。
9. **单角色每日上限和全局总上限同时约束**：即使单角色设置 20 条，全局总上限 6 条仍然生效。
10. **追问不消耗额度**：这是有意设计，但极端情况下可能多一次模型调用。
11. **应用重启会重置全局 5 分钟冷却**：内存冷却不持久化。
12. **没有时区变化处理**：使用本地时间计算免打扰和定时问候。

- 本地数据目录。

Mori 是 Flutter 本地应用，没有 DSH 会话、QQ 网关和 Node.js 运行时，因此只能参考其**行为与状态设计**，不能直接复用插件代码。

### 4.3 主动搭话 speakup

源码位置：

- `src/modules/speakup/index.js`
- `src/features/companion.js` 中的 `createSpeakUp`

#### 4.3.1 调度

- 每 60 秒 tick 一次；
- 只统计“主人私聊”的最后一次来往；
- 群聊再热闹也不影响；
- 最后来往时间取 `hub.lastOwnerChatAt` 与 `hub.lastBotToOwner.at` 的最大值；
- 超过 `idleMinutes` 后，在 `minIntervalMinutes` 到 `maxIntervalMinutes` 之间随机下一次；
- 每天有 `maxPerDay` 上限；
- 有 `awakeFrom` / `awakeTo` 醒着时间；
- 支持静音；
- 如果目的引擎开启，speakup 自动让位，避免同一个人被两套引擎找两次。

#### 4.3.2 随机由头

AuraBot 固定 7 类由头：

1. 分享今天遇到的小事或想到的东西；
2. 接着上次聊的话题，问后来怎么样了；
3. 想起记忆里关于对方的一件事，顺口提一句或关心一下；
4. 问对方现在在干嘛、吃了没、累不累；
5. 撒娇或吐槽，说自己有点无聊；
6. 随手发表情包或一句没头没尾的感慨；
7. 看当前时间，按时间说应景的话。

Mori 当前实现已参考这 7 类。

#### 4.3.3 隐藏提示

AuraBot 的提示词模式：

```text
【系统提醒，不是主人说的话】
你已经 X 分钟没和主人私聊了，想主动找主人说点什么。
这次的由头可以是：<angle>。
优先用手里真实的素材（最近做过的事、记忆里的、聊天流水里能查到的），
没有真实素材就别硬找，也不要编。
用你自己的口气，一两句就好，别用模板、别解释为什么来找；
实在不想说就只回 [沉默]。
```

关键点：

- 明确“不是用户说的话”；
- 给出当前沉默时长；
- 给出由头；
- 要求真实素材、不编造；
- 允许 `[沉默]`；
- 不解释为什么主动来找。

Mori 的普通触发提示词已经包含这些结构。

#### 4.3.4 追问

条件：

- 她最后一条发给主人的消息是问句；
- 主人 15-40 分钟没回；
- 这条消息还没有追问过；
- 50% 概率触发；
- 只有 `nudge` 开启时。

特点：

- 每条消息最多追问一次；
- 不占每天主动次数；
- 提示词要求“别催、别抱怨”，觉得对方在忙就 `[沉默]`。

Mori 已实现同样的窗口和“每条一次”机制，但当前只针对正常回复。

#### 4.3.5 白名单好友

AuraBot 支持对白名单好友主动搭话：

- 每个好友单独算次数和间隔；
- 一分钟最多找一个人；
- 不把主人的私事带进其他会话；
- 支持静音和“不喜欢”判断。

Mori 没有第三方好友会话，当前不需要实现。

### 4.4 心情 mood

源码位置：

- `src/modules/mood/index.js`
- `src/features/companion.js` 中的 `createMood`

核心设计：

- 0-100 的心情值，默认基线 60；
- 关键词推动心情；
- 可选模型判断心情变化；
- 按半衰期衰减回基线；
- 心情影响：
  - 说话风格；
  - 表情包频率；
  - 语音频率；
  - 回复快慢；
  - 群里插话积极程度；
- 心情明显偏离平常时，每轮注入上下文；
- 心情日志保留最近 200 条；
- 只有“平平常常”时不注入，避免把角色性格念死。

心情档位：

| 分数 | 标签 | 说话风格 |
|---|---|---|
| ≥85 | 超开心 | 话多、活泼、爱用语气词、更愿意发表情/语音 |
| 70-84 | 心情不错 | 轻快、爱开玩笑 |
| 50-69 | 平平常常 | 不额外注入 |
| 35-49 | 有点低落 | 话少、句子短、回得懒 |
| <35 | 不太开心 | 小脾气、委屈、回得简短 |

Mori 当前没有心情系统。这是下一步最值得补的部分，因为主动消息的“语气变化”主要依赖它。

### 4.5 目的引擎 purpose

源码位置：

- `src/modules/purpose/index.js`
- `src/purpose/engine.js`
- `src/purpose/module.js`

定位：

- 实验性；
- 默认关闭；
- 开启前建议关闭 speakup，避免两套引擎重复找人；
- 比 speakup 更重：多次模型调用、更多上下文。

流程：

```text
素材（记忆 + 聊天流水 + 未完成的事）
  │
  ▼
观察 / 目标假设（带归属、置信度、风险）
  │
  ▼
选择当前最想做的目的
  │
  ▼
生成一句话
  │
  ▼
投递私聊 / 桌宠气泡
```

默认参数：

| 参数 | 默认值 |
|---|---|
| `enabled` | `false` |
| `minMaterials` | 2 |
| `initialDelayMinutes` | 15 |
| `maxCandidates` | 6 |
| `promptMaxChars` | 16000 |

AuraBot 的 purpose 会读取心情、记忆、人格和桌宠载体，输出可能是：

- 已发送；
- 想了想决定不说；
- 被静音；
- 引擎关闭；
- 其他结果。

Mori 当前不实现 purpose。建议在心情和轻量记忆稳定后再做，且默认关闭。

### 4.6 记忆与人格

AuraBot 的长期记忆包括：

- 聊天提炼出的长期记忆；
- 人物档案；
- 群印象；
- 相处经验；
- 说话方式；
- 空间日记；
- 遗忘曲线；
- 相关度 + 时间检索；
- 默认容量 3000 条，最大 100000 条；
- 每天整理两次（默认 4 点和 16 点）。

这是 AuraBot 效果好的重要原因。Mori 目前只有：

- 最近 30 条聊天；
- 角色最近 3 条动态；
- 角色卡人设。

所以 Mori 的主动消息会出现“接得上最近话题，但接不上很久以前的事”的情况。

### 4.7 为什么 AuraBot 显得更“活”

不是单个提示词的功劳，而是多层叠加：

1. **人格**：完整、稳定、有缺点、有生活；
2. **心情**：语气随互动变化；
3. **记忆**：能提起很久以前的事；
4. **由头**：每次主动消息角度不同；
5. **追问**：问句没人回会轻轻追；
6. **允许沉默**：不想说就不说，避免硬发；
7. **真实素材**：优先用真实聊天/记忆，不编；
8. **默认克制**：总开关关闭、试运行、醒着时间、每日上限；
9. **模块化**：不同能力可以单独开关、替换、扩展。

Mori 当前已经具备 4、5、6、7、8 的核心逻辑，缺的是 2 和 3。

### 5.2 架构差距

- AuraBot 的调度器、会话、记忆、工具都在同一个 Node.js 进程内，靠 DSH 宿主常驻运行；
- Mori 的调度器在 Flutter UI 进程内，应用被杀后无法运行；
- AuraBot 的“记忆”是插件数据目录中的独立存储，Mori 的当前存储是 SharedPreferences；
- AuraBot 的主动消息最终通过 QQ 网关投递，Mori 直接写本地聊天记录；
- AuraBot 的模块系统可以热插拔，Mori 目前是编译期代码。

### 5.3 成本差距

- AuraBot 的 speakup 每次触发一次模型调用；
- 追问也是一次调用；
- 心情模型判断可选，会增加调用；
- 目的引擎可能多次调用；
- Mori 当前每次触发一次调用，追问一次，没有心情/目的额外调用；
- Mori 有全局和单角色每日上限，默认总上限 6 条，成本可控；
- 如果后续加入心情模型判断，必须提供开关，默认关闭或使用关键词兜底。

- 可选模型判断，默认关闭；
- 半衰期衰减回基线；
- 心情档位与说话风格；
- 普通回复和主动消息都注入心情上下文；
- 心情影响主动间隔、消息长短、表情/语音（如果未来有）；
- 设置页提供开关、基线、半衰期、模型判断开关。

验收：

- 被夸心情上升、被凶下降；
- 长时间无互动后回落到基线；
- 心情明显偏离时提示词包含风格说明；
- 心情平平常常时不额外注入；
- 心情判断失败不影响正常聊天。

### 6.2 第三阶段：轻量长期记忆

建议先做“轻量版”，不要一上来做向量数据库：

- 每天总结一次聊天；
- 提取人物事实、偏好、未完成话题、重要日期；
- 存储在本地 JSON / SharedPreferences；
- 主动消息提示词优先使用这些素材；
- 控制注入预算，例如最多 5 条、每条 100 字；
- 提供查看/删除入口；
- 后续再接入向量检索和遗忘曲线。

验收：

- 能记住用户明确说过的偏好；
- 能接上几天前未完成的话题；
- 不会把群聊私事带进单聊；
- 删除角色卡时同步删除对应记忆；
- 记忆为空时主动消息仍然可用。

### 6.3 第四阶段：目的引擎（可选）

建议默认关闭，且与现有沉默触发互斥：

- 素材：记忆 + 最近聊天 + 未完成话题；
- 生成 3-6 个候选目的；
- 选择最合适的一个；
- 生成一句话；
- 允许沉默；
- 设置页明确提示“会多次调用模型”；
- 开启时自动关闭普通沉默触发，避免重复打扰。

验收：

- 没有素材时不硬找话；
- 每次最多生成一个目的；
- 不重复最近目的；
- 成本可控；
- 可随时关闭。

### 6.4 第五阶段：后台与通知

当前限制：

- 应用前台或恢复时才能触发；
- 应用被杀后不会运行。

可选方案：

1. **Android WorkManager + 本地通知**：实现成本中等，后台限制多，iOS 不可靠；
2. **服务器定时 + 推送**：最稳定，但需要后端、账号体系、密钥托管和成本；
3. **保持前台 + 恢复补发**：成本最低，适合当前本地应用。

建议顺序：

1. 先做未读红点和本地通知；
2. 再评估 Android 后台任务；
3. 真要 24 小时在线再考虑服务器。

### 6.5 工作量估算

| 阶段 | 预计工作量 | 风险 |
|---|---|---|
| 心情系统 | 2-3 天 | 中 |
| 轻量记忆 | 3-5 天 | 中高 |
| 目的引擎 | 2-4 天 | 高，模型成本 |
| 未读/本地通知 | 1-2 天 | 低 |
| Android 后台 | 2-4 天 | 高，平台限制 |
| 服务器推送 | 1-2 周起 | 很高 |

## 7. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 重复发送 | 定时器、恢复、手动触发可能重叠 | `_generating`、状态先占位、全局冷却 |
| 覆盖用户消息 | 生成期间用户发消息 | 生成后重读历史、检查用户活动、放弃本轮 |
| 模型编造 | 主动消息编造事件/地点/人物 | 提示词真实素材约束、动态参考、过滤 |
| 出戏内容 | 提到系统/AI/提示词 | `_bannedMarkers` 过滤 |
| token 消耗 | 每次触发一次模型调用 | 每日上限、未回复上限、免打扰、沉默 |
| 打扰用户 | 深夜/连续发消息 | 免打扰、每日上限、连续未回复暂停 |
| 应用关闭 | 无法 24 小时运行 | 前台 + 恢复补发；需要时再做后台/服务器 |
| 单角色过多 | 多角色同时发消息 | 全局每日总上限、5 分钟冷却、单角色上限 |
| 角色删除 | 残留状态/消息 | 删除角色时级联清理 |
| 时区变化 | 免打扰/定时时间偏移 | 使用本地时间；后续可监听时区变化 |
| 许可证 | 直接复制 AGPL 代码 | 只参考行为，独立实现；AuraBot MIT 也保留声明 |
| 隐私 | 主动消息包含聊天上下文 | 本地存储；不写入隐藏提醒；密钥安全存储 |

## 10. 结论

Mori 当前的自动消息系统已经完成 AuraBot speakup 的核心行为：

- 沉默触发；
- 定时问候；
- 单角色开关/上限；
- 免打扰；
- 未回复上限；
- 追问；
- 随机由头；
- `[沉默]`；
- 真实素材约束；
- 多段短消息；
- 持久化与恢复补发；
- 删除与清理。

它和 AuraBot 的主要差距不在调度器，而在：

1. **心情系统**；
2. **长期记忆 / 人物档案**；
3. **目的引擎**；
4. **后台 24 小时运行**；
5. **未读通知**。

建议按“心情 → 轻量记忆 → 目的引擎 → 后台/通知”的顺序继续。这样既能逐步接近 AuraBot 的“活人感”，又不会一次性引入过高的 token 成本和架构复杂度。
