# 对话页面开发文档

> 文档日期：2026-11-08
>
> 文档范围：会话列表、单聊、群聊、动态、聊天设置、聊天记录、群聊身份语义
>
> 主要入口：`HomePage` 第 0 个 Tab「对话」
>
> 说明：本文档按当前实现重写，替代 2026-11-07 版本。旧版中的欢迎页、快捷建议和常驻配置提醒已经移除。

## 1. 功能概览

对话模块负责 Mori 的主要聊天交互，当前包含：

- 角色卡单聊与群聊统一显示在会话列表。
- 会话支持长按置顶，置顶会话优先展示。
- 每个角色卡和每个群聊各自保存独立的聊天记录。
- 文本消息发送与大模型流式回复。
- 一轮回复可以拆成多条短气泡连发，接近真人聊天节奏。
- 相册/相机图片发送，仅视觉模型可用。
- 群聊支持固定顺序、随机顺序、随机一名、点名优先等发言策略。
- 回复期间可以继续发送消息，消息进入队列并显示「排队中」「回复中」。
- 支持停止当前流式回复。
- 支持长按删除单条消息，以及清空角色/群聊的聊天记录。
- 支持单聊角色自动消息：沉默触发、定时问候、免打扰和频率保护。
- 支持角色心情：聊天关键词推动、半衰期衰减、上下文注入和回复节奏影响。
- 删除角色卡时会级联清理相关聊天记录、群聊消息、动态和评论。
- 用户资料入口、个人设置和用户头像展示。
- 动态流：用户发布文字动态，角色使用当前模型生成动态。
- 单聊设置与群聊设置。
- 群聊发送者身份区分、角色名前缀清理等语义处理。

页面职责约定：

- 页面负责展示和交互。
- 持久化由 Store 负责。
- 聊天记录与记忆模块完全独立，不自动互相写入。
- 单聊通过 `characterId` 打开对应角色卡会话；群聊使用 `GroupProfile` 中的成员列表。

## 3. 关键数据模型

### 3.1 `ChatMessage`

文件：`lib/models/chat_message.dart`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `String` | 消息 ID，用于图片文件名和稳定标识 |
| `role` | `ChatRole` | `user` 或 `assistant` |
| `content` | `String` | 消息正文 |
| `image` | `ChatImage?` | 可选图片 |
| `createdAt` | `DateTime?` | 消息时间 |
| `senderId` | `String` | 群聊发送者 ID；用户固定为 `user`，AI 为角色卡 ID |
| `senderName` | `String` | 群聊发送者名称，用于界面展示和 API 前缀 |

`ChatImage` 保存图片字节和 MIME 类型，通过 `dataUrl` 转换为：

```text
data:<mimeType>;base64,<base64 字节>
```

### 3.2 `GroupProfile`

文件：`lib/models/group_profile.dart`

| 字段 | 说明 |
|---|---|
| `id` | 群聊 ID，格式为 `group_<microseconds>` |
| `name` | 群名称，空字符串时展示为「群聊」 |
| `avatar` | 群头像相对文件名 |
| `memberIds` | 群成员角色卡 ID 列表 |
| `createdAt` | 创建时间 |
| `replyMode` | 群聊发言顺序策略，默认固定顺序 |

群成员至少需要两个。删除角色卡后，群资料中仍保留原 ID；发送消息时会自动忽略不存在的角色卡。

### 3.3 `UserProfile`

文件：`lib/models/user_profile.dart`

| 字段 | 说明 |
|---|---|
| `name` | 用户名称 |
| `avatar` | 用户头像相对文件名 |
| `gender` | 性别 |
| `birthday` | 生日 |
| `signature` | 个性签名 |

`displayName` 在名称为空时返回「我」，用于顶部栏和资料抽屉。群聊消息中的用户发送者标签使用另一套规则：名称为空时使用「用户」。

## 4. 会话列表

`ChatListPage` 同时展示：

- 所有角色卡单聊。
- 所有已创建的群聊。

每个条目包含：

- 左侧角色卡头像或群头像。
- 会话名称。
- 最新消息摘要。
- 最新消息时间。

### 4.1 摘要与排序

最新消息通过 `ChatHistoryStore.summaryFor(conversationId)` 获取：

- 从最后一条消息向前查找第一条有正文或图片的消息。
- 纯图片消息摘要显示为 `[图片]`。
- 正文中的连续空白会压缩为一个空格。
- 助理的空占位消息不会成为摘要。

排序规则：

1. 置顶会话优先排在所有普通会话之前。
2. 多个置顶会话之间，按最新消息时间倒序。
3. 置顶会话没有消息时排在置顶区域后面。
4. 普通会话按最新消息时间倒序。
5. 没有消息的会话排在普通区域后面。
6. 时间相同时，角色卡按原列表顺序，群聊排在角色卡之后。

### 4.2 刷新与打开

- 角色卡列表或群聊列表变化时自动刷新。
- 从聊天页返回后刷新摘要和排序。
- 支持下拉刷新。
- 没有消息的单聊显示「暂无消息」。
- 没有消息的群聊显示「N 位成员」。
- 点击单聊后以该角色卡 ID 进入 `ChatDetailPage`，不再切换全局“当前角色”。
- 点击群聊直接进入 `GroupChatDetailPage`。

### 4.3 会话置顶

长按会话列表中的单聊或群聊条目，会弹出一个小菜单：

- 未置顶时显示「置顶」。
- 已置顶时显示「取消置顶」。

置顶行为：

- 单聊使用角色卡 ID，群聊使用群聊 ID，两者共用同一套置顶状态。
- 置顶状态由 `PinnedConversationStore` 管理，持久化 Key 为 `pinned_conversations_v1`。
- 置顶条目使用 `surfaceContainerLow` 作为行背景，比普通会话略灰，便于区分。
- 多个置顶会话仍按最新消息时间倒序。
- 取消置顶后恢复普通会话排序。
- 置顶操作失败时通过 SnackBar 提示。

会话列表当前不包含删除和搜索。

### 4.4 未读红点

- 角色主动消息写入后，如果当前没有打开对应会话，按消息条数累加未读；
- 会话列表在名称右侧显示未读徽标；
- 底部「对话」Tab 显示所有会话的未读总数；
- 打开会话后未读自动清零；
- 未读数保存在 `unread_conversations_v1`；
- 删除角色卡或清空聊天记录时同步清理对应未读；
- 当前未读数只来自主动消息，不统计普通聊天里用户离开页面后到达的消息。

## 5. ChatPage 状态与生命周期

### 5.1 构造参数

```dart
ChatPage({super.key, this.group, this.characterId})
```

- `group == null`：单聊模式，使用 `characterId` 对应的角色卡。
- `group != null`：群聊模式。

关键派生值：

| 属性 | 说明 |
|---|---|
| `_isGroup` | 是否为群聊 |
| `_conversationId` | 单聊为 `characterId`，群聊为群聊 ID |
| `_groupMembers` | 按 `memberIds` 顺序解析出的当前有效角色卡 |

### 5.2 关键状态

| 字段 | 类型 | 说明 |
|---|---|---|
| `_messages` | `List<ChatMessage>` | 当前会话消息 |
| `_inputController` | `TextEditingController` | 输入框 |
| `_scrollController` | `ScrollController` | 消息列表滚动 |
| `_service` | `ChatService` | 流式对话服务 |
| `_imagePicker` | `ImagePicker` | 图片选择器 |
| `_isSending` | `bool` | 当前是否有角色回复轮次在执行 |
| `_hasText` | `bool` | 输入框是否有有效文本 |
| `_pendingImage` | `ChatImage?` | 待发送图片 |
| `_queuedUserMessages` | `List<ChatMessage>` | 回复期间排队等待处理回复轮次的用户消息 |
| `_activeTurnMessageId` | `String?` | 当前正在生成回复的排队用户消息 ID |
| `_stopRequested` | `bool` | 是否请求停止当前回复 |
| `_activeStopCompleter` | `Completer<void>?` | 用于中断当前流式请求 |
| `_loadedConversationId` | `String` | 已加载完成的会话 ID |
| `_historyLoadToken` | `int` | 历史加载竞态令牌 |
| `_messageSequence` | `int` | 消息 ID 序号 |

### 5.3 初始化监听

`initState()` 会：

- 监听输入框变化。
- 监听 `ModelStore.selection` 和 `ModelStore.modelCatalog`。
- 监听 `CharacterStore.cards`，角色卡变化时刷新头像和名称。
- 监听 `UserProfileStore.profile`，用户资料变化时刷新头像。
- 监听 `ChatHistoryStore.clearedConversation`，聊天记录被清空时立即清空界面。
- 调用 `_loadHistory(_conversationId)`。

### 5.4 会话切换

单聊页由会话列表按角色卡 ID 打开，页面生命周期内不再切换角色：

- 每个聊天页只加载 `characterId` 对应的聊天记录。
- 角色卡改名或换头像时，页面通过 `cards` 监听刷新。
- 群聊同样按群聊 ID 加载记录。

历史加载使用 `_historyLoadToken` 防止旧请求覆盖新会话。加载完成后才会允许发送；如果用户过快点击发送，会提示「正在加载聊天记录，请稍候」。

### 5.5 销毁

`dispose()` 中移除所有监听，并释放：

- 输入控制器
- 滚动控制器
- `ChatService` 的 HTTP client

## 6. 消息渲染

### 6.1 消息列表

- 消息为空时聊天区域为空白，不再展示欢迎页或快捷建议。
- 消息按时间顺序从上到下排列。
- 列表支持拖动收起键盘。
- 新消息、流式增量和历史加载后自动滚动到底部。
- 长按任意消息会弹出底部菜单，可删除单条消息。

### 6.2 时间分隔

显示规则：

- 第一条消息始终显示时间。
- 与上一条消息间隔超过 5 分钟时显示。
- 跨天时显示。

时间格式：

| 时间 | 格式 |
|---|---|
| 今天 | `HH:mm` |
| 昨天 | `昨天 HH:mm` |
| 今年内 | `M月d日 HH:mm` |
| 更早 | `yyyy/M/d HH:mm` |

### 6.3 气泡

| 类型 | 展示 |
|---|---|
| 用户消息 | 右侧、主题色气泡、右侧显示用户头像 |
| 单聊助理消息 | 左侧、表面色气泡、左侧显示当前角色卡头像 |
| 群聊助理消息 | 左侧、气泡上方显示发送者名称、头像按 `senderId` 查找 |
| 空助理占位 | 气泡内显示进度圈 |
| 图片消息 | 图片在上，正文在下；图片最大 220×280 |
| 图片加载失败 | 显示损坏图片图标 |

气泡最大宽度为屏幕宽度的 78%。

当前正文使用普通 `Text` 展示，不支持 Markdown 渲染。

## 7. 输入区与图片

### 7.1 输入区

`_Composer` 包含：

- 多行输入框，`minLines: 1`、`maxLines: 4`。
- 占位文案：`发消息…`。
- 图片按钮：仅当前模型支持视觉输入时显示，回复期间仍可使用。
- 发送按钮：不会因为角色正在回复而变成加载状态。
- 角色回复期间仍可输入和发送，新消息进入排队队列。

满足以下任一条件即可发送：

- 输入框有非空文本。
- 已选择待发送图片。

### 7.2 选择图片

点击图片按钮后弹出底部选择框：

- 「照片」：`ImageSource.gallery`
- 「拍摄」：`ImageSource.camera`

`ImagePicker.pickImage` 参数：

- `maxWidth: 1600`
- `maxHeight: 1600`
- `imageQuality: 85`

### 7.3 图片校验

- 字节为空：提示重新选择。
- 超过 8 MB：提示选择更小图片。
- MIME 类型只允许 JPEG、PNG、GIF、WebP。
- MIME 优先取 `XFile.mimeType`，否则按扩展名判断。
- HEIC/HEIF 能被识别，但不在允许集合内，会被拒绝。
- 选择成功后展示 76×76 缩略图，可点击关闭按钮移除。

### 7.4 模型能力

通过 `ModelStore.supportsVision(selection)` 判断：

- 不支持的模型不显示图片按钮。
- 发送前再次校验，避免切换模型后发送不支持的图片。
- 当前有 pending 图片时切换到不支持视觉的模型，会自动清空待发送图片。

### 7.5 API 序列化

`ChatMessage.toApiJson()` 的行为：

- 纯文本消息使用字符串 `content`。
- 带图片的消息使用 OpenAI 兼容的多模态数组。
- 发送者名称非空时，会在正文前添加：

```text
<发送者名称>：<正文>
```

纯图片且没有文字时，只发送 `image_url` 部分。群聊用户发送纯图片时，由于用户消息带有 `senderName`，会生成一个带名称的文本片段和图片片段。

示例：

```json
{
  "role": "user",
  "content": [
    { "type": "text", "text": "小森：看看这张图" },
    {
      "type": "image_url",
      "image_url": { "url": "data:image/png;base64,..." }
    }
  ]
}
```

## 8. 发送流程

### 8.1 发送前校验

`_sendMessage()` 依次检查：

1. 文本和图片是否都为空。
2. 当前会话历史是否加载完成。
3. 当前供应商是否配置 API Key。
4. 是否已选择模型。
5. 有图片时模型是否支持视觉。
6. 群聊中是否至少存在一个有效角色卡。

角色回复期间发送的新消息不会并发发起请求，而是加入 `_queuedUserMessages`，当前回复轮次结束后按顺序处理。

### 8.2 用户消息

单聊：

```dart
ChatMessage(
  role: ChatRole.user,
  content: text,
  image: image,
)
```

不写入 `senderId` / `senderName`。

群聊：

```dart
ChatMessage(
  role: ChatRole.user,
  content: text,
  image: image,
  senderId: 'user',
  senderName: userProfile.name.isEmpty ? '用户' : userProfile.name,
)
```

用户消息追加后立即保存一次聊天记录，避免流式回复失败时丢失用户刚发送的内容。

### 8.3 单聊流程

```text
用户消息
  │
  ▼
_saveHistory
  │
  ▼
_streamReply(
  responder = 会话所属角色卡,
  systemPrompt = MoriConfig.buildSystemPrompt(角色卡),
  showSender = false,
)
  │
  ▼
追加空的助理占位消息
  │
  ▼
逐块写入 buffer
  │
  ├─ 检测到 ||| → 当前气泡增量显示 → 后续气泡逐条出现
  └─ 未检测到 ||| → 保持等待占位，生成结束后再拆分
  │
  ▼
按打字节奏逐条追加剩余气泡
  │
  ▼
保存聊天记录，处理队列中的下一条用户消息
  │
  ▼
队列清空后恢复空闲状态
```

### 8.4 群聊流程

```text
用户消息
  │
  ▼
保存聊天记录
  │
  ▼
按 `group.replyMode` 顺序解析有效角色卡并选择本轮发言者
  │
  ▼
第一位发言者请求 → 流式回复
  │
  ▼
下一位发言者请求（历史中包含前一位的回复）
  │
  ▼
继续直到本轮发言者结束或某个成员失败
  │
  ▼
处理队列中的下一条用户消息
```

说明：

- 每个成员单独发起一次模型请求。
- 所有成员共用当前选择的模型和 API Key。
- 后回复的成员能看到前面成员已经生成的回复。
- 任意一个成员失败会停止后续成员回复。
- 群成员数量越多，耗时和调用成本越高。

### 8.5 `_streamReply()`

职责：

- 使用当前回复轮次开始时的历史快照，而不是实时消息列表。
- 创建空的助理占位消息。
- 通过稳定的消息 ID 定位并更新占位消息，而不是依赖列表索引。
- 群聊中写入 `senderId` / `senderName`。
- 逐块读取 SSE，写入 `StringBuffer`。
- 未检测到 `|||` 时不把整段文字直接塞进第一条气泡，避免生成结束后“长文闪一下再拆分”。
- 检测到 `|||` 后按段增量更新当前气泡，并为下一段追加新的助理气泡。
- 群聊中实时清理回复开头自己的角色名前缀。
- 空回复时移除占位气泡。
- 请求异常时保留已经收到的部分内容，只移除完全空白的占位气泡。
- `finally` 中保存聊天记录。

### 8.6 回复期间的消息队列

- 角色回复期间继续发送时，用户消息立即加入 `_messages` 并显示。
- 同时加入 `_queuedUserMessages` 队列，并持久化到 `chat_queue_v1_<conversationId>`。
- 当前回复轮次结束后，按发送顺序取出队列消息并生成对应回复。
- 每轮开始时会生成历史快照，快照会排除仍在队列中的后续用户消息，避免它们提前影响当前角色。
- 群聊同一轮中，前一个成员的回复会加入本轮快照，后一个成员可以看到。
- 队列全部处理完后，`_isSending` 才恢复为 `false`。
- 发送按钮不显示加载状态，图片按钮在回复期间也可继续使用。
- 输入框和已排队消息仍会立即保存到聊天记录。
- 排队中的用户消息显示「排队中」，正在回复的消息显示「回复中」。
- 回复期间提供「停止回复」按钮；停止会中断当前流式请求并清空未处理的队列。
- 应用关闭后，队列消息 ID 仍保存在本地；重新进入会话时会检查消息是否已有回复，未回复的排队消息会自动继续处理。
- 如果历史中已经存在非空助理回复，则对应队列项视为已完成并自动移除。

### 8.7 连发消息

模型的一轮回复可以在界面上拆成多条气泡：

- 优先识别 `|||` / `｜｜｜` 显式分隔符；
- 模型使用分隔符时，气泡在生成过程中就按段出现，不会先显示一整条长消息；
- 流式增量阶段，`|||` 段内的换行也会被当作气泡边界，避免一个气泡内部出现多行换行；
- 任何最终仍留在气泡内部的换行都会在显示前压成正常标点：前一句已有句末/逗号标点时直接拼接，否则补一个中文逗号；
- 模型没有使用分隔符时，先显示等待占位，生成结束后再按换行或句末标点拆条，避免长文闪烁后再拆分；
- 其次按换行拆分；
- 对较短回复，按中文句末标点拆分；
- 当用户明确说“多发几条”“连发”“分几条”“一条条说”等时：
  - 从用户消息里解析目标条数（`两条`/`三条`/`4条` 等，默认 3，限制 2-5）；
  - 在本轮 system prompt 末尾追加【本轮连发要求】，要求模型输出指定条数；不会追加额外的隐藏 user 消息，避免模型把提醒当成新一轮用户发言而只回“好嘞”；
  - 优先要求模型输出 JSON 字符串数组，例如 `["第一条","第二条","第三条"]`，客户端解析后逐条显示；
  - JSON 解析失败时，再回退到 `|||`、换行、句末标点和逗号拆分；
  - 模型返回数量多于目标时，把多余内容合并到最后一条；
  - 模型返回数量少于目标时，最多追加 2 次续发生成，补齐缺少的条数；
- 代码块、列表和超过 240 字的内容默认不拆；用户明确要求连发时，句末标点拆分可以突破长度限制；
- 单轮最多 5 条，多余内容合并到最后一条；
- 使用分隔符时，第 2 条起随模型生成进度逐条出现；
- 生成结束后才拆分的情况，第 2 条起按文本长度延迟 0.3-1.5 秒追加，模拟打字节奏；
- 群聊中每条气泡都保留 `senderId` / `senderName`，后发言的成员能看到前面成员的全部气泡。

单聊和群聊的系统提示词都会追加【连续消息】说明，鼓励模型用 `|||` 主动控制连发；固定通用提示词也从“回复通常 2-5 句”改为“一次只说一两句，想说的多就拆成几条发，用 `|||` 分隔”。角色卡编辑页提供「填入连发模板」，可一键把短句/`|||`/禁止大段的说明写进人格描述、说话方式或粘贴设定。用户明确要求连发时，本轮 system prompt 会追加指定条数的 JSON 输出要求，并声明这是系统格式要求、优先于角色平时的单条回复习惯。

连发倾向设置：

- 全局：设置 → 聊天 →「连发倾向」，可选关闭 / 自然 / 积极；
- 单角色：角色设置页 →「聊天连发倾向」，可选跟随全局 / 关闭 / 自然 / 积极；
- 关闭：不追加连发提示，也不按换行/句末标点自动拆条；模型自己使用 `|||` 时仍分条；
- 自然：追加“想说的多就拆成几条”的说明，默认 1-3 条、每条 10-60 字；
- 积极：追加“默认拆成 2-5 条、每条 15-100 字”的强提示，适合话多的角色；
- 条数和字数范围都可以在「设置 → 聊天 → 条数与字数范围」中分别修改自然/积极两种倾向；
- 模型返回条数超过范围上限时合并多余内容；积极倾向少于下限时自动续发补齐；
- 用户明确要求“多发几条”时，优先执行显式连发要求，不受关闭倾向影响，指定条数会先夹到当前范围内。

### 8.8 群聊发言顺序

群设置页支持选择发言策略：

- 固定顺序，全部回复。
- 随机顺序，全部回复。
- 随机选择一名角色回复。
- 优先回复被点名的角色；没有点名时随机一名。

发言策略保存在 `GroupProfile.replyMode`，重新打开群聊后保持。

### 8.9 跨场景活动记忆（第一阶段）

角色会记录自己做过的事，并在后续聊天里知道这些事，但不把其他场景的聊天全文带进来。

数据模型：`CharacterActivity`

- `characterId`：哪个角色做的；
- `kind`：单聊消息、群聊消息、主动消息、动态、动态评论、动态回复；
- `contextId` / `contextLabel`：发生在哪个会话/群/动态，以及当时的名称快照；
- `content`：角色自己说的话或动态正文；
- `createdAtMs`；
- 隐私级别：
  - `private`：单聊和主动消息；
  - `group`：群聊发言；
  - `public`：动态、动态评论和回复。

存储：`CharacterActivityStore`，Key `character_activity_v1`，每个角色最多保留最近 300 条。

记录时机：

- 单聊/群聊助理消息发送成功后；
- 主动消息发送成功后；
- 角色发布动态后；
- 角色评论或回复动态后。

上下文注入：`CharacterActivityContextBuilder`

- 单聊/主动消息：可以注入自己的群聊发言和公开动态，最多 8 条，每条最多 90 字；
- 群聊：只注入自己的公开动态/评论，不注入其他群和单聊内容；
- 动态生成：只看自己的公开动态/评论；
- 不注入当前会话的同一类消息，避免和聊天历史重复；
- 注入文本明确说明“这是你自己做过的事，不是用户刚说的”，要求自然带出、不要逐条复述。

隐私规则：

- 群聊里不能说其他群的聊天内容；
- 群聊里不能提及其他单聊的内容；
- 单聊里可以自然提起自己的群聊经历和动态；
- 动态生成不引用私聊原文。

历史回填：`CharacterActivityBackfill.ensureBackfilled()` 首次启动时扫描已有单聊、群聊、动态和评论，只回填角色自己的内容，完成后写入一次性标记。

这一阶段只做“最近活动 + 按场景过滤”，不做摘要、长期记忆、遗忘曲线和向量检索；这些属于后续记忆/日记阶段。

## 9. 群聊身份语义

群聊中需要同时解决两个问题：

1. 用户消息不能被模型误认为其他 AI 成员发送。
2. AI 回复正文不能反复带上自己的角色名。

### 9.1 发送者标签

发给模型的群聊历史中：

| 消息 | 角色 | 名称前缀 |
|---|---|---|
| 用户消息 | `user` | 用户名称；未设置时使用「用户」 |
| 当前回复者的历史回复 | `assistant` | 不加前缀 |
| 其他 AI 成员的历史回复 | `assistant` | 对应角色名称 |

当前回复者自己的历史消息由 `buildGroupRequestHistory()` 去除 `senderName`，避免模型模仿「名字：正文」的格式。其他成员保留名称，便于区分不同 AI。

### 9.2 群聊系统提示词

群聊会在角色卡基础提示词后追加：

```text
你正在群聊「<群名称>」中。
AI 群成员有：<成员名称列表>。
用户在聊天记录中显示为「<用户标签>」。
聊天记录中，带名称前缀的消息用于区分发送者：以「<用户标签>」开头的是用户本人发送的，其他名称开头的是对应的 AI 成员。没有名称前缀的助理消息是你自己之前发送的内容。
请只以「<当前角色>」的身份回复用户最新的消息，不要代替其他成员或用户发言，不要把其他 AI 成员的发言误认为自己的发言，也不要重复其他成员已经说过的内容。
直接输出回复正文，不要在正文开头添加任何人的名字或角色名前缀，界面会自动显示发送者名称。
```

### 9.3 名称前缀清理

工具函数：`lib/utils/chat_text_utils.dart`

`stripLeadingSpeakerName(text, name)` 会移除开头的发送者名称，支持：

- 全角冒号 `：` 和半角冒号 `:`。
- 中文方括号/英文方括号：`【Mori】：`、`[Mori]:`。
- Markdown 粗体：`**Mori**：`、`**Mori：** 你好`。
- 最多连续清理 3 层重复前缀。
- 大小写不敏感。
- 不破坏正文本身的 Markdown 粗体格式。

使用位置：

- 群聊流式回复时实时清理当前 AI 自己的名字前缀。
- 加载群聊历史时清理已保存的旧名前缀。

### 9.4 历史归一化

群聊加载历史时：

- 用户消息统一设置 `senderId = 'user'`，并使用当前用户标签。
- 助理消息按 `senderId` 查找当前角色卡名称。
- 角色卡改名后，历史中的发送者名称会更新。
- 同时尝试清理“当前名称”和“历史保存名称”对应的开头前缀。

因此旧群聊记录中已经保存的「Mori：大家好」会在显示时变成「大家好」，下次保存时写回干净正文。

## 10. 系统提示词与模型请求

### 10.1 单聊提示词

单聊使用：

```dart
MoriConfig.buildSystemPrompt(character)
```

`MoriConfig` 根据角色卡类型组合：

- 名字
- 角色简介
- 人格描述
- 性格、说话方式、背景、关系、喜好、边界
- 场景、开场白、示例对话
- 附加系统指令
- 附加行为要求
- 固定聊天规则

`paste` 类型如果存在原文定义，会直接使用原文，不再追加结构化字段。

### 10.2 群聊提示词

群聊使用：

```text
MoriConfig.buildSystemPrompt(当前发言角色)
+ 群聊上下文
+ 发送者识别规则
+ 不代替他人发言规则
+ 不输出名字前缀规则
```

### 10.3 `ChatService` 请求

`lib/services/chat_service.dart` 使用 OpenAI 兼容协议：

```http
POST {baseUrl}/chat/completions
Accept: text/event-stream
Authorization: Bearer <API Key>
Content-Type: application/json
```

请求体：

```json
{
  "model": "<modelId>",
  "messages": [
    { "role": "system", "content": "<系统提示词>" },
    { "role": "user", "content": "..." }
  ],
  "stream": true,
  "thinking": { "type": "disabled" }
}
```

- `thinking` 只在供应商 `supportsThinkingToggle == true` 时发送，用于关闭深度思考、缩短首字延迟。
- 连接/首包超时：30 秒。
- 流式数据间隔超时：60 秒。
- 只处理 `data:` 行。
- `data: [DONE]` 结束。
- 从 `choices[0].delta.content` 读取文本增量。
- 无法解析的行直接忽略。
- 除聊天记录外，服务不负责持久化或记忆写入。

### 10.4 上下文注入与心情

`ChatPage._streamReply()` 在角色卡系统提示词之后依次追加：

1. 系统时间上下文；
2. 跨场景活动上下文；
3. 长期记忆召回；
4. 最近日记上下文；
5. 心情上下文；
6. 连发倾向说明；
7. 用户明确要求连发时的 JSON 格式要求。

系统时间上下文由 `SystemContextBuilder` 生成，包含当前日期、时间、星期、时区和距离上一条消息的时间；默认开启，可在「设置 > 聊天 > 系统感知」关闭。单聊和群聊都会注入，群聊中每个发言角色看到的是同一份系统时间。

长期记忆只在单聊和主动消息中注入，群聊不读取单聊记忆、人物档案和未完成话题。群聊只注入当前群的群公共记忆和群印象。召回会使用用户最新一条消息作为查询，按关键词、重要性和新近程度选出最多 6 条记忆；人物小档案和最多 3 条未完成话题会一起注入。格式类似：

```text
（以下是你长期记得的关于对方的事，不是对方刚说的。只在自然相关时使用，可以顺口提起，但不要逐条复述，也不要编造。）
【人物小档案】
- 对方是谁：用户是住在杭州的设计师
- 稳定喜好：喜欢睡前喝热牛奶
【还没结果的事】
- [待跟进 · 3 天前] 用户下周要去看牙医，还没告诉我结果
- [喜好 · 昨天] 用户喜欢在睡前喝热牛奶
```

对话页不会把记忆全文或完整聊天记录直接塞进提示词，只注入检索到的少量长期事实。最近日记由 `DiaryContextBuilder` 读取，默认最多 2 篇、每篇最多 180 字，要求角色自然提起、不要逐字复述。群聊不会注入私人日记。

群聊使用 `MemoryContextBuilder.buildForGroupChat(groupId)`，只读取该群的群公共记忆和群印象，不会读取单聊记忆、人物档案或未完成话题。

心情上下文仅在心情开启且标签不是「平平常常」时追加，格式类似：

```text
（你现在超开心，因为用户说「喜欢你」。这会自然影响你说话：话多一点、语气活泼……不用说出来自己心情如何。）
```

心情观察发生在生成回复之前：

- 单聊：`observe(characterId, userText, direct: true, owner: true)`；
- 群聊：对每个本轮发言角色调用 `observe(memberId, userText, direct: false, owner: true)`；
- 正向关键词每个 `+6`，负向关键词每个 `-8`，单条消息总分夹在 `±20`；
- 单聊权重 `1.0`，群聊 `0.3`，用户本人发言 `1.5`；
- 心情实际值限制在 `5-100`，并按半衰期回落到基线；
- 心情只做本地关键词判断，不额外调用模型。

心情还会影响气泡延迟：`chatBubbleDelay()` 的结果乘以 `MoodStore.delayFactor()`。超开心时回复更快，不太开心时更慢。

主动消息、角色动态、动态评论和评论回复也会在系统提示词中追加心情上下文，保证同一角色在不同场景里的语气一致。

## 11. 聊天记录存储

### 11.1 存储位置

| 数据 | 位置 |
|---|---|
| 文本聊天记录 | SharedPreferences，Key：`chat_history_v1_<conversationId>` |
| 聊天图片 | 应用 Support Directory 下的 `chat_images/<conversationId>/` |

`conversationId`：

- 单聊：角色卡 ID。
- 群聊：群聊 ID。

### 11.2 保存字段

每条消息保存：

```json
{
  "id": "消息 ID",
  "role": "user 或 assistant",
  "content": "正文",
  "createdAt": "ISO 8601 时间",
  "senderId": "群聊发送者 ID，可选",
  "senderName": "群聊发送者名称，可选",
  "image": {
    "file": "图片相对文件名",
    "mimeType": "image/png"
  }
}
```

说明：

- 空的助理占位消息不会落盘。
- 图片文件当前统一以 `.jpg` 扩展名保存，实际 MIME 类型单独记录。
- 保存失败会被吞掉，不阻断当前聊天。
- 加载时会跳过格式无效的消息。
- 图片文件缺失时，该消息只保留文本部分。

### 11.3 摘要

`summaryFor(conversationId)` 用于会话列表：

- 从最后一条向前查找可展示消息。
- 纯图片消息返回 `[图片]`。
- 正文连续空白压缩为一个空格。
- 最多用于列表一行展示，实际截断由 UI 处理。

### 11.4 删除

- 长按聊天中的单条消息，可在菜单中选择「删除消息」。
- 删除消息后立即重写该会话的本地聊天记录，并清理对应聊天图片。
- 角色设置页提供「删除聊天记录」，清空该角色的全部聊天记录、消息图片和排队消息。
- 群聊设置页提供「删除聊天记录」，清空该群聊的全部聊天记录、消息图片和排队消息。
- 删除角色卡时，会同时删除该角色卡的聊天记录、图片目录、动态、评论，以及群聊中由该角色发送的消息。
- 清空聊天记录时，已打开的聊天页会通过 `ChatHistoryStore.clearedConversation` 立即清空界面。
- 当前尚未提供群聊删除入口。

> 聊天记录不是记忆。`ChatHistoryStore` 不读写记忆模块，也不会把聊天记录自动转成长期记忆。

## 12. 单聊与群聊设置

> 设置主页、模型、外观、动态互动、自动消息、心情和关于页面的完整实现说明见 `.docs/20261107-设置页面开发文档.md`。

### 12.1 单聊设置

`ChatDetailPage` 右上角有三个点按钮，点击进入角色页面：

- AppBar 标题为当前角色名称。
- 页面顶部展示当前角色卡头像、名称和类型。
- 页面展示该角色当前心情：标签、数值、进度、最近变化原因与重置按钮；心情关闭时显示关闭提示。
- 页面提供「日记」卡片：可查看该角色是跟随全局还是单独设置，并直接调整该角色的日记开关和写作时间。
- 角色信息下方是「动态」入口，可进入该角色的动态主页。
- 再下方是「角色卡设置」入口。
- 点击角色卡设置打开对应的 `CharacterCardEditPage`。
- 保存成功返回后提示「角色卡已保存」。
- 角色卡保存会更新 `CharacterStore.cards`，聊天页标题、头像和后续提示词同步更新。
- 页面提供「允许主动消息」卡片，可以单独关闭该角色的主动消息或设置该角色每日上限，并跳转全局自动消息设置。
- 页面底部提供「删除聊天记录」，确认后清空该角色的全部本地聊天记录。

### 12.2 群聊设置

`GroupChatDetailPage` 右上角有三个点按钮，点击进入 `GroupSettingsPage`：

- 修改群头像：相册、相机、移除，图片限制 4 MB。
- 修改群名称：最多 30 字，留空保存为「群聊」。
- 修改群成员：至少保留两名成员。
- 修改发言顺序：固定顺序、随机顺序、随机一名、点名优先。
- 进入「群公共记忆」查看群印象和共同记忆，支持立即整理和清空。
- 群头像通过 `AvatarStore` 保存，群资料只记录相对文件名。
- 保存后 `GroupChatDetailPage` 通过 `GroupStore.groups` 监听自动更新标题、头像和成员数。
- 替换头像后会删除旧头像文件。
- 页面底部提供「删除聊天记录」，确认后清空该群聊的全部本地聊天记录。

### 12.3 新建群聊

入口为「对话」Tab 右上角加号菜单：

- 至少选择两张角色卡。
- 群名称最多 30 字。
- 留空时使用前三个选中角色名称，以「、」连接。
- 角色卡不足两张时显示提示，创建按钮不可用。
- 创建成功后返回 `HomePage` 并直接进入该群聊。
- 群聊 ID 使用 `group_<microseconds>`。

### 12.4 个人资料

左上角用户资料入口：

- 点击用户头像/名称打开左侧 Drawer。
- `UserProfileDrawer` 头部和「个人信息」入口都可进入 `PersonalSettingsPage`。
- 支持修改头像、名称、性别、生日和个性签名。
- 用户头像保存在本地头像目录。
- 聊天中的用户消息使用用户自己的头像。
- 用户资料存储 Key：`user_profile`。
- Drawer 底部新增「设置」入口，进入 `SettingsPage`。

名称为空时：

- 顶部栏和 Drawer 使用「我」。
- 群聊发送者标签使用「用户」。

### 12.5 自动消息

入口：「设置 > 自动消息」。

第一版只支持角色单聊，入口分为全局设置和角色单独设置：

- 「设置 > 自动消息」：全局开关、间隔、定时、免打扰和频率保护。
- 角色设置页「允许主动消息」：控制单个角色是否主动，以及该角色单独的每日上限。

主要设置：

| 设置 | 默认值 | 说明 |
|---|---|---|
| 启用自动消息 | 关闭 | 全局总开关 |
| 沉默主动 | 开启 | 双方一段时间没有新消息后主动发一条 |
| 沉默间隔 | 60-180 分钟 | 每次在区间内随机选择下一次触发时间 |
| 追问未回复的问题 | 开启 | 她发出问句后 15-40 分钟没回复时，偶尔轻轻追一句 |
| 定时问候 | 开启 | 每天在指定时间点主动发消息 |
| 定时时间 | 08:30、22:30 | 可添加、删除多个时间点 |
| 免打扰 | 23:30-07:00 | 时间段内不主动发消息 |
| 全局每日上限 | 6 条 | 所有单聊每天主动消息总数上限 |
| 角色每日上限 | 跟随全局 | 单个角色可设置任意非负整数，0 表示跟随全局，负数表示该角色无上限 |
| 连续未回复上限 | 3 条 | 某个会话用户一直不回复时暂停该会话 |
| 单角色开关 | 开启 | 关闭后该角色不会自动发消息 |

实现方式：

- `ProactiveMessageStore` 保存全局设置和每个会话的调度状态。
  - 设置 Key：`proactive_message_settings_v1`
  - 会话状态 Key：`proactive_message_state_v1_<conversationId>`
- `ProactiveMessageService` 由 `main()` 启动，每 30 秒检查一次；应用退到后台时暂停，恢复时补发一次。
- 触发时会先读取最近聊天记录和角色卡提示词，并参考角色最近发布的动态，再追加一条**不落盘的内部提醒**作为隐藏用户消息，让模型以角色身份生成主动消息。
- 生成提示词会追加跨场景活动上下文和心情上下文；心情只影响语气，不改变触发频率。
- 每次从多个“由头”中随机选一个：分享小事、接上次话题、提动态或记忆里的事、问对方在忙什么、撒娇吐槽、没头没尾的感慨、按时间说应景的话。
- 提示词要求优先使用真实素材，没有真实素材时不要编造具体事件、地点或人物。
- 模型可以只输出 `[沉默]`，表示这轮不想说话；此时不写入消息，也不消耗每日额度和未回复计数。
- 追问机制只在最后一条正常回复是问句、用户 15-40 分钟没回、且该消息还没追问过时触发；追问不消耗每日额度。
- 生成结果会去掉角色名前缀和包裹引号，过滤明显的系统提示、AI 自述和出戏内容。
- 模型返回多行或使用 `|||` 分隔时，最多拆成 5 条短消息写入聊天记录，更接近真人连发。
- 主动消息写入 `ChatHistoryStore` 后，通过 `messageAppended` 通知已打开的聊天页追加消息，并让会话列表刷新摘要。
- 手动触发不消耗每日额度，也不增加未回复计数。
- 自动触发全局至少间隔 5 分钟，避免多个角色同时刷屏。
- 生成期间如果用户开始聊天，本次主动消息会让路。
- 未配置模型或 API Key 时自动跳过，不弹出打扰提示。
- 清空聊天记录或删除角色卡时会清理对应自动消息状态。

限制：

- 只在应用前台或恢复时触发，应用被系统关闭后无法保证定时发送。
- 第一版不支持群聊自动消息，也不支持角色之间自动对话。
- 自动消息会调用当前模型，每次触发产生一次请求；追问也会产生额外请求。
- 追问窗口固定为 15-40 分钟，暂不可配置。

> 完整开发细节、AuraBot 参考分析和后续心情/记忆方案见 `.docs/20261108-自动消息与AuraBot参考开发分析文档.md`。

## 13. 动态页面

> 动态数据模型、存储、发布、生成、评论、自动互动和删除的完整说明见 `.docs/20261108-动态页面开发文档.md`。

底部导航第三个 Tab 为「动态」，由 `MomentsPage` 实现。设置页不再占用底部 Tab，改为从左侧个人资料抽屉底部进入。

### 13.1 数据模型与存储

`Moment` 字段：

| 字段 | 说明 |
|---|---|
| `id` | 动态 ID |
| `authorId` | 发布者 ID；用户固定为 `user`，角色为角色卡 ID |
| `authorName` | 发布者名称，作为角色卡不存在时的回退显示 |
| `isUser` | 是否为用户发布 |
| `content` | 动态正文，图文动态可以为空 |
| `createdAt` | 发布时间 |
| `imageFile` | 图片相对文件名 |
| `imageMimeType` | 图片 MIME 类型 |
| `image` | 运行时图片字节与 MIME |
| `comments` | 评论列表 |

`MomentComment` 字段：

| 字段 | 说明 |
|---|---|
| `id` | 评论 ID |
| `authorId` | 评论者 ID |
| `authorName` | 评论者名称 |
| `isUser` | 是否为用户评论 |
| `content` | 评论正文 |
| `createdAt` | 评论时间 |
| `replyToCommentId` | 被回复评论的 ID，普通评论为空 |
| `replyToAuthorName` | 被回复者名称，用于显示「回复 @」 |

`MomentStore`：

- 存储 Key：`moments_v1`。
- 保存最近发布的全部动态，按时间倒序加载。
- 动态图片保存在应用 Support Directory 下的 `moment_images/` 目录。
- 图片文件名写入动态 JSON，图片字节不写入 SharedPreferences。
- 新增动态、评论后立即持久化，失败时回滚内存状态。
- 跳过损坏或缺少必要字段的动态记录和评论记录。

### 13.2 动态流

- 动态按发布时间倒序展示。
- 每条动态显示发布者头像、名称、时间和正文。
- 图文动态显示图片；纯图片动态不显示正文区域。
- 每条动态底部显示评论入口。
- 用户动态使用当前 `UserProfile` 的头像和名称。
- 角色动态通过 `authorId` 查找当前角色卡，角色改名或换头像后动态列表同步更新。
- 角色卡不存在时使用保存的 `authorName` 和默认头像占位。
- 没有动态时显示空状态，提供「发动态」和「角色发动态」入口。

### 13.3 发布用户动态

- 点击悬浮按钮「发动态」或空状态按钮，打开底部编辑面板。
- 文本最多 500 字。
- 支持从相册或相机添加一张图片。
- 图片限制：
  - 最大 8 MB。
  - 仅支持 JPEG、PNG、GIF、WebP。
  - HEIC/HEIF 会被识别但拒绝。
- 支持纯文字、图文或纯图片动态；文本和图片至少存在一项才能发布。
- 发布后写入 `MomentStore`，`authorId = 'user'`。
- 用户资料名称和头像使用当前值，不额外复制头像文件。
- 发布成功后自动触发角色互动：其他角色评论，并可能产生角色之间的回复。

### 13.4 角色动态

- 点击「角色发动态」打开角色选择面板。
- 选择一个角色后，使用当前模型和 API Key 生成动态。
- 生成提示词包含角色卡完整系统提示词、系统时间上下文、随机创作方向、最近 5 条动态和当前心情上下文。
- 生成要求：
  - 第一人称。
  - 1-3 句话。
  - 具体、有当下感。
  - 不总是围绕同一个爱好、食物或口头禅。
  - 最近动态已集中出现某个主题时，必须换一个生活切面。
  - 不反复使用「今天」开头，不照抄最近动态。
  - 不加角色名前缀、标题、引号或 Markdown。
- 生成使用 temperature 1.0，并配合随机创作方向减少重复。
- 生成结果会清理开头的角色名前缀和包裹引号，最长 500 字。
- 生成成功后写入 `MomentStore`，`authorId` 为角色卡 ID。
- 生成成功后自动触发其他角色的评论和回复。
- 生成过程中显示进度条，并禁用角色动态按钮。
- 未配置 API Key、未选择模型、网络失败或空结果时通过 SnackBar 提示。
- 当前角色动态为纯文字，按需生成，不会定时自动发布。

### 13.5 评论与自动互动

用户评论：

- 点击动态底部「评论」打开评论编辑面板，发表新的顶层评论。
- 点击评论区中的某条评论，会直接打开绑定该评论的回复输入框。
- 回复输入框标题和提示文案为「回复 XXX」，其中 XXX 是当前解析出的评论者名称。
- 评论最多 200 字，正文非空才能发布。
- 评论保存为 `authorId = 'user'`，显示在对应动态下方。
- 显示评论数量。
- 回复保存目标评论 ID、目标名称和回复层级。
- 评论或回复发布后自动触发角色互动。
- 长按评论区中的任意评论，可以在菜单中选择「删除评论」，同时删除其下所有回复。
- 评论回复目标名称不使用写死名称，而是优先根据 `replyToCommentId` 找到目标评论，再读取当前角色卡名称或当前用户名称。
- 角色卡改名或用户改名后，评论区显示的「A 回复 B」会同步更新。
- 旧数据中保存的 `replyToAuthorName: 用户` 仍会优先通过目标评论 ID 解析成当前用户名称。

角色自动互动：

- 按设置中的评论人数，随机选择多个其他角色自动发表评论。
- 如果动态作者是角色，作者会自动回复这些评论。
- 如果动态作者是用户且还有其他角色，其他角色会自动回复这些评论。
- 用户发表评论后，动态作者（角色）或其他角色会自动回复。
- 用户直接回复某条角色评论时，不受自动回复层数限制；被回复的角色会主动回复用户一次。
- 该主动回复同样只回复一层，不会继续触发自动回复循环。
- `自动评论人数` 大于 1 时，额外的角色会作为「共同好友」加入同一条评论，形成 A 回复用户、B 也回复用户的互动。
- 自动回复最多嵌套到设置中的层数；达到层数后停止。
- 自动互动按队列串行执行，避免同时发出多个模型请求。
- 角色评论和回复使用当前模型、角色卡提示词、动态内容、已有评论、跨场景活动上下文和心情上下文。
- 评论上下文会标记「你自己」，并附带「A 回复 B」关系，避免角色把其他角色的评论误认为自己的评论。
- 如果当前模型支持图片识别，评论和回复请求会把动态图片一起发送给模型；不支持视觉的模型只接收文字上下文和「包含图片」提示。
- 未配置 API Key 时不会生成自动评论或回复。
- 不再需要手动点击「角色评论」按钮。

动态互动设置：

- 入口：`设置 > 动态互动`。
- 自动评论人数：默认 `2`，范围 `0 - 5`。
- 自动评论人数同时决定「共同好友」加入评论的数量：设为 2 时，除了主要回复者，还会有一个其他角色加入。
- 自动回复层数：默认 `1`，范围 `0 - 3`。
- 用户直接回复角色评论时不受自动回复层数限制，被回复角色会主动回复一次。
- 人数设置为 `0` 时关闭对应的自动行为。
- 回复层数设置为 `0` 时关闭自动回复。
- 设置保存在 `moment_interaction_settings_v1`，应用重启后恢复。
- 设置修改后，在下一次新动态或新评论触发互动时生效。
- 设置页会显示当前配置摘要，例如「评论 2 人 · 回复 1 层」。

### 13.6 删除动态

- 每条动态卡片右上角有三个点按钮。
- 点击弹出小菜单，当前菜单项为「删除」。
- 选择删除后弹出确认对话框。
- 确认后从 `MomentStore` 移除动态，并删除对应图片文件。
- 动态下的评论随动态一起删除。
- 取消确认不会修改数据。

### 13.7 角色动态主页

入口：

```text
单聊页右上角三个点
  └── CharacterChatSettingsPage（标题为角色名称）
      └── 动态
          └── CharacterMomentsPage
```

`CharacterMomentsPage`：

- AppBar 显示角色头像、角色名称和「动态」。
- 仅展示 `authorId` 等于该角色卡 ID 的动态。
- 不显示用户动态和其他角色的动态。
- 不显示「发动态」悬浮按钮和「角色发动态」入口。
- 仍可查看动态图片和评论，并会触发角色自动回复。
- 角色没有动态时显示空状态。

## 14. 异常与边界处理

| 场景 | 处理 |
|---|---|
| 未配置 API Key | SnackBar 提示前往「设置 > 模型」填写 |
| 未选择模型 | SnackBar 提示先选择模型 |
| 正在发送时再次发送 | 直接忽略 |
| 文本和图片都为空 | 不发送 |
| 聊天记录尚未加载完成 | 提示稍候 |
| 群聊没有有效角色卡 | 提示「群聊中没有可用角色」 |
| 图片超过 8 MB | 提示选择更小图片 |
| 图片格式不支持 | 提示仅支持 JPEG/PNG/GIF/WebP |
| 当前模型不支持图片 | 提示切换支持图片的模型 |
| 模型切换为不支持视觉 | 自动清空待发送图片 |
| 助理空回复 | 移除占位气泡并提示重试 |
| 请求超时或网络错误 | 展示 `ChatServiceException` 的中文消息 |
| 流式过程中出现部分内容后失败 | 保留已收到的部分内容并提示错误 |
| 页面已销毁 | 异步回调前检查 `mounted` |
| 图片渲染失败 | 显示损坏图片图标 |
| 聊天记录 JSON 损坏 | 跳过无效消息，尽量恢复剩余内容 |
| 聊天记录保存失败 | 不阻断当前聊天 |
| 动态文本和图片都为空 | 发布按钮不可用 |
| 角色动态生成缺少 Key/模型 | SnackBar 提示先完成模型配置 |
| 角色动态生成空结果 | 提示重新生成 |
| 动态图片保存失败 | 不写入动态并提示重试 |
| 评论保存失败 | 回滚评论并提示重试 |
| 自动评论/回复失败 | 静默跳过，不影响动态和后续互动 |
| 未配置模型时自动互动 | 评论和回复跳过 |
| 动态保存失败 | 回滚内存列表并提示重试 |
| 动态互动设置保存失败 | 回滚设置并提示重试 |
| 动态删除失败 | 保留原动态并提示重试 |
| 角色动态主页找不到角色 | 显示「角色卡不存在或已被删除」 |
| 动态记录 JSON 损坏 | 跳过无效记录，尽量恢复剩余内容 |

`ChatService` 对非 200 响应的处理包括：

- `400`：请求格式不正确
- `401`：API Key 无效
- `402`：账户余额不足
- `403`：没有访问权限
- `422`：请求参数错误
- `429`：请求太频繁
- `500` / `503`：服务暂时不可用
- 其他状态码：显示 HTTP 状态码和供应商返回的错误详情

## 16. 已知限制

- 支持停止当前流式回复和删除单条消息；不支持重新生成或编辑消息。
- 连发条数依赖模型是否使用 `|||`、换行或句末标点；用户明确要求连发时会追加内部提醒并用逗号兜底，但模型坚持输出单句时仍可能只有一条。
- 模型不使用 `|||` 时，文本会在生成完成后一次性拆条显示，而不是逐字流式显示；使用 `|||` 时可以边生成边显示当前气泡。
- 不支持 Markdown 渲染，模型输出的 Markdown 会按普通文本显示。
- 图片以 base64 data URL 放入请求体，大图片会明显增加请求体积。
- HEIC/HEIF 图片会被识别但拒绝发送。
- 群聊每个发言成员单独请求，人数越多耗时和成本越高。
- 群聊支持固定顺序、随机顺序、随机一名和点名优先，但尚未接入 LLM 动态选人或自动连续对话模式。
- 群聊任意发言成员失败会停止本轮后续成员回复。
- 暂无群聊删除、退群和群公告；群资料目前仅支持修改名称、头像、成员和发言顺序。
- 支持删除单条消息和清空角色/群聊聊天记录；暂无导出聊天记录、搜索会话和未读数。
- 自动消息只在应用前台或恢复时触发，不支持应用被杀死后的定时推送；第一版只覆盖单聊。
- 主动消息默认发送本地通知并在会话列表显示未读红点；关闭本地通知后仍会计未读。
- 点击通知会打开对应角色单聊；通知权限被系统拒绝时不会弹出提醒，但未读仍保留。
- 自动消息每次触发都会调用模型，建议配合每日上限、免打扰和连续未回复上限使用。
- 心情目前只根据关键词判断，不调用模型；表情包、语音频率、群聊插话积极程度和主动消息触发间隔暂不受心情影响。
- 心情只在非「平平常常」时注入上下文，避免角色语气被固定；心情日志每个角色保留最近 50 条。
- 用户资料仅保存在本机，尚未支持账号登录和跨设备同步。
- 单聊设置页提供角色卡设置和删除聊天记录。
- 对话历史不会自动写入记忆或日记；单聊和主动消息会以只读方式注入少量长期记忆和最近日记。
- 动态支持文字、单张图片、评论和评论回复。
- 角色动态仍由用户点击生成；角色评论和回复会在新动态或新评论出现时自动触发。
- 自动互动不是定时任务，不会在应用关闭或没有新事件时持续运行。
- 自动互动使用当前模型，每次自动评论/回复都会产生一次模型请求，成本随角色数、动态数和回复层数增加。
- 自动评论人数和自动回复层数可以在「设置 > 动态互动」中调整，并会持久化。
- 自动互动人数和层数不设上限，可填写任意非负整数；负数表示无上限。设置过高会显著增加模型消耗，请谨慎调整。
- 评论和回复中的图片只有在当前模型支持视觉时才会发送给模型；否则模型只能看到文字上下文和图片提示。
- 动态暂不支持编辑、多图、图片评论和分页。

## 17. 开发约定

- 页面只负责展示和交互，持久化放在 Store。
- 聊天记录与记忆必须保持独立，不得自动互相写入。
- 单聊页通过 `characterId` 定位角色卡；群聊页依赖 `GroupProfile` 和当前存在的角色卡。
- 不要在页面中直接读写 SharedPreferences。
- 群聊消息必须保留 `senderId` / `senderName`，否则重新加载后无法恢复发送者头像和名称。
- 群聊用户消息固定使用 `senderId = 'user'`。
- 群聊请求历史必须通过 `buildGroupRequestHistory()` 处理当前回复者的名称前缀。
- 群聊本轮发言者必须通过 `selectGroupSpeakers()` 按 `GroupProfile.replyMode` 选择，不要在其他地方重复实现顺序逻辑。
- 模型输出开头的角色名前缀必须在流式显示和历史加载两处清理。
- 角色卡改名后，群聊历史展示名称应随 `CharacterStore` 更新。
- 流式占位消息必须通过消息 ID 定位更新，不能依赖列表索引。
- 回复轮次必须使用本轮开始时的历史快照；后续排队用户消息不能提前进入当前轮上下文。
- 排队用户消息 ID 必须持久化到 `ChatQueueStore`，重进会话时过滤已回复项并恢复未完成队列。
- 停止回复必须取消当前流式读取、保留已收到的部分内容并清理未处理队列。
- 删除单条消息必须同步更新聊天记录、排队队列和对应聊天图片文件。
- 清空聊天记录必须同时清理 `ChatHistoryStore` 和 `ChatQueueStore`，并通过 `clearedConversation` 通知已打开的聊天页。
- 删除角色卡必须级联删除其聊天记录、聊天图片、排队消息、群聊中该角色发送的消息、动态、评论和置顶状态。
- 删除动态评论时必须连同其下所有回复一起删除。
- 动态和评论的删除只能通过 `MomentStore` 完成，页面不得直接维护持久化结构。
- 自动消息必须通过 `ProactiveMessageService` 调度，不要在页面里直接起 `Timer`。
- 自动消息的隐藏触发提示不能写入 `ChatHistoryStore`，只能作为本次请求的临时消息。
- 自动消息触发前必须检查总开关、模型配置、免打扰、每日上限、连续未回复上限和当前会话是否正在生成回复。
- 自动消息写入聊天记录后必须通过 `ChatHistoryStore.messageAppended` 通知界面刷新。
- 用户发送消息后必须调用 `noteUserMessage()` 重置未回复计数和沉默计时。
- 生成回复前必须调用 `MoodStore.observe()`；单聊使用 `direct: true`，群聊使用 `direct: false`，用户发言传 `owner: true`。
- 心情上下文只能通过 `MoodStore.contextLine()` 生成；不要在各页面重复拼接标签或风格文案。
- 只有非「平平常常」的心情才注入上下文；心情关闭时 `contextLine()` 必须返回空字符串。
- 气泡延迟必须乘以 `MoodStore.delayFactor()`，但不得改变消息写入顺序和持久化内容。
- 长期记忆只能通过 `MemoryContextBuilder` 注入单聊和主动消息；群聊不得读取单聊记忆。
- 记忆召回条数必须从 `MemoryStore.settings` 读取，不要在聊天页硬编码。
- 自动消息必须先检查 `ProactiveMessageState.enabled` 和角色的每日上限，再考虑全局上限。
- 模型输出 `[沉默]` 时必须放弃发送，并且不增加每日次数和未回复计数。
- 追问必须绑定最后一条助理消息 ID，每条消息最多追问一次，窗口固定为 15-40 分钟。
- 动态作者 ID：用户固定为 `'user'`，角色使用角色卡 ID。
- 角色动态和角色评论必须使用当前角色卡提示词，并清理开头角色名前缀。
- 角色动态提示词必须包含最近动态和防重复要求。
- 自动互动必须限制为每个新动态一轮；直接回复者数量受自动评论人数限制，整条回复链不超过设置层数。
- 自动互动人数和层数必须从 `MomentInteractionSettingsStore` 读取，不要硬编码。
- 自动互动必须使用 `MomentInteractionService` 串行队列，不要在页面中直接并发请求。
- 自动回复目标必须通过 `replyToCommentId` 动态解析当前显示名称，不能依赖写死的「用户」或旧名称。
- 评论回复 UI 必须同时支持回复用户评论和角色评论。
- 动态图片只保存相对文件名，图片字节保存在 `moment_images/` 目录，不写入 SharedPreferences。
- 评论或回复涉及动态图片时，如果当前模型支持视觉，必须把图片作为多模态输入发送；不支持视觉时只发送文字提示。
- 删除动态时必须同时删除对应图片文件、评论和回复。
- 评论必须保留 `authorId` / `authorName` / `isUser`，回复评论还需保存 `replyToCommentId` / `replyToAuthorName` / `replyDepth`，但展示名称应优先按 ID 动态解析。
- 新增消息字段时，需要同步更新：
  1. `ChatMessage`
  2. `ChatHistoryStore.saveFor()`
  3. `ChatHistoryStore.loadFor()`
  4. 相关测试
- 新增动态字段时，需要同步更新：
  1. `Moment`
  2. `MomentStore.load()`
  3. `MomentStore.add()`
  4. 相关测试
- 头像文件只保存相对文件名，删除或替换后清理旧文件。
- 修改群成员后，下一条消息按新的成员列表回复。
