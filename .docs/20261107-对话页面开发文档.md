# 对话页面开发文档

> 文档日期：2026-11-07  
> 页面文件：`lib/pages/chat_page.dart`  
> 入口位置：`HomePage` 第 0 个 Tab（标题「对话」）  
> 页面类型：`StatefulWidget`

## 1. 页面概览

对话页是 Mori 的核心交互页面，负责：

- 展示欢迎页与快捷建议。
- 输入并发送文本消息。
- 从相册或相机选择图片并随消息发送。
- 调用大模型接口，实时展示流式回复。
- 在未配置 API Key 或模型时显示配置提醒。
- 自动滚动到最新消息。
- 展示发送中、空回复、请求失败等状态。

对话页本身不包含 `Scaffold` 和 `AppBar`，外层由 `HomePage` 提供。页面返回一个 `Column`，依次放置提醒条、消息区域、待发送图片预览和输入区。

## 2. 依赖与技术

| 类型 | 依赖 | 用途 |
|---|---|---|
| UI | Flutter Material 3 | 页面布局、主题、输入框、气泡、SnackBar |
| 图片选择 | `image_picker` 1.2.4 | 相册选择、相机拍摄 |
| 网络 | `http` 1.6.0 | 通过 `ChatService` 发起流式请求 |
| 状态 | `ValueNotifier` / `ValueListenableBuilder` | 监听模型选择与 API Key |
| 配置 | `ModelProviderCatalog` | 获取当前供应商信息 |
| 模型能力 | `ModelStore.supportsVision()` | 判断当前模型是否支持图片 |
| 安全存储 | `ApiKeyStore` | 读取当前供应商 API Key |
| 数据模型 | `ChatMessage` / `ChatImage` | 文本与多模态消息 |
| 服务 | `ChatService` | 流式对话与 SSE 解析 |

## 4. 页面状态

`_ChatPageState` 中的关键字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `_messages` | `List<ChatMessage>` | 当前会话消息，仅保存在内存 |
| `_inputController` | `TextEditingController` | 文本输入控制器 |
| `_scrollController` | `ScrollController` | 消息列表滚动控制 |
| `_service` | `ChatService` | 对话服务实例 |
| `_imagePicker` | `ImagePicker` | 图片选择器 |
| `_isSending` | `bool` | 是否正在发送，防止重复请求 |
| `_hasText` | `bool` | 输入框是否有有效文本 |
| `_pendingImage` | `ChatImage?` | 已选择但尚未发送的图片 |

初始化与销毁：

- `initState()` 监听输入框变化、`ModelStore.instance.selection` 和 `modelCatalog`。
- `dispose()` 移除监听，释放输入控制器、滚动控制器和 `ChatService`。
- 模型或模型能力变化时，如果新模型不支持图片，会清空 `_pendingImage`。

## 5. 交互流程

### 5.1 文本消息发送

```text
点击发送 / 点击快捷建议
        │
        ▼
_isSending 检查（发送中直接返回）
        │
        ▼
提取文本并去除首尾空格
        │
        ▼
校验 API Key → 校验模型
        │
        ▼
构造 ChatMessage(role: user, content: text)
        │
        ▼
追加用户消息 + 空的助手占位消息
        │
        ▼
清空输入框、进入发送状态
        │
        ▼
ChatService.streamChat 逐块返回内容
        │
        ▼
更新助手消息 → 滚动到底部
        │
        ▼
流结束 / 错误 / 空响应处理 → 恢复发送状态
```

### 5.2 图片发送

1. 点击图片按钮，弹出底部选择框：
   - 「照片」：`ImageSource.gallery`
   - 「拍摄」：`ImageSource.camera`
2. 调用 `ImagePicker.pickImage`：
   - `maxWidth: 1600`
   - `maxHeight: 1600`
   - `imageQuality: 85`
3. 读取图片字节并校验：
   - 字节为空：提示重新选择。
   - 超过 8 MB：提示选择更小的图片。
   - MIME 类型不在 JPEG / PNG / GIF / WebP 中：提示不支持的格式。
4. 通过 `_imageMimeType()` 判断类型：
   - 优先使用 `XFile.mimeType`。
   - 其次按扩展名判断 `.png`、`.webp`、`.gif`、`.heic`、`.heif`，默认 `image/jpeg`。
   - 注意：HEIC / HEIF 能被识别，但不在支持集合内，会被拒绝。
5. 选择成功后设置 `_pendingImage`，在输入区上方展示 76×76 缩略图，可点击关闭按钮移除。
6. 发送时再次校验当前模型是否支持视觉输入。
7. 图片通过 `ChatImage.dataUrl` 转换为：

```text
data:<mimeType>;base64,<base64 字节>
```

8. `ChatMessage.toApiJson()` 将带图片的消息转换为 OpenAI 兼容的多模态内容：

```json
{
  "role": "user",
  "content": [
    { "type": "text", "text": "看看这张图" },
    {
      "type": "image_url",
      "image_url": { "url": "data:image/png;base64,..." }
    }
  ]
}
```

仅图片、没有文字时，`content` 数组只包含 `image_url` 一项。

### 5.3 模型能力判断

- 页面通过 `ModelStore.instance.supportsVision(selection)` 判断是否显示图片按钮。
- 判断依据来自模型列表缓存 `modelCatalog`：
  - `ModelOption.supportsVision`
  - 模型列表由 `ModelListService` 从供应商 `/models` 接口获取。
  - 支持的元数据字段：`input_modalities`、`architecture.input_modalities`、`supports_vision`。
- 当前模型不在缓存列表时，默认视为不支持视觉，图片按钮不显示。
- 发送前仍会再次校验，避免模型切换后发送不支持的图片。

## 6. 流式响应实现

`ChatService.streamChat()` 的请求结构：

```text
POST {baseUrl}/chat/completions
Accept: text/event-stream
Authorization: Bearer <API Key>
Content-Type: application/json

{
  "model": "<modelId>",
  "messages": [
    { "role": "system", "content": "<MoriConfig.systemPrompt>" },
    { "role": "user", "content": "..." }
  ],
  "stream": true,
  "thinking": { "type": "disabled" }
}
```

说明：

- `thinking` 仅在 `provider.supportsThinkingToggle == true` 时发送，当前为 DeepSeek。
- 首包/连接超时 30 秒。
- 流式数据间隔超时 60 秒。
- SSE 解析规则：
  - 仅处理 `data:` 行。
  - `data: [DONE]` 结束。
  - 从 `choices[0].delta.content` 读取文本增量。
  - 无法解析的行直接忽略。

页面收到每个 chunk 后：

1. 写入 `StringBuffer`。
2. 用最新 buffer 替换助手占位消息。
3. 调用 `_scrollToLatest()` 滚动到底部。

## 7. 异常与边界处理

| 场景 | 处理方式 |
|---|---|
| 未配置 API Key | SnackBar 提示前往「设置 > 模型」填写 |
| 未选择模型 | SnackBar 提示先选择模型 |
| 点击发送时正在发送 | 直接忽略，避免并发请求 |
| 文本和图片都为空 | 不发送 |
| 图片超过 8 MB | 提示选择更小图片 |
| 图片格式不支持 | 提示仅支持 JPEG / PNG / GIF / WebP |
| 当前模型不支持图片 | 提示切换模型 |
| 模型切换为不支持视觉 | 自动清空待发送图片 |
| 助手返回空内容 | 移除占位气泡并提示重试 |
| 请求超时/网络错误 | 展示 `ChatServiceException` 的中文消息 |
| 其他异常 | 提示「发送失败，请稍后重试」 |
| 页面已销毁 | 异步回调前检查 `mounted` |
| 图片渲染失败 | `Image.memory` 的 `errorBuilder` 显示损坏图标 |

## 9. 当前限制

- 消息仅保存在内存，切换页面由 `IndexedStack` 保留，应用重启后清空。
- 不支持中止流式回复、重新生成或编辑消息。
- 不支持 Markdown 渲染。
- 图片以 base64 data URL 直接放入请求体，8 MB 原图编码后会明显增大请求体积。
- HEIC / HEIF 图片会被识别但拒绝发送。
- 相机/相册权限异常只做统一提示，没有引导用户前往系统设置。
- 对话页不直接读取 `MoriConfig`，系统提示词由 `ChatService` 统一拼接。
