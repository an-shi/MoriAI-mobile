## 1. 页面概览

动态模块负责用户与角色之间的轻量社交内容，当前包含：

- 动态流：按时间倒序展示所有动态；
- 用户发布文字动态或单张图片动态；
- 角色使用当前模型生成动态；
- 动态评论与评论回复；
- 角色自动评论、自动回复和共同好友加入；
- 评论长按删除；
- 动态删除；
- 删除角色卡时级联删除该角色动态和评论；
- 角色个人动态主页。

已移除：

- 点赞功能；
- 点赞字段、自动点赞设置和点赞测试。

动态不是聊天记录，也不是长期记忆。动态内容只保存在 `MomentStore`，不会自动写入 `ChatHistoryStore` 或记忆模块。

## 3. 数据模型

### 3.1 `MomentImage`

文件：`lib/models/moment.dart`

| 字段 | 类型 | 说明 |
|---|---|---|
| `bytes` | `Uint8List` | 图片字节 |
| `mimeType` | `String` | MIME 类型 |

`MomentImage` 是运行时对象，不直接持久化；持久化的是图片文件名和 MIME 类型。

### 3.2 `Moment`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `String` | 动态 ID，格式 `moment_<microseconds>_<sequence>` |
| `authorId` | `String` | 用户固定为 `user`，角色为角色卡 ID |
| `authorName` | `String` | 发布时名称，作为角色卡不存在时的回退 |
| `isUser` | `bool` | 是否为用户发布 |
| `content` | `String` | 正文，可为空（图片动态） |
| `createdAt` | `DateTime` | 发布时间 |
| `imageFile` | `String` | 图片相对文件名，空表示无图 |
| `imageMimeType` | `String` | 图片 MIME 类型 |
| `image` | `MomentImage?` | 运行时图片字节 |
| `comments` | `List<MomentComment>` | 评论列表 |

约束：

- 正文为空时必须存在 `imageFile`；
- 正文和图片都为空时，`Moment.fromJson` 会抛出 `FormatException`；
- 图片文件缺失时：
  - 如果还有正文，保留动态并清空图片字段；
  - 如果正文也为空，加载时跳过该动态。

### 3.3 `MomentComment`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `String` | 评论 ID，格式 `comment_<microseconds>_<sequence>` |
| `authorId` | `String` | 用户固定为 `user`，角色为角色卡 ID |
| `authorName` | `String` | 发布时名称，作为回退显示 |
| `isUser` | `bool` | 是否为用户 |
| `content` | `String` | 评论正文，不能为空 |
| `createdAt` | `DateTime` | 发布时间 |
| `replyToCommentId` | `String` | 回复的目标评论 ID，空表示顶层评论 |
| `replyToAuthorName` | `String` | 回复目标名称快照 |
| `replyDepth` | `int` | 回复层级，顶层为 0 |

约束：

- 评论正文必须非空；
- `replyDepth` 小于 0 时归零；
- 评论的展示名称优先按 `authorId` 动态解析，`authorName` 只作为回退；
- 回复目标名称优先通过 `replyToCommentId` 查找当前评论，再按作者 ID 解析，`replyToAuthorName` 只作为回退。

### 3.4 `MomentInteractionSettings`

| 字段 | 默认值 | 范围 | 说明 |
|---|---|---|---|
| `autoCommentCount` | 2 | 0-5 | 每条新动态自动评论的角色数；0 关闭 |
| `autoReplyDepth` | 1 | 0-3 | 自动回复最大嵌套层数；0 关闭 |

文件：

- `lib/models/moment_interaction_settings.dart`
- `lib/services/moment_interaction_settings_store.dart`

持久化 Key：`moment_interaction_settings_v1`。

## 4. 存储

### 4.1 动态数据

文件：`lib/services/moment_store.dart`

| 数据 | 位置 |
|---|---|
| 动态和评论 | SharedPreferences，Key `moments_v1` |
| 动态图片 | 应用 Support Directory 下的 `moment_images/` |

动态 JSON 结构：

```json
{
  "id": "moment_...",
  "authorId": "mori",
  "authorName": "Mori",
  "isUser": false,
  "content": "今天下午下了很大的雨。",
  "createdAt": "2026-11-08T14:30:00.000",
  "image": {
    "file": "moment_....jpg",
    "mimeType": "image/jpeg"
  },
  "comments": [
    {
      "id": "comment_...",
      "authorId": "user",
      "authorName": "我",
      "isUser": true,
      "content": "我这边也下了。",
      "createdAt": "2026-11-08T14:35:00.000",
      "replyToCommentId": "",
      "replyToAuthorName": "",
      "replyDepth": 0
    }
  ]
}
```

### 4.2 加载流程

`MomentStore.load()`：

1. 读取 `moments_v1`；
2. JSON 解析失败或不是列表时，置空；
3. 逐条调用 `Moment.fromJson()`；
4. 跳过损坏记录和重复 ID；
5. 对有图片的动态调用 `_hydrateImage()`；
6. 图片文件不存在且正文为空时跳过；
7. 按 `createdAt` 倒序排序；
8. 写入 `moments` ValueNotifier。

### 4.3 保存流程

`MomentStore._persist(previous, next)`：

1. 先更新 `moments.value`，让 UI 立即刷新；
2. 写入 SharedPreferences；
3. 写入失败时回滚到 `previous` 并抛出异常；
4. 页面捕获异常后显示 SnackBar。

### 4.4 图片文件

- 文件名：`<momentId>.jpg`；
- 文件名中的非法字符会被替换为 `_`；
- 图片只保存相对文件名，不保存绝对路径；
- 删除动态时同步删除图片文件；
- 删除角色时同步删除该角色动态的图片；
- 图片文件清理失败不会抛出到 UI。

### 4.5 删除接口

| 方法 | 行为 |
|---|---|
| `delete(momentId)` | 删除动态、评论和图片 |
| `deleteComment(momentId, commentId)` | 删除评论及其所有后代回复 |
| `deleteForCharacter(characterId)` | 删除该角色发布的动态，并从其他动态中移除该角色的评论 |

### 5.3 状态监听

```dart
AnimatedBuilder(

    MomentStore.instance.moments,
    CharacterStore.instance.cards,
```

监听目的：

- 新动态、评论、删除后刷新列表；
- 角色改名/换头像后动态作者信息同步更新；
- 用户改名/换头像后用户动态和评论名称同步更新。

### 5.4 排序与过滤

- `MomentStore.moments` 本身按发布时间倒序；
- `authorId == null`：展示全部动态；
- `authorId != null`：只展示该角色发布的动态；
- 角色动态主页过滤用户和其他角色；
- 动态数量没有分页，当前一次性渲染全部。

### 5.5 空状态

`_EmptyMoments`：

- 图标；
- 「还没有动态」；
- 「发一条动态，或者让角色发一条。」；
- 根据 `showComposer` 显示「发动态」按钮；
- 根据 `showCharacterAction` 显示「角色发动态」按钮。

### 5.6 动态卡片

`_MomentCard` 内容顺序：

```text
头像 + 作者名 + 时间 + 菜单
图片（可选）
正文（可选）
「评论」或「评论 N」按钮
分隔线
评论列表（可选）
```

菜单：

- 只有「删除」；
- 没有点赞、分享或编辑；
- 删除前弹出确认对话框。

评论：

- 点击评论行：回复该评论；
- 长按评论行：弹出「删除评论」菜单；
- 删除评论时提示「该评论下的回复也会一起删除」；
- 评论显示为 RichText，名称加粗，支持「A 回复 B」格式；
- 回复目标名称优先按评论 ID 查找，找不到时回退到 `replyToAuthorName`。

### 5.7 时间显示

`_formatTime()`：

| 条件 | 显示 |

| 小于 1 分钟或未来时间 | 刚刚 |
| 小于 60 分钟 | N 分钟前 |

## 6. 发布用户动态

### 6.1 入口

`showComposer == true` 时显示右下角「发动态」FAB。

### 6.2 发布面板 `_MomentComposer`

- 用户头像和名称；
- 多行输入框，最多 500 字；
- 图片选择按钮；
- 图片预览；
- 发布按钮；
- 正文和图片至少有一个才能发布。

### 6.3 图片规则

- 支持相册和相机；
- `image_picker` 最大宽高 1600；
- 压缩质量 85；
- 单张图片最大 8 MB；
- 仅支持：
  - JPEG；
  - PNG；
  - GIF；
  - WebP；
- HEIC/HEIF 会被识别但拒绝发送；
- 只支持单张图片；
- 图片仅保存在发布草稿的内存中，点击发布后才写入本地文件。

### 6.4 发布流程

1. 关闭面板，拿到 `_MomentDraft`；
2. 读取 `UserProfileStore`；
3. `MomentStore.add()`：
   - 生成动态 ID；
   - 保存图片文件；
   - 写入动态列表和 SharedPreferences；
4. 调用 `MomentInteractionService.onMomentCreated()`（不阻塞 UI）；
5. 显示「动态已发布」；
6. 失败时显示「发布动态失败，请重试」。

## 7. 角色动态生成

### 7.1 入口

- 动态页标题栏「角色发动态」；
- 空状态「角色发动态」按钮；
- 角色动态主页不显示该入口。

### 7.2 选择角色

`_pickCharacter()`：

- 读取 `CharacterStore.instance.cards.value`；
- 底部弹窗列出所有角色卡；
- 选择后返回 `CharacterProfile`；
- 没有角色卡时提示「还没有可用的角色卡」。

### 7.3 生成流程

1. 设置 `_generating = true`，页面显示 `LinearProgressIndicator`；
2. 调用 `MomentService.generateForCharacter(character)`；
3. 生成成功后 `MomentStore.add()`；
4. 调用 `MomentInteractionService.onMomentCreated()`；
5. 显示「「角色名」发布了新动态」；
6. 失败时显示 `MomentGenerationException.message` 或通用提示；
7. `finally` 中恢复 `_generating = false`。

### 7.4 生成提示词

`MomentService.generateForCharacter()`：

- 使用 `MoriConfig.buildSystemPrompt(character)`；
- 当前日期和时间段；
- 10 类创作方向随机选一：
  - 最近发生的一件小事；
  - 一个突然冒出来的想法；
  - 对某件事的轻微吐槽；
  - 一段和过去有关的回忆；
  - 最近在期待的事情；
  - 观察到的生活细节；
  - 自己的小习惯或小缺点；
  - 和用户或朋友的一次互动；
  - 当下时间带来的心情变化；
  - 和角色核心设定有关但角度新鲜的日常片段。
- 最近 5 条自己的动态摘要，要求不要重复主题、开头和句式；
- 1-3 句话；
- 第一人称；
- 不添加标题、角色名前缀、引号、括号说明或 Markdown；
- 最大 500 字；
- temperature 1.0。

### 7.5 生成结果清理

`_normalize()`：

- 去掉开头角色名前缀；
- 去掉包裹引号（中文引号、直角引号、双引号）；
- 超过最大长度时截断并追加省略号；
- 空结果抛出「角色没有生成内容，请再试一次。」。

## 8. 评论与回复

### 8.1 发表评论

点击「评论」按钮：

1. 打开 `_CommentComposer`；
2. 显示动态摘要；
3. 用户头像和名称；
4. 多行输入框，最多 200 字；
5. 发布后调用 `MomentStore.addComment()`：
   - `authorId = 'user'`；
   - `isUser = true`；
   - `replyToCommentId = ''`；
   - `replyDepth = 0`；
6. 调用 `MomentInteractionService.onCommentCreated()`；
7. 显示「评论已发布」。

### 8.2 回复评论

点击评论行：

1. 打开 `_CommentComposer(replyTo: comment)`；
2. 标题为「回复 XXX」；
3. 提示文案为「回复 XXX…」；
4. 显示被回复评论摘要；
5. 保存时：
   - `replyToCommentId = comment.id`；
   - `replyToAuthorName = 当前解析出的作者名`；
   - `replyDepth = comment.replyDepth + 1`；
6. 显示「回复已发布」。

### 8.3 评论显示

- 顶层评论和回复按插入顺序展示；
- 每条评论显示「作者」或「作者 回复 目标」；
- 作者名称按 `authorId` 动态解析：
  - 用户：`UserProfileStore.displayName`；
  - 角色：`CharacterStore.cardById().displayName`；
  - 角色不存在：`authorName`；
  - 都为空：「角色」。
- 删除目标评论后，回复的 `replyToCommentId` 可能找不到目标；此时使用 `replyToAuthorName` 回退显示。

### 8.4 评论删除

长按评论行：

- 弹出底部菜单「删除评论」；
- 提示「该评论下的回复也会一起删除」；
- 确认后调用 `MomentStore.deleteComment()`；
- 删除算法：
  1. 先把目标评论 ID 放入 `removedIds`；
  2. 循环扫描所有评论；
  3. 如果某条评论的 `replyToCommentId` 在 `removedIds` 中，把该评论 ID 也加入；
  4. 重复直到没有新增；
  5. 过滤掉所有 `removedIds` 中的评论；
  6. 持久化。

这保证删除父评论时会级联删除所有后代回复，而不只是直接回复。

## 9. 自动互动

### 9.1 触发时机

- 新动态发布后：`onMomentCreated(moment)`；
- 新评论或回复发布后：`onCommentCreated(moment, comment)`；
- 自动互动不是定时任务，只在有新事件时运行；
- 应用关闭后不会继续互动。

### 9.2 串行队列

`MomentInteractionService` 使用 `_queue` 串行执行：

```dart
Future<void> _enqueue(Future<void> Function() action) {
  final next = _queue.then((_) => action()).catchError((Object _) {});
  _queue = next;
  return next;
}
```

好处：

- 用户快速发布多条动态时，不会同时发出多个模型请求；
- 自动互动异常不会中断后续任务；
- 生成失败的单个角色被跳过，不影响其他角色。

### 9.3 新动态自动评论

`_handleMoment(moment)`：

1. 重新读取当前动态，确认仍然存在；
2. 读取互动设置；
3. 候选角色排除动态作者；
4. 打乱候选顺序；
5. 排除已经在顶层评论过的角色；
6. 目标评论人数 = `min(autoCommentCount, 候选角色数)`；
7. 剩余人数 = 目标人数 - 已有顶层评论角色数；
8. 依次生成评论；
9. 每条评论生成后继续调用 `_continueReplies()`；
10. 单个角色失败时跳过。

### 9.4 新评论自动回复

`_handleComment(momentId, comment)`：

- 如果用户回复的是角色评论：
  - 找到被回复的角色；
  - 该角色主动回复一次；
  - **不受 `autoReplyDepth` 限制**；
  - 每个用户回复只回复一次，避免重复。
- 其他情况：
  - 如果 `autoReplyDepth <= 0`，直接返回；
  - 调用 `_continueReplies()` 继续回复链；
  - 调用 `_addJoiners()` 添加共同好友。

### 9.5 回复链

`_continueReplies(moment, start, settings)`：

```text
replyTo = 起始评论
while replyTo.replyDepth < autoReplyDepth:
  ├─ 如果已经有人回复了 replyTo，停止
  ├─ 选择回复者
  ├─ 生成回复
  ├─ 写入评论
  └─ replyTo = 新回复
```

回复者选择 `_pickResponder()`：

1. 如果动态作者是角色且不是被回复者，优先由动态作者回复；
2. 否则从其他角色中随机选一个；
3. 没有可用角色时停止。

### 9.6 共同好友

`_addJoiners(moment, target, settings)`：

- 加入人数 = `autoCommentCount - 1`；
- 如果 `target.replyDepth >= autoReplyDepth`，不加入；
- 候选角色排除：
  - 被回复评论的作者；
  - 已经直接回复过目标评论的角色；
- 打乱后依次生成回复；
- 每个共同好友单独调用一次模型。

### 9.7 防重复

- `_addReply()` 在写入前检查：
  - 是否已经有同角色对同一评论的回复；
  - 有则跳过。
- `_continueReplies()` 检查目标评论是否已有任何回复；
- `_replyToUserReply()` 检查角色是否已回复过该用户回复。

### 9.8 成本与失败处理

- 每条自动评论/回复都会调用一次模型；
- 自动评论人数和回复层数越高，成本越高；
- 生成失败被 `catch` 并返回 `null`，不弹用户提示；
- 自动互动失败不会影响动态本身；
- 当前不会对自动互动设置每日上限，只通过人数和层数限制。

## 10. 删除动态与角色级联

### 10.1 删除动态

`_deleteMoment()`：

1. 弹出确认对话框「删除动态」；
2. 用户确认后调用 `MomentStore.delete(moment.id)`；
3. 删除动态 JSON；
4. 删除动态图片文件；
5. 显示「动态已删除」；
6. 失败时显示「删除动态失败，请重试」。

### 10.2 删除角色卡

`CharacterStore.deleteCard(cardId)` 会调用：

```dart
await MomentStore.instance.deleteForCharacter(cardId);
```

行为：

- 删除该角色发布的全部动态；
- 删除这些动态的图片文件；
- 从其他动态的评论列表中移除该角色发表的评论；
- 其他角色对已删除评论的回复不会自动删除，展示时通过 `replyToAuthorName` 回退；
- 同时删除该角色的聊天记录、群聊消息、动态、评论、置顶和自动消息状态。

详细级联删除见 `.docs/20261107-对话页面开发文档.md` 和 `.docs/20261107-记忆与人格卡页面开发文档.md`。

## 12. 异常与边界

| 场景 | 处理 |
|---|---|
| 未配置 API Key | `MomentGenerationException`，提示先配置 Key |
| 未选择模型 | `MomentGenerationException`，提示先选择模型 |
| 模型不支持视觉 | 评论/回复只发送文字和「包含图片」提示 |
| 动态图片文件丢失 | 有正文则保留动态并清空图片，否则跳过 |
| 动态 JSON 损坏 | 跳过该条，不影响其他动态 |
| 评论 JSON 损坏 | 跳过该条评论 |
| 动态正文和图片都为空 | `Moment.fromJson` 拒绝，`MomentStore.add` 拒绝 |
| 动态不存在时评论 | `StateError('Moment not found')`，页面提示失败 |
| 删除已不存在的动态 | 直接返回，不抛异常 |
| 评论删除目标不存在 | 直接返回，不抛异常 |
| 角色卡不存在 | 展示回退名称/头像；动态主页显示不存在 |
| 图片清理失败 | 忽略，不影响删除结果 |
| 自动互动失败 | 静默跳过，不阻断后续任务 |
| 用户快速连续发布 | 互动队列串行处理 |
| 用户直接回复角色评论 | 角色回复一次，不受自动回复层数限制 |

## 14. 已知限制

- 动态不支持编辑；
- 只支持单张图片；
- 不支持图片评论；
- 不支持点赞（已完全移除）；
- 不支持分享、转发、收藏；
- 不支持分页，当前一次性加载全部动态；
- 自动互动不是定时任务，只在有新动态或新评论时触发；
- 自动互动每次评论/回复都会调用模型，人数和层数越高成本越高；
- 自动互动失败会静默跳过，不会重试；
- 动态图片以本地文件保存，评论/回复涉及图片时只有视觉模型才能看到；
- 删除父评论会删除所有后代回复，且没有撤销；
- 删除角色卡会级联删除动态和评论，且没有撤销；
- 暂不支持导出动态或迁移到其他设备。

## 15. 开发约定

- 页面只负责展示和交互，持久化统一通过 `MomentStore`。
- 动态和评论的作者名称必须优先按 `authorId` 解析，不能依赖写死名称。
- 用户作者 ID 固定为 `'user'`。
- 动态图片只保存相对文件名，不保存绝对路径。
- 动态正文和图片至少存在一个，评论正文不能为空。
- 删除动态必须同时删除图片文件。
- 删除评论必须级联删除所有后代回复。
- 删除角色卡必须调用 `MomentStore.deleteForCharacter()`。
- 自动互动必须通过 `MomentInteractionService` 串行队列，不要在页面中直接并发请求。
- 自动互动人数和层数必须从 `MomentInteractionSettingsStore` 读取。
- 自动回复目标名称必须通过 `replyToCommentId` 动态解析。
- 评论回复 UI 必须同时支持用户评论和角色评论。
- 动态图片在发送给模型前必须检查 `ModelStore.supportsVision()`。
- 不要把动态内容自动写入聊天记录或记忆模块。
- 新增动态字段时，需要同步更新：
  1. `Moment` / `MomentComment` 序列化；
  2. `MomentStore.load()` / `_persist()`；
  3. 相关页面展示；
  4. 测试。
